## 1. 本版目的

本版不是重新设计官网，也不是开放任意拖拽的建站器，而是把现有 Nuxt 页面接入可验证的 Visual Editing 闭环：运营人员在真实官网画布中选择页面区块，编辑 CMS 内容，立即看到临时结果，保存后从 Directus 回读，刷新后仍保持，并能撤销、重做、取消和恢复。

本版先修正执行口径：自动化测试通过、接口返回 HTTP 200、Directus 中存在字段，都不能单独证明官网已经连接 CMS。只有“真实浏览器画布 + 请求目标 + Directus 精确回读 + 刷新保持 + 原值恢复”同时成立，才算一个元素完成。

### 2.2 不可修改

Nuxt 继续拥有 DOM 结构、布局、PSD 坐标、动画、路由、锚点、响应式断点和组件逻辑。CMS 不保存任意 HTML/CSS/JavaScript，不提供自由像素重排。位置调整仅限模板白名单：排序、对齐、焦点、字号、字重、颜色、行高和有限偏移。

## 3. 架构和数据所有权

```text
Nuxt 模板层（结构、坐标、动画、路由）
        ↓
Visual Binding 层（选择、定位、临时状态、历史、白名单样式）
        ↓
Directus（页面、产品、新闻、媒体、权限、版本、发布）
        ↓
MySQL 127.0.0.1:3307 + MinIO 9000/9001
```

每个可编辑元素必须有唯一绑定：

```json
{
  "collection": "pages",
  "itemId": "1",
  "sectionKey": "performance",
  "fieldPath": "body"
}
```

缺少任一字段、使用排序数组下标、或来源只是代码 fallback 的元素，必须显示为“只读/待建模”，不能伪装成已连接 CMS。媒体只保存 Directus 文件引用；页面不得保存本地路径或未经治理的外链。

## 4. 工作台交互要求

- 顶部：页面/区块、选择、文字、媒体、撤销、重做、缩放、保存草稿、预览。
- 左栏：六页及其真实二级区块；禁止出现两层同名分类。
- 中栏：真实 Nuxt PC 画布；点击属性项必须滚动到真实锚点并高亮。
- 右栏：内容、媒体、版式、文字样式、状态和绑定诊断。
- `1440x900` 时预览画布至少 720px；不得被面板覆盖或横向溢出。
- 修改在 300ms 内开始更新；视频播放、失败、被阻止或未结束都不得阻塞编辑。
- 撤销、重做、取消同时恢复表单、画布和本地草稿状态；保存失败保留草稿并允许单项重试。

## 5. 内容规则

- 新闻和视频分享每页最多 6 条，按业务发布日期降序；第 7 条进入下一页。
- 产品、设备、证书、客户和合作品牌库存可扩展，但前台必须分页、轮播或懒加载，不能一次渲染全部素材。
- 视频先显示海报和文字，海报可自动取首帧但必须允许人工替换。
- 时间轴为共用里程碑数据；首页和关于页只保存展示配置，不能产生两份主数据。
- 全站 Header、Footer、CTA 和联系方式只维护一份来源。
