# 瑞钧官网 Visual Editing 继续执行 PRD

- 版本：v9.0
- 日期：2026-08-25
- 文档状态：执行基线，P0 未完成
- 适用范围：PC 端六个官网栏目；手机端本阶段只读
- 上一版本：`Visual Editing继续执行PRD-v8.md`

## 1. 背景与问题定义

当前系统已经具备 Directus 工作台、真实 Nuxt 画布和部分字段的可视化编辑能力，但“能打开工作台”“画布有变化”“自动化测试通过”都不足以证明真实官网内容已经形成闭环。必须逐项证明：画布元素绑定了正确的 Directus 记录，修改不需等待视频结束即可显示，保存只写入目标字段，刷新后仍一致，并且撤销、重做、失败恢复行为可靠。

本 PRD 的目标是继续完成这条真实闭环，而不是重新设计官网页面或制作一个通用网页搭建器。

## 2. 目标与非目标

### 2.1 本期目标

运营人员在一个 PC 工作区内完成以下操作：

1. 从六个一级栏目进入对应页面和页面内容区。
2. 在真实 Nuxt 页面画布中选中或双击已登记元素。
3. 在顶部工具栏或右侧属性面板修改文字、媒体和受控视觉属性。
4. 修改后立即在同一个 iframe 画布看到结果，不受视频播放进度影响。
5. 保存草稿、撤销、重做、取消恢复，并能识别保存失败和未保存离开。

### 2.2 明确不做

- 不改变 Nuxt 现有 PSD 布局、动画、路由、锚点、DOM 结构和响应式行为。
- 不开放任意 HTML、CSS、JavaScript、外链资源或无限制像素拖拽。
- 不把工作台改造成模板市场、自由区块拼装器或手机端编辑器。
- “素材不限制数量”只表示 CMS 可存储多条记录；前台仍必须分页、轮播、折叠或懒加载。

## 3. 产品结构

```text
页面模板层
  网站主页 / 产品展示 / 先进制造 / 视频新闻 / 关于瑞钧 / 服务支持
        ↓
页面区块层
  Banner / TextMedia / ProductList / NewsList / Gallery
  Timeline / ProcessCanvas / Offices / RichText / Video
        ↓
可视化绑定层
  sectionKey + collection + itemId + fieldPath
  + elementType + mediaRole + placementKey
        ↓
Directus 数据层
  页面、文章、产品、里程碑、证书、媒体、办事处等真实集合
```

工作区固定为：顶部操作栏、左侧六栏目和当前页面区块导航、中央真实 Nuxt PC 画布、右侧属性面板。画布不能覆盖属性面板；专注画布模式必须有明确退出按钮。左侧区块导航必须直接对应真实页面区块，禁止重复的“网站主页/网站主页”两层分类。

## 4. 内容与绑定契约

每一个可编辑 DOM 元素至少声明：

```json
{
  "sectionKey": "service-offices",
  "collection": "service_locations",
  "itemId": 1,
  "fieldPath": "service_scope",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

约束：

- `collection`、真实 `itemId`、`fieldPath` 任一缺失时只读，不显示保存控件。
- `itemId` 必须来自 Directus 返回值，不能从 URL、数组下标或字段名称推断。
- 跨集合元素必须分别声明绑定，禁止一次编辑污染相邻记录。
- 多集合保存逐项返回成功/失败；部分失败时保留未保存草稿和操作历史。
- 保存成功后更新本地成功基线；取消恢复基线，不依赖重新请求才能恢复。

允许的视觉属性为白名单：

- 位置：`align`、`offset_x`、`offset_y`、`max_width`
- 文字：项目字体、字号、字重、颜色、行高、预设样式
- 媒体：`fit`、焦点位置、遮罩、海报图

偏移默认限制为容器比例 `-30..30`。禁止任意 CSS、脚本和危险链接写入内容数据。

## 7. 继续执行计划

### P0-1：完成真实集合绑定

顺序：`qualifications` → `manufacturing_evidence` → 其他六页未覆盖集合。

每个集合先写失败测试，确认真实 `collection/itemId/fieldPath`，再做最小绑定修复。每个样本必须记录修改前后值、即时预览、Directus 返回、刷新一致和恢复结果。

### P0-2：完成编辑状态机

覆盖：输入即时同步（包括未失焦输入）、保存中、保存成功、部分失败、网络失败、撤销、重做、取消恢复、切页和未保存离开。

规则：新编辑清除重做分支；保存失败不得丢草稿；取消只能恢复最近一次成功基线。

### P0-3：完成媒体真实闭环

前置条件是业务提供至少一张已审核图片和一个已审核视频，并提供版权、用途、类型和 `placementKey`。系统必须拒绝未发布、未授权、类型不符或用途不符的媒体；图片、视频和背景预览不能等待播放结束。媒体需完成保存、刷新、撤销和恢复验证。

### P0-4：完成六页覆盖与 PC 回归

建立“可见元素 → 绑定 → 操作 → 测试 → 浏览器证据 → Directus 证据”表。PC 检查 `1440x900`、`1920x1080`、`3840x2160`；`390x844` 只做只读检查。不得因工作台实现改变官网原布局。

## 8. TDD 执行规则

每个切片固定执行：

```text
失败测试 → 最小修复 → 定向测试 → CMS/Nuxt 相关全量测试 → 构建
→ 真实 PC 浏览器操作 → Directus 读取核验 → 刷新复核 → 恢复测试值
```

不得使用测试媒体、伪造媒体或演示资讯作为真实验收证据。不得记录密码或 token。每完成一个切片，更新本文件的状态表和证据链接。

## 9. 验收标准（Definition of Done）

只有同时满足以下条件，才可宣布本阶段 P0 完成：

1. 六页承诺元素全部真实绑定，或明确标记为只读、延期、待建模。
2. 文字、媒体、视觉属性和排序均能即时预览、保存、撤销、重做、失败恢复和刷新保持。
3. 跨集合操作只写入目标 Directus 记录。
4. 真实审核媒体通过类型、用途、发布和版权校验。
5. CMS/Nuxt 测试、扩展构建、Nuxt 构建通过。
6. `8055/4175/3307/9000/9001` 健康检查通过。
7. 临时测试数据恢复，浏览器 PC 多分辨率回归无布局回退。

## 10. 风险、成本与待决策项

- 媒体库为空是外部输入阻断，不是可以用代码绕过的缺陷；在素材审核完成前，媒体 P0 不能关闭。
- 无限自由拖拽会破坏 PSD、响应式和维护成本。本 PRD 采用受控偏移；若必须像 PPT 一样任意拖拽，需要另立“自由画布编辑器”项目。
- 证书、地址、电话、负责人和宣传数字的可编辑性不代表可以直接发布，仍需业务审核和发布权限。
- 新闻和视频“无限存放”会增加媒体存储、缩略图、分页和备份成本，前台容量上限与 CMS 存储上限必须分开。

当前结论：`qualifications` 和 `manufacturing_evidence` 已完成代码绑定，但真实浏览器/Directus 闭环被业务发布状态阻断；下一执行点是取得已审核发布样本后完成两集合闭环，随后执行历史操作矩阵和真实媒体闭环。P0 仍未完成。
