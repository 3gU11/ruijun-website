## 1. 产品结论

本项目不是重新制作官网，也不是通用网页搭建器。要交付的是：

> 在完全保留现有 Nuxt 官网模板、坐标体系、动画、路由、锚点和响应式结构的前提下，让运营人员在真实页面画布上选择内容，并以类似 PowerPoint 的操作习惯修改文字、图片、视频、列表顺序及受控视觉属性。

“类似 PowerPoint”只描述操作方式，不代表可以任意拖动 DOM、写 CSS 或改变页面结构。页面模板继续由 Nuxt 管理，内容、媒体及经过白名单约束的展示参数由 Directus 管理。

### 1.1 三层职责

```text
Nuxt 页面模板层
  负责布局、动画、路由、锚点、响应式和组件结构
                 ↓
可视化编辑绑定层
  负责选中、高亮、字段定位、预览同步、撤销/重做和受控样式
                 ↓
Directus 数据层
  负责页面、产品、新闻、图片、视频、权限、审核和发布状态
```

任何一层都不能越权：Directus 内容不得改写 Nuxt 模板；画布不得猜测数据目标；Nuxt 兜底内容不得伪装成已经接入 CMS 的字段。

## 2. 需要纠正的前提

| 说法 | 判断 | 原因与处理 |
| --- | --- | --- |
| 六页画面上看得到的内容现在都能编辑 | 错误 | 当前仍有 Directus 内容与 PSD/代码兜底内容并存；没有真实绑定的元素只能只读 |
| 字段显示在属性面板就说明绑定正确 | 错误 | 当前首页已出现可见正文与目标字段不一致，存在误写风险 |
| 自动化测试全绿就可以交付 | 错误 | 还必须验证真实 Chromium 操作、Directus 保存回读、刷新保持和失败恢复 |
| 没有遮挡就代表边做边预览可用 | 错误 | 1440 宽度下属性面板打开后画布约 360px，虽不重叠但不具备 PC 官网编辑价值 |
| 像 PPT 一样可以任意拖放 | 错误 | 任意坐标会破坏 PSD 布局、动画和响应式；只开放模板、排序、对齐和受限偏移 |
| 素材不限量等于页面不限量渲染 | 错误 | 素材库存可扩展，前台仍需分页、轮播或懒加载 |
| 接口返回 HTTP 200 就说明 CMS 有内容 | 错误 | `data: null` 也可返回 200；必须核对记录内容和发布状态 |

## 3. 目标与非目标

### 3.1 P0 目标

1. 在一个工作台内按“六个页面 → 页面真实区块”管理内容，不再出现两层同名分类。
2. 中央区域加载真实 Nuxt 页面，单击选择、双击文字编辑、媒体替换和区块定位可用。
3. 工作台明确显示当前元素的集合、真实记录 id、section 和字段路径。
4. 文字、图片、视频、列表排序和白名单视觉属性至少各完成一条真实数据闭环。
5. 保存、回读、刷新保持、撤销、重做、取消、失败恢复和离开提示可验证。
6. 六页承诺内容逐项标记为“已闭环、只读、待建模或延期”，不能用页面级“已接入”掩盖字段缺口。
7. 改造前后 Nuxt 官网的结构、坐标、动画、路由、锚点和响应式行为不发生非内容性变化。

### 3.2 本期非目标

- 不重做 Nuxt 官网画面。
- 不建设 HTMLPage、Webflow 或 WordPress 式通用建站器。
- 不开放任意 HTML、JavaScript、CSS、绝对坐标和第三方字体上传。
- 不在手机端提供自由画布编辑。
- 不在 P0 建设生产 CDN、视频转码集群或跨地区高可用。
- 不以迁移演示资讯代替真实业务内容审核。

### 5.2 PC 可用性要求

- 进入“可视化编辑”后，Directus 原始记录表单应折叠或退出主工作区，不能与画布长期争抢宽度。
- 在 `1440x900` 下，属性面板打开时有效画布宽度不得低于 `720px`。
- 右侧属性面板建议宽度 `300-360px`，不得覆盖画布。
- 左侧页面导航可折叠，展开宽度建议 `200-240px`。
- 顶部工具栏允许分组或横向滚动，但控件不得重叠、换位或遮挡画布。
- `1920x1080` 和 `3840x2160` 下不能把多余空间浪费为固定空白；画布应按上限合理扩展。

当前“1440 下约 360px 画布”只满足无重叠，不满足本节验收，仍是 P0 缺陷。

## 6. 核心操作

| 操作 | 正常结果 | 阻断或失败处理 |
| --- | --- | --- |
| 单击元素 | 高亮并打开属性面板；显示业务名称和绑定来源 | 绑定不完整时只读，并显示缺失项 |
| 双击文字 | 进入就地编辑；属性面板同步 | 禁止脚本、危险 HTML 和任意样式 |
| 选择图片/视频 | 显示替换、焦点、适配方式和规格 | 未审核媒体不可进入发布状态 |
| 拖动元素 | 仅修改允许的排序、对齐或受限偏移 | 超范围、重叠或破坏模板时拒绝 |
| 点击左侧区块 | 打开正确页面并滚动到真实锚点 | 锚点缺失时明确报错，不静默回页首 |
| 切换页面 | 已保存内容保持；未保存内容先确认 | 不允许无提示丢失草稿 |
| 保存草稿 | 显示逐目标保存结果并建立新基线 | 部分失败不得显示为全部成功 |

### 6.1 视频行为

- 页面进入编辑模式后立即显示海报和文字，视频异步加载。
- 编辑、导航和滚动不等待视频播放结束。
- 自动播放必须静音；被浏览器阻止时仍可编辑。
- 支持暂停、跳过和替换海报。
- 视频加载失败时保留海报、文字和可重试状态。

### 6.2 历史与恢复

- 撤销/重做只作用于当前未保存会话。
- 新编辑发生后清空重做分支。
- 取消恢复到最近一次保存成功的基线。
- 保存成功后建立新基线，刷新后从 Directus 回读。
- 网络失败时保留本地草稿，不得显示“已保存”。
- 离开页面、关闭工作台或切换页面前，有未保存内容必须提示。

## 7. Visual Binding 强制契约

每个可编辑元素必须产生完整、可验证的绑定：

```json
{
  "sectionKey": "performance",
  "collection": "pages",
  "itemId": "1",
  "fieldPath": "body",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

### 7.1 规则

1. `collection`、真实 `itemId`、`fieldPath` 任一缺失，元素必须只读。
2. `itemId` 只能来自 Directus 响应，不能根据路由、数组下标或名称猜测。
3. `pages` 集合先用 `sectionKey` 定位 `sections[]` 中的 section，`fieldPath` 必须相对于该 section，例如 `body`、`title`、`media.0`。
4. 独立集合使用该集合自身的数据结构。例如 `homepage_sections` 的字段可以是 `content.body`，不能与 `pages` 路径混用。
5. 排序或过滤数组后仍要保存原始数组索引或稳定记录 id，避免写错项目。
6. PSD 和代码兜底内容可以展示，但没有真实媒体字段时只能只读。
7. 属性面板显示的当前值必须与画布可见值一致；不一致时禁用编辑和保存。
8. 保存前再次校验集合、记录 id、字段存在性和版本；禁止自动创建不存在的字段路径。
9. 跨集合保存逐项返回结果；失败项可重试，成功项不得重复写入。

### 7.2 当前已确认阻断缺陷

首页可见文字：

```text
效能提升50%，丝损降低30%
```

已核对的 Directus 来源是 `pages/1` 中 section `performance` 的 `body`。正确目标应为：

```text
pages / 1 / section:performance / body
```

当前工作台曾显示：

```text
pages / 1 / content.items.0.body
```

并且属性值为空。两者不一致，证明绑定不是安全的。修复并验证前，首页理由区不得执行真实保存测试。

同一区域的 `introTitle`、`introDetail` 也必须绑定到各自的 `performance`、`advanced-manufacturing`、`industry-leadership` section，不能继承 `why-ruijun` 或依赖列表位置猜测目标。

## 8. 六页 P0 内容边界

字段级完整清单以配套规范为准。本 PRD 只定义页面行为和验收边界。

| 页面 | P0 内容 | 关键行为 | 模板保护 |
| --- | --- | --- | --- |
| 网站主页 | 视频/海报/文字、三大理由、产品系列、横移图文、时间轴、页尾 | 视频不阻塞；每个理由独立绑定；时间轴有稳定顺序 | 不改首页动画、坐标、锚点 |
| 产品展示 | 首屏、分类、系列、型号、参数、单位、尺寸图、资料 | 内容多时分页；参数可增删排序；媒体可选 `contain/cover` | 不改卡片、详情模板和筛选路由 |
| 先进制造 | 首屏、工艺画布、节点图文、制造区域、核心设备图库 | 节点使用固定锚点；图库库存可扩展，前台按需加载 | 不改工艺模板、动画和响应式逻辑 |
| 视频新闻 | 首屏、动态新闻、视频分享 | 各每页最多 6 条；按业务发布日期降序；新闻有图文详情 | 不改详情路由和页面模板 |
| 关于瑞钧 | 首屏、品牌故事、共用时间轴、各类图库、品牌和客户 | 图库可扩展；时间轴共用数据；图片分页/轮播/懒加载 | 不改故事动画、场景和锚点 |
| 服务支持 | 首屏、支持说明、型号、服务入口、地区和门店 | 地区/门店可新增排序；联系方式发布前复核 | 不改服务布局、子路由和既有交互 |

“所有内容可编辑”的验收单位是具体可见元素，不是整页。每个元素必须在验收矩阵中有以下四种且仅一种状态：`已闭环`、`只读`、`待建模`、`延期`。

## 9. 视觉控制白名单

| 类别 | P0 允许 | 约束 |
| --- | --- | --- |
| 文字 | 内容、样式预设、字号、字重、行高、颜色、对齐、最大宽度 | 只用项目已授权字体；按元素类型限制范围 |
| 位置 | 模板、对齐、顺序、层级、桌面横纵偏移 | 偏移限制在容器比例 `-30..30`；不得生成任意定位 |
| 图片 | 素材、替代文本、`cover/contain`、焦点、遮罩、顺序 | 只引用已审核 Directus 媒体；禁止不可信外链 |
| 视频 | 文件、海报、静音、循环、移动替代媒体、字幕 | 首屏不依赖播放；失败必须有海报回退 |
| 响应式 | 显示开关、安全模板、独立字号 | PC 可编辑；手机本期只使用安全预设 |

禁止保存任意 CSS、JavaScript、事件代码、未清洗 HTML、任意字体文件和无限像素坐标。

## 10. 数据、媒体与发布

### 10.1 本地链路约束

```text
Nuxt 4175 → Directus 8055 → MySQL 127.0.0.1:3307
                              ↘ MinIO 9000/9001
```

- CMS 只能使用隔离的 MySQL `3307`，不得操作既有 `3306`。
- Directus 环境变量改变后必须重启，再验证真实连接。
- MinIO 是否启动不能靠进程名判断，必须验证端口、健康接口和真实对象写入。
- 真实预览必须区分 Directus 内容与 Nuxt fallback；`data: null` 不是内容读取成功。

### 10.2 媒体流程

```text
上传 → Directus 文件记录 → MinIO 对象
→ 用途/版权/规格审核 → 页面草稿引用 → 审核 → 发布
```

图片必须记录替代文本、用途、版权、尺寸和格式。视频必须记录海报、时长、编码、用途及可选字幕/文字稿。具体分辨率和体积要求沿用配套规范。

### 10.3 状态流

```text
草稿 → 待审核 → 已批准 → 已发布
          └────→ 已退回 → 草稿
已发布 → 已归档 / 回退历史版本
```

公开 BFF 只能返回已发布且有权限的内容。演示资讯不进入正式发布流程；删除演示数据前必须区分演示记录与真实记录，并保留可恢复备份。

## 11. 当前事实、推测与决策

### 11.1 已验证事实

| 事实 | 当前结论 |
| --- | --- |
| 工作台已能在真实 Chromium 中单击选中文字 | 选择链路存在，但不能代表字段目标全部正确 |
| 属性面板与画布已做到不重叠 | 三个 PC 视口无覆盖；1440 下画布宽度仍不足 |
| `1440x900` 属性面板打开后画布约 `360px` | 功能可运行，但不满足边做边预览的产品目标 |
| `1920x1080`、`3840x2160` 当前画布约 `475px` | 仍低于本 PRD 的 `720px` 最低要求 |
| 首页 `pages/1` 的 `performance.body` 存在真实文字 | 当前工作台目标路径曾错误指向 `content.items.0.body` |
| 公开首页 BFF 曾返回 `{"data":null}` | 只能说明请求有响应，不能证明公开内容已发布 |
| 最近记录的 Nuxt 全量测试为 `230/230` | 是代码基线，不是六页真实数据验收 |

### 11.2 尚未验证的推测

- 其他五页可能存在同类“画面值正确但保存路径错误”的问题，必须逐元素审计，不能从首页外推为都正常。
- 现有独立集合与 `pages.sections` 可能存在重复内容来源；最终保留哪一个要以真实绑定和迁移成本决定。
- 当前工作台若继续嵌在 Directus 记录表单旁边，可能无法达到 1440 下的最小画布要求，可能需要独立全屏编辑路由。

### 11.3 已作产品决策

- P0 采用受控 Visual Editing，不做自由建站器。
- PC 优先，手机端只读回归。
- 优先复用现有集合，新增集合必须说明迁移、权限和回滚。
- 第一条真实闭环通过前，不批量修改或宣布六页完成。

## 12. 继续执行计划

### P0-0 冻结视觉基线

1. 固定六页基准 URL、锚点和 PC/手机截图。
2. 建立允许变化清单：只允许业务内容和已批准的白名单视觉属性变化。
3. 任何 Nuxt 模板、坐标、动画、路由或响应式结构变化立即停止并回退该切片。

验收：六页基准证据齐全，后续能自动或人工判断结构性回归。

### P0-1 修复首页绑定阻断

1. 先写失败测试，覆盖 `pages/1 + performance + body` 和 `homepage_sections/{id} + content.body` 两种不同数据形态。
2. 将首页绑定改为“每字段显式路径”，禁止用一个前缀再拼接所有字段。
3. 修正三条理由的标题、正文、缩略图、主图和图标归属。
4. 没有真实媒体字段的 PSD 图片保留显示，但标记只读。
5. 属性面板值与画布值不一致时禁用保存。

验收：选择“效能提升50%，丝损降低30%”后，来源显示 `pages · 1 · performance · body`，属性值与画面完全相同。

### P0-2 恢复可用工作区

1. 将可视化编辑切换为独立全宽模式，折叠原 Directus 记录表单。
2. 保持左侧页面导航、中央画布、右侧属性面板互不覆盖。
3. 在 1440、1920、3840 三种宽度实测面板打开和关闭状态。

验收：1440 下属性面板打开后画布不低于 720px，工具栏无重叠，页面可滚动和定位。

### P0-3 第一条文字闭环

按固定顺序执行：

```text
读取原值 → 画布选中 → 临时修改 → 即时预览
→ 撤销 → 原值 → 重做 → 临时值 → 取消 → 原值
→ 再次修改 → 保存 → Directus 回读 → 刷新保持
→ 恢复原值 → 再次保存和回读
```

第一次历史验证不得保存业务临时值。正式保存测试必须在最后恢复原值。

验收：画面、属性面板、保存请求和 Directus 回读四处值一致，无其他字段变化。

### P0-4 媒体与失败恢复闭环

1. 使用一张审核图片和一个短视频测试替换、撤销、重做、保存、刷新和恢复。
2. 验证 Directus 文件记录、MinIO 对象和页面引用一致。
3. 分别模拟 Directus 失败、MinIO 失败、预览断连和部分保存失败。

验收：失败时保留本地草稿和原媒体引用，不产生“页面引用存在但对象缺失”的半成品。

### P0-5 六页逐元素绑定审计

执行顺序：网站主页 → 产品展示 → 先进制造 → 视频新闻 → 关于瑞钧 → 服务支持。

每个区块依次完成：

```text
可见元素盘点 → 数据来源确认 → 绑定测试 → 画布选择
→ 属性编辑 → 保存目标核对 → Directus 回读 → 刷新 → 恢复样本
```

验收：六页矩阵中每个元素都有唯一状态和证据；不存在“页面整体已接入”的模糊结论。

### P0-6 内容行为和发布闭环

- 产品和大图库验证分页、轮播或懒加载。
- 新闻和视频分别验证每页 6 条及业务发布日期降序。
- 验证草稿、审核、发布、退回和回退权限。
- 删除 CMS 演示资讯，但先完成识别、备份和真实内容隔离。

验收：公开 BFF 只返回已发布样本；草稿不会泄漏；测试数据全部恢复或清理。

### P1 运营增强

版本对比、批量排序、媒体高级筛选、审核差异、操作日志、导入导出、辅助线和更细权限。P1 不得降低 P0 的绑定与发布安全规则。

### P2 后续范围

手机端可视化编辑、生产视频转码/CDN、多人实时协同、通用模板市场。必须单独立项。

## 13. 测试与证据要求

每个实现切片执行：

```text
失败测试 → 最小实现 → 定向测试 → 全量测试 → 生产构建
→ 真实 Chromium → Directus 回读 → 刷新复核
→ 撤销/重做/失败恢复 → 恢复测试数据 → 登记证据
```

### 13.1 三类证据必须分开

| 证据类型 | 能证明 | 不能替代 |
| --- | --- | --- |
| 代码测试 | 路径计算、校验和状态逻辑符合契约 | 真实 UI、真实数据和存储链路 |
| 浏览器证据 | 用户能选择、修改、定位且无覆盖 | Directus 是否保存到正确记录 |
| 数据闭环 | 保存目标、回读、发布状态和恢复正确 | 页面视觉没有结构性回归 |

### 13.2 单元素证据模板

| 字段 | 要求 |
| --- | --- |
| 页面/区块/元素 | 使用用户可见名称 |
| 绑定目标 | `collection/id/sectionKey/fieldPath` |
| 原值与临时值 | 不含令牌或敏感信息 |
| 浏览器操作 | 选择、编辑、撤销、重做、保存、刷新 |
| API 与回读 | 状态、版本、保存批次和最终值 |
| 回归视口 | 至少包含 `1440x900` 和 `1920x1080` |
| 恢复结果 | 原值恢复且再次回读一致 |
| 证据路径 | 截图、测试输出和日志的仓库相对路径 |

## 14. P0 发布门槛

只有以下项目全部通过才能宣布 P0 完成：

- [ ] 六页导航按真实区块组织，无两层同名分类。
- [ ] 单击选择、双击文字、媒体替换、区块定位可用。
- [ ] 1440 下画布宽度满足最低要求，面板和工具栏不覆盖。
- [ ] 视频未结束、失败或被阻止时仍能编辑。
- [ ] 每个可编辑元素都有真实集合、记录 id、section 和字段路径。
- [ ] 画布值、属性值、请求值和 Directus 回读值一致。
- [ ] PSD/代码兜底元素明确只读，不伪装成 CMS 字段。
- [ ] 文字、图片、视频、排序和视觉属性完成真实闭环。
- [ ] 撤销、重做、取消、刷新、离开提示和失败恢复通过。
- [ ] 跨集合部分失败可识别、可重试且不重复写入。
- [ ] 新闻/视频分页和排序符合规则，大图库按需加载。
- [ ] 草稿、审核、发布、退回和回退权限有效。
- [ ] Nuxt 六页在三个 PC 视口无结构性变化。
- [ ] `390x844` 手机只读页面无新增重叠、溢出和路由回归。
- [ ] Directus、Nuxt、MySQL `3307`、MinIO `9000/9001` 有真实链路证据。
- [ ] 所有测试样本已恢复，演示资讯已按确认范围清理。

任一项缺失时只能报告“部分完成”，不能报告“六页已全部可视化编辑”。

## 15. 风险、成本与待确认

### 15.1 主要风险

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 同一内容同时存在于 `pages.sections` 和独立集合 | 修改来源不唯一、可能互相覆盖 | 每个元素确定唯一主来源，迁移后停写旧来源 |
| 以数组下标作为长期身份 | 排序后写错记录 | 使用真实 id 或保存原始索引并在提交前复核 |
| 画布过窄但以“无覆盖”通过 | 用户仍无法边做边看 | 设定 720px 最低宽度，必要时独立全屏路由 |
| 过度开放位置和字体 | 破坏 Nuxt 原布局和品牌一致性 | 使用模板和白名单，不开放任意 CSS |
| 真实业务资料未审核 | 宣传数字、证书、电话或客户 Logo 错误 | 发布前指定业务负责人签字 |
| 不限量媒体直接渲染 | 首屏慢、内存和带宽成本上升 | 分页、缩略图、懒加载和发布上限 |
| 只在本机验证 | 生产环境仍可能缺备份、HTTPS、CDN 和转码 | P0 与生产部署分开验收，另立上线清单 |

### 15.2 必须由业务确认

1. 最终发布权限归属，是否要求编辑、审核、发布三人分离。
2. 第一批闭环测试使用哪组已审核文字、图片和视频。
3. 宣传数字、客户 Logo、证书、负责人和联系方式由谁确认真实性与授权。
4. 新闻排序日期采用业务发布日期、创建时间还是事件日期；本 PRD 暂按业务发布日期。
5. 产品、设备和图库默认每页/每屏数量。
6. 哪些现有记录属于可删除演示资讯，哪些已转为真实业务资料。

这些问题不阻塞绑定修复和工作台布局修复，但会阻塞真实内容发布和 P0 最终签字。

## 16. 最终执行判定

现在可以继续开发，但不能直接进入“六页批量可编辑”阶段。正确顺序是：先修首页错误绑定，再恢复可用画布宽度，然后完成一条可恢复的真实文字闭环和一条媒体闭环，最后逐页扩展。

后续进度不再写成“某页面已接入”，而应写成“某个可见元素已绑定到哪个真实字段，并通过了哪些浏览器和数据证据”。这样才能避免工作台看起来功能很多，实际却修改不到官网真实内容或写入错误字段。
