# 瑞钧官网 Visual Editing 继续执行 PRD

- 版本：v21.0（执行重整版）
- 日期：2026-08-26
- 适用范围：PC 网页端六页；手机端仅做只读回归
- 文档定位：v20 的后续执行入口。v20 保留作为历史证据，不再作为任务排期入口
- 当前结论：继续采用“受控 Visual Editing”，不改造成任意拖拽建站器

## 1. 产品决策

运营人员应在 CMS 工作台的同一窗口中选择官网画布元素，使用顶部工具栏和右侧属性面板修改内容，并在不等待视频播放结束的情况下看到草稿效果。保存后，内容必须能从 Directus 精确回读，刷新仍保持，且可以取消、撤销、重做和恢复原值。

“六页所有内容可编辑”按以下边界解释：

- 业务内容可编辑：有真实 Directus 记录和唯一绑定的文字、图片、视频、新闻、产品、证书、客户、合作品牌、办事处、里程碑和重复项。
- 模板内容受控：布局、PSD 坐标、动画、路由、锚点、响应式结构和页面骨架继续由 Nuxt 控制。字体、字号、颜色、行高、对齐、排序、裁切焦点和有限偏移只能使用模板白名单。
- 只读内容：PSD 静态层、代码 fallback、无 Directus 文件记录、无 MinIO 对象或未经治理的外链，不生成可编辑绑定，并在工作台显示只读原因。

## 2. P0 完成定义

PC 六页只有同时满足以下条件才可宣布 P0 完成：

1. 工作台按“一级页面 → 页面真实区块 → 元素”组织，不出现两层相同分类。
2. 画布选择能打开正确的 `collection`、真实 `itemId`、`sectionKey` 和 `fieldPath`；不得用页面 id 或数组下标冒充记录 id。
3. 编辑面板与预览画布并排，预览不能覆盖面板；草稿变更目标为 300ms 内开始显示，视频不阻塞文字或图片预览。
4. 保存、回读、刷新、取消、撤销、重做、恢复原值均有测试和真实请求证据。
5. 图片/视频同时具备 Directus 文件元数据、MinIO 对象和 Nuxt 渲染证据；任一环节失败不得留下半条业务记录。
6. 草稿、审核、发布、退回和版本回退按角色生效，公开接口只返回已发布内容。
7. Nuxt 原布局、坐标、动画、路由、锚点以及 PC/手机响应式结构没有非内容性变化。

## 4. 编辑器交互契约

工作台布局固定为：顶部工具栏、左侧六页与区块树、中间 Nuxt 画布、右侧属性面板。顶部提供页面切换、选择、文字/媒体属性、撤销/重做、缩放、保存、预览和发布状态；右侧按“内容、媒体、文字样式、受控位置、绑定诊断”分组。

每个可编辑元素必须携带以下绑定：

```json
{
  "collection": "product_series",
  "itemId": "1",
  "sectionKey": "series-card",
  "fieldPath": "title"
}
```

保存前由服务端校验字段权限、媒体类型、大小、尺寸、位置范围和状态流转。断连时保留本地草稿并显示失败原因；不得静默回退到旧值。

## 5. 内容规则

- 动态新闻：标题、业务日期、封面、富文本详情、发布状态；点击封面或标题展开详情。
- 视频分享：标题、业务日期、视频文件；无独立海报时使用视频首帧，可人工替换。
- 动态新闻与视频分享每页最多 6 条，按业务日期倒序；页码越界收敛到最后一页。
- 产品、设备、证书、客户和合作品牌支持新增、编辑、隐藏、排序及分页/轮播，CMS 库存不设四张等硬编码上限。
- 首页和关于瑞钧共用同一 `milestones` 主数据，不复制里程碑。
- 上传提示规格只用于校验和引导，不得改变官网既有布局。

## 7. 继续执行计划

### P0-A：六页最小真实闭环

每页选择至少一个真实文字、媒体或重复项，完成：画布选择 → 临时预览 → 保存 → Directus 回读 → 刷新 → 取消 → 撤销/重做 → 恢复原值。记录完整绑定、原值/临时值/最终值、请求目标、响应状态和截图。

### P0-B：真实媒体闭环

业务提供至少一张正式图片和一个正式视频。完成 Directus 文件记录、MinIO 对象、媒体元数据、Nuxt 渲染、草稿预览、发布回读和刷新验证。素材未到位时保持阻塞，不创建演示内容冒充正式内容。

### P0-C：列表、详情和分页

完成新闻图文展开、视频首帧、6 条上限、日期倒序，以及产品/设备/证书/客户/合作品牌的新增、隐藏、排序和分页回归。

### P0-D：审核发布闭环

验证“草稿 → 待审核 → 已批准 → 已发布”以及退回和版本回退。编辑、审核、发布角色分别调用 API，公开 BFF 不得返回草稿。

### P1：体验完善

补齐批量上传、规格提示、定位高亮、键盘操作、断连重试、操作日志和手机只读回归；不改变官网视觉设计。

## 8. 测试与发布门槛

每个切片按固定顺序执行：失败测试 → 最小实现 → 定向测试 → Nuxt/CMS 全量测试 → 生产构建 → Chromium PC 验收 → Directus/MinIO 精确回读 → 刷新 → 撤销/重做/恢复。

发布前必须满足：定向测试全通过；全量测试无回归；构建通过；预览不遮挡编辑面板；公开接口不泄漏草稿；正式媒体有 MinIO 对象；六页各保留至少一条完整闭环证据。任何一项失败都标记对应切片为阻塞，而不是扩大 fallback 的可编辑范围。

## 9. 外部前置条件与风险

业务需确认正式文案/素材、编辑/审核/发布人员、新闻日期时区、默认分页数量、上传限制以及可删除的演示数据清单。删除演示数据前必须备份并获得确认。

主要风险是把 fallback 当成 CMS 成功、把 HTTP 200 当成已读取内容、用数组下标代替 Directus id、以及在修复编辑器时改变 Nuxt 原布局。所有验收以真实记录、发布状态、对象存在和回读结果为准。
