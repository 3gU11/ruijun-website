## 1. 先统一问题定义

本项目不是重新制作官网，也不是把 CMS 变成任意拖拽建站器。Nuxt 仍然负责页面模板、PSD 坐标、动画、路由、锚点和响应式；CMS 只负责已建模内容、媒体和受控视觉参数。所谓“可视化编辑”是：在真实官网画布中选中区块或元素，在工作台修改其内容，预览立即显示临时值，保存后从 Directus 精确回读，刷新后仍保持，并可撤销、重做、取消和恢复原值。

以下情况单独成立时都不算完成：自动化测试通过、接口返回 HTTP 200、Directus 中存在字段、画布显示了 fallback 文案，或元素带有编辑框但没有稳定数据来源。

## 2. 目标与非目标

### 2.1 本期目标（P0）

- PC 端六个一级页面按真实业务区块进入同一内容编辑工作台。
- 每个可编辑元素具备唯一绑定、可定位、可临时修改、可保存和可回读。
- 图片、视频、海报、文字、重复列表、排序、分页和受控文字样式可验证。
- 预览不遮挡编辑面板；视频加载、播放失败或未结束不阻塞编辑。
- 草稿、审核、发布、退回、回退在 Directus API 权限层生效。
- 手机端本期只做只读回归，不新增编辑能力。

### 2.2 明确不做

- 不改 Nuxt 原布局、PSD 坐标、动画时序、路由、锚点和断点。
- 不保存任意 HTML、CSS、JavaScript、本地文件路径或未经治理的外链。
- 不提供无限自由像素拖拽；位置只允许模板白名单内的排序、对齐、焦点和有限偏移。
- 不把代码 fallback、PSD 装饰层或无 Directus 记录的素材标记为可编辑。
- 不删除演示资讯，除非业务确认清单明确允许并有备份。

## 5. 唯一绑定与数据所有权

每个可编辑元素必须携带完整契约：

```json
{
  "collection": "product_series",
  "itemId": "1",
  "sectionKey": "series-card",
  "fieldPath": "title"
}
```

`itemId` 必须是 Directus 稳定记录 id，禁止使用数组下标、DOM 顺序或标题作为身份。缺少任一字段的元素只能显示“只读/待建模”。媒体只保存 Directus 文件 id；公开 BFF 只返回已发布内容，预览会话可受控读取草稿及允许的关联集合。

## 6. 工作台与预览交互

- 顶部工具栏：页面/区块、选择、文字、媒体、撤销、重做、缩放、保存草稿、预览。
- 左栏：六页和真实二级区块；选中条目后画布滚动到对应锚点并高亮。
- 中栏：真实 Nuxt PC iframe/画布，`1440x900` 预览列至少 720px，不能被面板覆盖或横向溢出。
- 右栏：内容、媒体、版式、文字样式、状态和绑定诊断；编辑时不得依赖视频播放结束。
- 文字样式只允许白名单字段：字体、字号、字重、颜色、行高、对齐、有限偏移；服务端必须校验范围。
- 修改应在 300ms 内开始同步；预览断连时保留本地草稿并显示错误，不丢失输入。
- 画布点击必须把 `collection/itemId/sectionKey/fieldPath` 传回工作台，并打开对应记录表单，而不是停留在 `pages` 页面记录。

## 7. 内容与媒体规则

- 动态新闻和视频分享每页最多 6 条，按业务发布日期降序；第 7 条进入下一页。
- 新闻包含标题、日期、封面和图文详情；视频分享包含标题、视频文件，封面默认首帧但可人工替换。
- 产品、设备、证书、客户和合作品牌允许不限库存，但前台必须分页、轮播或懒加载。
- 图片上传前后校验格式、体积、尺寸和比例；视频校验格式、时长、体积，并生成可用海报。
- 上传成功必须同时有 Directus 文件元数据和 MinIO 对象存在证据；失败不得写入半条业务记录。

## 9. TDD 与证据协议

每个切片固定顺序：失败测试 → 最小实现 → 定向测试 → CMS/Nuxt 全量测试 → 生产构建 → 真实 Chromium → Directus/MinIO 精确回读 → 刷新 → 撤销/重做/取消 → 恢复原值 → 更新 PRD。
