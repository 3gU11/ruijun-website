## 1. 目标和结论

### 1.1 要交付的产品

在 Directus 的“内容编辑工作台”中，运营人员按官网 Header 的六个页面进入**同一个页面级编辑窗口**：

```text
Header 页面
  -> 当前页面的业务区块
    -> 真实 Nuxt PC 画布
      -> 右侧属性面板中的可保存 CMS 字段
```

六个一级页面固定为：网站主页、产品展示、先进制造、视频新闻、关于瑞钧、服务支持。

进入页面后，左侧只显示该页面的业务区块，例如“首页视频、三大特点、产品系列、时间轴”。不得再显示一层重复的“网站主页/产品展示”等分类，也不得把完整编辑表单挤进左侧导航。

编辑流程必须是：选页面 -> 选区块或直接点画布元素 -> 修改右侧字段 -> 画布即时显示草稿 -> 保存草稿 -> 刷新确认 -> 审核/发布（后续阶段）。

### 1.2 已确定的边界

本期采用“模板约束的 Visual Editing”，不是任意网页搭建器。

这是必要约束，不是偏好：用户同时要求“像 PPT 一样在画布编辑”和“绝不打乱 Nuxt 原布局、PSD 几何、动画、路由和响应式”。对已有官网页面开放任意拖拽、任意缩放、任意 CSS，这两个目标不能同时可靠实现。

本期允许：

| 对象 | 可以编辑 | 约束 |
| --- | --- | --- |
| 文字 | 内容、字体、字号、字重、行高、颜色、对齐 | 仅限区块白名单和项目字体 |
| 图片/视频 | 已治理素材、替代文本、标题、裁切焦点、适配、海报 | 必须有 Directus 文件、`media_assets` 和 MinIO 对象 |
| 位置/样式 | 预设对齐、有限偏移、最大宽度、层级、显示开关 | 每个区块有边界；超界不允许保存 |
| 列表 | 新增、排序、隐藏、分页策略 | 每条记录都有独立真实 ID；删除可恢复 |
| 按钮/链接 | 文案、图标、已审批 URL | 校验协议、目标与无障碍名称 |

本期不允许：任意改变页面结构、任意绝对定位、任意 CSS、编辑 PSD 文件本身、用本地路径或静态 fallback 冒充可替换 CMS 媒体。

如未来确需真正自由画布，应独立立项“专题页搭建器”，另行处理 PC/移动断点、碰撞、撤销栈、版本迁移、无障碍和性能成本，不能直接加在这六个既有页面上。

| 正式媒体 | 当前 `media_assets=0`；大量页面图片/视频来自 PSD 或静态 fallback | 媒体可替换不具备验收条件 |
| 发布状态 | 六个页面记录是 `draft/unpublished` | 公开端不能作为已发布内容的证明 |

### 2.2 不能据此推导的结论

| 错误前提 | 为什么不成立 | 正确验证方式 |
| --- | --- | --- |
| `HTTP 200` 等于 CMS 内容已经读到 | 可能是缓存、`data: null` 或 fallback | 同时检查受保护 Directus 回读、Nuxt 请求载荷和画布内容 |
| 页面上出现红色可编辑框等于能保存 | 可能没有稳定记录 ID 或字段路径 | 完成“选中-保存-回读-刷新-恢复”闭环 |
| PSD/static 文件可在 CMS 替换 | 没有 Directus 媒体记录、用途、版权和替代文本 | 先完成媒体导入和用途绑定 |
| 一条文字可保存等于整个页面已接 CMS | 页面其他文字、图片、列表可能仍是硬编码或 fallback | 逐元素更新绑定台账 |

### 2.3 需要业务方提供，技术不能自行猜测

1. 正式图片、视频、证书、图标文件，以及版权/授权、用途、替代文本、桌面裁切焦点。
2. 要删除的 CMS 演示资讯、保留资讯与替换规则。
3. 每个区块允许调整的视觉范围，尤其是字号、偏移、宽度、层级和移动端显示顺序。
4. 新闻业务日期的时区和同日排序规则。
5. 编辑、审核、发布是否必须由不同账号执行。

缺少这些输入时，相关项目必须显示“待媒体”或“待业务确认”，不能伪装为已完成。

## 3. 产品结构和数据契约

### 3.1 三层架构

```text
页面模板层：既有 Nuxt 页面、路由、动画、响应式
        ↓
区块组件层：Banner、图文、产品列表、新闻列表、图库、富文本、页尾
        ↓
Directus 数据层：页面、产品、新闻、媒体、版式白名单、审核和版本
```

| 层 | 责任 | 禁止承担 |
| --- | --- | --- |
| Nuxt 模板层 | 保持原视觉结构、动画和响应式；声明区块锚点 | 根据显示文字、坐标或数组下标猜测写入位置 |
| 区块组件层 | 渲染 CMS 数据；声明可视化编辑绑定；限制可调范围 | 直接写数据库或开放任意 CSS |
| Directus 数据层 | 内容、媒体、版式白名单、状态、审计、版本 | 将静态 fallback 伪装为正式内容 |
| 内容编辑工作台 | 元素选择、草稿、预览、保存、错误处理、发布操作 | 改写官网模板结构 |

### 3.2 元素绑定契约

每个可编辑元素必须具备稳定绑定；缺少任一关键字段则只读。

```json
{
  "pageKey": "manufacturing",
  "sectionKey": "precision-machining",
  "collection": "pages",
  "itemId": "8",
  "fieldPath": "sections[precision-machining].title",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

工作台必须始终优先编辑当前草稿记录，而不是左侧列表缓存。跨页面、跨区块、跨记录后必须清空旧选中态，防止串写。

### 3.3 编辑界面要求

- 顶部：页面/区块面包屑、选择/文字/媒体模式、撤销、重做、缩放、保存草稿、预览、状态。
- 左侧：当前页面的区块与记录列表，支持搜索/折叠，不承载完整表单。
- 中央：真实 Nuxt iframe。编辑模式下点击只选中，必须阻止链接跳转、卡片展开、视频播放或视频结束事件对编辑的干扰；浏览模式保留原行为。
- 右侧：仅展示当前元素允许的内容、媒体、受控样式、位置、绑定诊断与保存错误。
- 预览与输入并排，不得覆盖修改区域。视频加载、自动播放失败、播放结束和动画警告不能阻塞选中、预览或保存。

## 5. 执行路线图

### P0-A：工作台可靠性和串写防护

**目标**：画布选中的元素只能写入当前页面、当前区块、当前记录的允许字段。

执行项：

1. 验证首页、产品、制造页之间切换后，旧属性面板和选中框立即清空。
2. 验证制造页 `CNC车间` 画布选中显示 `pages · title`，而非不存在的 `manufacturing_evidence · title`。**已完成，2026-08-26**：临时值保存、认证回读、工作台重新加载和原值恢复均已验证。
3. 验证选择、文字、媒体模式，iframe 重新加载、视频结束、动画运行时均不阻塞编辑。
4. 保存失败时保留草稿并显示实际原因；禁止静默失败或写入列表快照。

**验收**：自动测试 + 扩展构建 + 真实 PC 浏览器；至少一次跨记录切换后的认证 Directus 回读正确。

### P0-B：六页元素绑定清单和文字闭环

**目标**：先消除“官网看得到、工作台找不到”的问题，再扩张编辑能力。

1. 以 [绑定台账](CMS可视化编辑绑定台账.md) 为唯一清单，为每个可见文字、按钮、图标、图片、视频、列表记录来源、集合、记录 ID、字段、编辑状态、媒体状态和证据。
2. 每页选择一个未覆盖的低风险文字字段执行闭环。首页、产品和先进制造已有样本，接下来顺序为：视频新闻、关于瑞钧、服务支持。
3. 一个字段的唯一完成定义：画布选中 -> 即时预览 -> 保存草稿 -> 认证 Directus 回读 -> 工作台整页刷新一致 -> 用同一画布路径恢复原值 -> 最终回读。
4. 无稳定绑定的项必须在工作台显示“待建模/只读/待媒体”和原因。

**建议固定样本**：

| 页面 | 样本字段 | 当前状态 |
| --- | --- | --- |
| 网站主页 | `pages/1.sections[product-task].title` | 已闭环，作为回归样本 |
| 产品展示 | `product_parameters/94.value` | 已闭环，作为回归样本 |
| 先进制造 | `pages/8.sections[precision-machining].title` | 已闭环，作为制造页文字回归样本 |
| 视频新闻 | 一条未使用的 `articles` 标题、摘要或业务日期 | 待选取真实记录 |
| 关于瑞钧 | `pages/2.sections[overview].title` 或共用里程碑字段 | 待验收 |
| 服务支持 | `pages/3.sections[support].title` 或 `service_locations/{id}.address` | 待选取真实记录 |

### P0-C：媒体治理与一条正式媒体闭环

**前置条件**：正式素材与元数据到位。不能绕过此前置条件。

1. 导入一条正式图片或视频，验证 Directus `directus_files`、`media_assets`、MinIO 实际对象、用途、版权、替代文本、发布状态。
2. 将其绑定到一个真实页面字段，完成替换 -> 即时预览 -> 保存 -> 认证回读 -> 刷新 -> 原值恢复。
3. 正式证书、核心设备、首页背景/视频等均在完成第一条媒体闭环后分批接入。

**验收**：`media_assets > 0`，且存在一条从上传到页面替换的可复核链路。`media_assets=0` 时不允许宣称图片/视频已 CMS 化。

### P1-A：列表、分页和内容详情

1. 新闻：标题、业务日期、封面、摘要、图文正文来自同一文章记录，支持新增、编辑、隐藏、排序、详情打开。
2. 视频：上传视频、标题、日期；默认提取首帧为封面，抽帧失败可以指定海报并提示错误。
3. 新闻和视频分享每页 6 条、业务日期降序、支持分页。
4. 产品参数、尺寸图、生产核心设备、证书、品牌、国内/国外客户图库使用独立记录，支持新增、排序、隐藏和按区块展示。

### P1-B：受控位置、样式、审核、发布和回退

1. 为每个区块定义文字样式和位置白名单及边界；超出模板范围时拒绝保存或回退。
2. 验证 PC `1440x900`、`1920x1080`、`3840x2160` 下不覆盖、不溢出、不改变既有布局。
3. 完成 `draft -> in_review -> published -> archived`、角色权限、操作审计、版本恢复、发布/下线和网络失败重试。
4. 公开官网只读取已发布内容；授权预览会话才可读取草稿。不得以 HTTP 状态或缓存判断发布成功。

## 6. 数据和媒体规则

### 6.1 受控位置和文字样式字段

建议每个区块的可视字段使用统一结构，例如：

```json
{
  "content": "生产核心设备",
  "text_style": {
    "font_family": "Source Han Sans CN",
    "font_size": 32,
    "font_weight": 600,
    "line_height": 1.35,
    "color": "#ffffff",
    "align": "left"
  },
  "placement": {
    "align": "left-top",
    "offset_x": 0,
    "offset_y": 0,
    "max_width": 640,
    "z_index": 2,
    "visible": true
  }
}
```

字段只表达模板允许的调整，不能提供任意 `style` 字符串、脚本或外部 URL。

### 6.2 媒体最低交付规格

| 用途 | 最低建议规格 | 必填元数据 |
| --- | --- | --- |
| 首屏图片/视频 | 图片至少 `2560x1440`；MP4 H.264 `1920x1080`、15-60 秒 | 海报、替代文本、PC/移动焦点、版权 |
| 产品/设备图 | `1:1` 或 `4:3`，至少 `1600x1200` | 名称、替代文本、`contain/cover` |
| 新闻封面 | `16:9`，至少 `1600x900` | 标题、业务日期、替代文本、焦点 |
| 证书/尺寸图 | 保持原比例，长边至少 `2000px` | 名称、来源、编号/版本、有效期（适用时） |
| 图标/标志 | SVG 优先；位图至少 `512x512` | 用途、浅深色适配、版权 |

## 7. 测试和发布门槛

每个开发切片必须严格遵循：

```text
失败测试 -> 最小修复 -> 定向测试 -> 相关构建
-> 真实 PC 浏览器 -> 认证 Directus 回读 -> 刷新一致
-> 恢复临时值 -> 更新 PRD 与绑定台账
```

不得以 HTTP `200`、本地缓存、静态 fallback、`data: null`、截图或仅通过单元测试替代真实回读。

本期“PC 六页可视化编辑完成”的发布门槛：

1. 每个承诺编辑的元素有稳定绑定，或明确标记只读/待建模/待媒体及原因。
2. 六页均至少有一个不同字段的真实闭环，且已有两个样本在回归中保持通过。
3. 文字、正式媒体、受控样式/位置、列表和错误恢复分别至少有一个闭环样本。
4. 工作台与原官网在上述三个 PC 视口不发生覆盖、横向溢出或无关布局变化。
5. 所有临时测试值已经恢复；草稿、审核、发布和公开读取的权限边界有证据。
