## 1. 结论与边界

### 1.1 要做的产品

为瑞钧既有 Nuxt PC 官网建设一个**模板约束的可视化编辑工作台**。编辑者从 CMS 进入六个 Header 页面之一，在同一界面中选择业务区块和真实 Nuxt 画布元素，在右侧修改内容，并即时查看草稿效果。

```text
网站页面模板（保留现有 Nuxt 画面）
  -> 页面业务区块（Banner、图文、列表、图库、RichText）
    -> Directus 记录与媒体资产
      -> 内容编辑工作台的选择、编辑、保存、审核与发布
```

六个入口固定为：网站主页、产品展示、先进制造、视频新闻、关于瑞钧、服务支持。进入页面后只显示该页面真实业务区块，例如“首页视频、三大理由、产品系列、时间轴”；不得再出现第二层重复的页面分类。

### 1.2 不做的产品

本期不是网页搭建器，也不是任意 CSS/HTML 编辑器。不能同时承诺“任意拖动、任意缩放、任意改样式”与“Nuxt 原布局、动画、断点完全不动”。前者会破坏后者的可验证性。

允许的“类似 PPT”交互是：画布点击/双击选中、顶部切换选择/文字/媒体模式、右侧编辑字段、有限样式和有限位置。位置和样式必须按区块白名单限制。若后续需要自由专题页，应单独立项，不能直接作用于这六个受保护官网模板。

## 2. 事实、判断与风险

### 2.1 已核实事实

| 项目 | 已核实证据 | 当前结论 |
| --- | --- | --- |
| 本地链路 | Nuxt `4175` -> Directus `8055` -> MySQL `127.0.0.1:3307`；MinIO `9000/9001` | 可继续进行本地端到端验证；每次重启后仍须实测服务状态 |
| 公开内容状态 | 六个页面记录仍为 `draft/unpublished` | 公开官网不能作为保存或发布成功的唯一证据 |
| 工作台基础 | 中文入口、六页导航、页面区块入口、真实 Nuxt iframe、画布选择、右侧面板、草稿保存已存在 | 可作为后续闭环基础，但不是“全部内容已接入”的证明 |
| 文字闭环样本 | 首页、产品、制造、新闻、关于瑞钧均至少有一个字段完成选中、即时预览、保存、认证回读、刷新、恢复原值 | 证明链路可行，不代表其它字段自动可编辑 |
| 关于页正文 | `pages/2.sections[overview].body` 已完成完整闭环 | 短 CMS 正文不会再被静态 fallback 静默覆盖 |
| 工作台导航 | 服务支持按钮被关于页菜单遮挡的问题已修复并经过浏览器验证 | 导航布局回归仍需保留测试 |
| 正式媒体 | 当前 `media_assets=0`；大量图片、视频、图标仍是 PSD/static fallback | 不能宣称这些素材已经可在 CMS 中替换 |

### 2.2 不可作为完成证据的情况

下列现象都不足以单独证明 CMS 已真实生效：HTTP `200`、`data: null`、缓存命中、截图、iframe 可见、静态 fallback、画布出现选框、侧栏出现字段。保存结论必须包含正确集合、记录 ID、字段路径的认证 Directus 回读。

### 2.3 当前主要风险

1. 把静态 PSD/fallback 当成 CMS 数据，会造成“工作台改了但官网没变”或写入错误目标。
2. 跨页面、跨区块或跨集合不清空选中状态，可能把新内容写到旧记录。
3. 若先开放自由拖拽和样式，现有 Nuxt 布局会先失稳，六页真实内容绑定反而无法验收。
4. 未提供版权、用途、替代文本、裁切规则的媒体不应开放上传替换。
5. 草稿和公开内容尚未完成角色与发布流程验证，保存草稿不得自动视为公开上线。

## 3. 用户、权限与工作流

| 角色 | 可执行操作 | 不可执行操作 |
| --- | --- | --- |
| 编辑者 | 选择画布元素、保存草稿、上传待审核素材、提交审核 | 直接发布、删除不可恢复内容 |
| 审核者 | 查看预览、通过或退回草稿 | 修改未经授权的模板结构 |
| 发布者 | 发布、下线、从版本恢复 | 绕过审核要求发布 |

内容状态目标：`draft -> in_review -> published -> archived`。

固定操作流程：

```text
选择页面 -> 选择业务区块或画布元素 -> 修改受支持属性
-> iframe 即时显示草稿 -> 保存草稿 -> 认证回读 -> 刷新一致
-> 提交审核 -> 发布者发布
```

切换页面、区块、记录或关闭工作台时，未保存修改必须提示；切换后必须清空旧的选中态、属性面板与保存目标。

## 4. 工作台验收规格

### 4.1 布局

- 顶部：页面/区块面包屑、选择/文字/媒体模式、撤销、重做、缩放、保存草稿、预览状态。
- 左侧：仅显示当前页面的业务区块和相关业务记录，可搜索、折叠或分页；不得放置完整编辑表单。
- 中间：真实 Nuxt PC iframe。编辑模式拦截跳转、播放、展开等原交互；浏览模式恢复官网行为。
- 右侧：当前元素的内容、媒体、样式、位置、绑定诊断、保存错误与恢复入口。
- 三栏均要实际占位，预览不得作为浮层遮挡输入区。

### 4.2 每个可编辑元素的数据契约

缺少以下任何一项的元素只读，并向编辑者显示原因：

```json
{
  "pageKey": "service",
  "sectionKey": "support",
  "collection": "pages",
  "itemId": "3",
  "fieldPath": "sections[support].title",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

禁止按显示文字、数组下标、旧侧栏快照、DOM 坐标或 fallback 资源猜测写入目标。

### 4.3 可编辑能力与限制

| 能力 | 本期允许 | 约束 |
| --- | --- | --- |
| 文字 | 标题、正文、按钮、年份、参数、链接说明 | 必须有稳定字段路径；富文本安全过滤 |
| 文字样式 | 字体、字号、字重、行高、颜色、对齐 | 区块白名单、范围校验和默认值恢复 |
| 图片/视频 | 文件、替代文本、海报、焦点、`cover/contain` | 先完成媒体资产和 MinIO 实物校验 |
| 受控位置 | 预设对齐、有限偏移、最大宽度、层级、显隐 | 按区块边界限制；不得改变模板结构 |
| 列表 | 新增、排序、隐藏、分页/轮播配置 | 每项独立真实 ID；删除可恢复 |

## 6. 媒体治理与交付规格

媒体开放替换前必须具备：Directus 文件记录、`media_assets` 业务记录、MinIO 实际对象、用途、版权/来源、替代文本、发布状态、PC 裁切焦点与适配方式。

| 用途 | 最低建议规格 | 必填元数据 |
| --- | --- | --- |
| 首屏图片/视频 | 图 `2560x1440`；MP4 H.264 `1920x1080`、15-60 秒 | 海报、替代文本、焦点、版权/来源 |
| 产品/设备图 | `1:1` 或 `4:3`，至少 `1600x1200` | 名称、替代文本、适配方式 |
| 新闻封面 | `16:9`，至少 `1600x900` | 标题、业务日期、替代文本、焦点 |
| 证书/尺寸图 | 原比例，长边至少 `2000px` | 名称、来源、编号/版本、有效期（如适用） |
| 图标/标志 | SVG 优先；位图至少 `512x512` | 名称、用途、深浅色适配、版权 |

视频首帧抽取失败时必须给出失败状态并允许人工指定海报。`media_assets=0` 时，未托管图片、视频、PSD 图层和 static fallback 均显示为“只读/待媒体”。

## 8. 单项验收协议

每个字段、媒体或列表功能按以下顺序执行，不能跳步：

```text
失败测试 -> 最小修复 -> 定向测试 -> 相关构建
-> 真实 PC 浏览器画布选中 -> iframe 即时草稿预览
-> 保存草稿 -> 认证 Directus 回读 -> 刷新一致
-> 同一路径恢复原值 -> 最终认证回读 -> 更新绑定台账
```

一项标记为“已闭环”的最低条件：

1. 画布选择命中正确的集合、记录 ID 与字段路径。
2. 临时值在同一 iframe 立即可见，不依赖视频结束或重新进入页面。
3. 保存后可认证回读到目标字段，刷新工作台与页面仍一致。
4. 测试值已通过同一路径恢复，最终回读无残留。
5. 未改变既有 Nuxt 布局、动画、路由或响应式。

PC 视口：`1440x900`、`1920x1080`、`3840x2160`。移动端本期只回归公开页面，不做移动端编辑器。

## 9. 暂停条件与业务待决项

出现以下情况时必须暂停对应功能并确认，不由开发自行推测：

1. 需要改变 PSD、现有 Nuxt 几何、动画、路由或响应式才能实现编辑。
2. 没有正式素材、版权或用途信息，却要求 static/PSD 素材作为 CMS 正式可替换媒体。
3. 同时要求任意 CSS/自由拖拽和原版式完全不变。
4. 要删除演示新闻、证书、媒体或历史内容，但没有保留清单和删除范围。
5. 未定义新闻日期时区、同日排序规则、审核人与发布责任人。
6. 要公开草稿页面，但发布状态、权限和回退未通过验收。
