## 0. 本版重整结论

本项目不是重做 Nuxt 官网，也不是制作一个可任意拖拽 DOM 的通用建站器。本期要交付的是：在不改变现有 Nuxt 视觉结果的前提下，让运营人员在真实 PC 官网画布中选择内容，并以接近 PowerPoint 的方式修改文字、媒体、重复项顺序和受控视觉参数。

本版修正三个容易导致误判的前提：

1. “页面上有字段”不等于“已连接 CMS”。完成必须包含选择、临时预览、保存、Directus 回读、刷新保持和原值恢复。
2. “自动化测试全绿”不等于“实时预览可用”。真实 Chromium 中的画布 DOM 必须实际更新。
3. “位置可调”不等于“任意坐标”。自由拖拽会破坏既有 PSD 布局、动画和响应式，本期只开放模板允许的排序、对齐、焦点和有限偏移。

当前执行顺序仍由实时预览优先。已定位并修复首页派生链的缓存问题：`cmsPreviewRecord → pageContent → reasons/marqueeItems → DOM` 现在在同一响应式副作用中重新派生。定向测试、全量测试和生产构建已通过；真实 Chromium 的 CMS 编辑闭环仍未签收，因为当前工作台被重定向到登录页，尚未取得可用的验收登录态。不得把代码测试通过写成 Directus 保存或浏览器闭环已完成。

### 1.2 不可突破的模板红线

Nuxt 独占以下内容，CMS 和工作台不得改写：

- 页面 DOM 和 Vue 组件结构；
- 现有 CSS 布局、PSD 坐标和响应式断点；
- GSAP 或其他动画时间线；
- 路由、页面锚点和导航行为；
- 任意 HTML、JavaScript、CSS 字符串和字体文件；
- 未列入白名单的绝对定位、层级和尺寸。

### 1.3 非目标

- 手机端可视化编辑；
- Webflow、HTMLPage 或 PowerPoint 式自由页面搭建；
- 多人实时协作、模板市场和插件市场；
- 生产 CDN、视频转码平台和公网部署；
- 通过迁移演示资讯数量来代替真实内容验收。

## 2. 系统分层与所有权

```text
Nuxt 页面模板层
布局 / 坐标 / 动画 / 路由 / 锚点 / 响应式
                    ↓
Visual Binding 编辑层
选择 / 高亮 / 字段定位 / 临时预览 / 历史 / 受控样式
                    ↓
Directus 数据与流程层
页面 / 产品 / 新闻 / 媒体 / 权限 / 审核 / 版本 / 发布
                    ↓
MySQL 3307 + MinIO 9000/9001
```

| 对象 | 唯一所有者 | 规则 |
| --- | --- | --- |
| 页面结构与动画 | Nuxt | CMS 不能保存 DOM、脚本或任意 CSS |
| 可编辑目标身份 | Visual Binding | 不得根据显示文字、路由名称或排序后的下标猜测 |
| 业务内容和状态 | Directus | 同一可见内容只能有一个主数据来源 |
| 媒体对象 | Directus + MinIO | 页面只保存受治理媒体引用，不保存本地路径 |
| 公开读取 | Nuxt BFF | 只返回当前角色可读且已发布的内容 |

已选本地拓扑为 `Nuxt 4175 → Directus 8055 → MySQL 3307 / MinIO 9000、9001`。每次重启后仍必须重新核对进程、端口、健康接口和真实请求；不得操作机器上既有的 MySQL `3306`。

### 5.1 重复内容的唯一来源

- 首页和关于页的时间轴共用同一份里程碑内容，可分别保存展示配置。
- Header 和 Footer 全站共用，禁止每页复制一份。
- `pages.sections` 与独立集合存在相似内容时，必须逐元素指定主来源；迁移后停止写旧来源。
- PSD 或代码 fallback 可以继续显示，但没有真实字段或媒体角色时只能只读，不能伪装成 CMS 内容。

## 6. Visual Binding 强制契约

每个可编辑元素必须暴露以下完整绑定：

```json
{
  "collection": "pages",
  "itemId": "1",
  "sectionKey": "performance",
  "fieldPath": "body",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

| ID | 规则 |
| --- | --- |
| BIND-01 | `collection`、真实 `itemId`、`sectionKey`、`fieldPath` 任一缺失即只读 |
| BIND-02 | `itemId` 必须来自 Directus 响应，不能从名称、路由或显示顺序推断 |
| BIND-03 | `pages` 的 `fieldPath` 相对选中的 `sections[]` 区块，例如 `body` |
| BIND-04 | `homepage_sections` 使用自身结构，例如 `content.body`，不得套用 `pages` 规则 |
| BIND-05 | 重复项必须保留稳定记录 id 或源索引，排序和筛选后提交前再次校验 |
| BIND-06 | 画布值、属性值和绑定来源不一致时禁止编辑与保存 |
| BIND-07 | 保存前校验集合、记录、字段、版本和权限；禁止自动创建不存在的路径 |
| BIND-08 | 跨集合保存逐项返回结果；失败项可重试，成功项不得重复写入 |
| BIND-09 | 不允许通过直接改 DOM 完成长期预览；Vue 状态、画布和保存源必须一致 |

已确认的首页样本绑定为：

```text
网站主页 / 三大理由 / 增效降损正文
→ pages / 1 / performance / body
```

该样本目前只能标记为“字段目标已核对、完整闭环未验收”。

## 7. 受控视觉和媒体能力

| 类别 | P0 允许 | 强制限制 |
| --- | --- | --- |
| 文字 | 内容、预设、字号、字重、行高、颜色、对齐、最大宽度 | 授权字体和范围白名单；长文本溢出检查 |
| 位置 | 模板、顺序、对齐、媒体焦点、桌面有限偏移 | 不生成任意绝对定位；越界由服务端拒绝 |
| 图片 | 受审核素材、替代文本、焦点、遮罩、`cover/contain`、顺序 | 禁止本地路径和不可信外链 |
| 视频 | 文件、海报、静音、循环、移动替代媒体、字幕或文字稿 | 首屏不依赖播放；失败保留海报和文字 |
| 重复项 | 新增、删除、排序、分页或轮播参数 | 稳定身份；不能用当前数组下标作为长期 id |
| 响应式 | 安全模板、显示开关、独立字号 | PC 可编辑；手机 P0 仅使用预设并做只读回归 |

“图片和视频不限制存放数量”仅指素材库和业务记录可扩展，不代表一个页面无限渲染。产品、设备、证书、客户和图库必须使用分页、轮播、缩略图或懒加载。

### 7.1 媒体流程

```text
上传 → Directus 文件记录 → MinIO 对象
→ 用途/版权/规格审核 → 页面草稿引用 → 内容审核 → 发布
```

图片至少记录用途、替代文本、版权、尺寸、比例和格式。视频至少记录标题、海报、时长、编码、用途、版权及可选字幕或文字稿。视频首帧可作默认海报，但必须允许人工替换。

## 8. 保存、预览与发布流程

| 阶段 | 正常结果 | 失败处理 |
| --- | --- | --- |
| 选择 | 高亮目标并显示中文名称和完整绑定 | 绑定缺失或值冲突则只读 |
| 临时编辑 | 300 ms 内开始更新目标画布，不整页刷新 | 保留输入并显示连接或校验错误 |
| 撤销/重做 | 属性面板、画布和本地历史一致 | 禁止只恢复一侧状态 |
| 保存草稿 | 按目标返回成功或失败并建立新历史基线 | 部分失败不得显示全部成功 |
| 回读 | Directus 返回的版本和值与请求一致 | 保留本地草稿，提供单项重试 |
| 刷新 | 已保存草稿在授权预览中保持 | 不得退回 fallback 冒充保存成功 |
| 审核发布 | 审核通过后公开 BFF 才可读取 | 草稿、退回和未来发布日期内容不公开 |
| 版本回退 | 建立可追踪的新版本并恢复历史内容 | 不直接覆盖审计记录 |

公开接口返回 HTTP 200 但 `data: null` 不能证明已读取 CMS 内容；还必须核对 `source`、记录值和发布状态。

### 10.2 历史浏览器证据

此前 Chromium 中已经观察到：CMS 表单和属性面板显示临时值，Nuxt 共享状态也包含临时值，但 iframe 中 `#reason-performance .performance-statement` 仍显示原值。该证据覆盖了消息传递，不覆盖 DOM 响应式更新。本轮已用红测锁定首页派生链并完成最小修复；因工作台当前无登录态，修复后的真实画布重绘、撤销/重做/取消和 Directus 回读尚未取得新浏览器证据。

2026-08-25 本轮在最新生产构建中复现同一结果，并排除了以下候选解释：旧 bundle 缓存、`overlayRecord()` 未直接读取命名状态、首页 computed 未显式消费该状态、每个 composable 实例使用本地 `shallowRef`、Nuxt 插件共享 `shallowRef` 以及对共享 ref 执行 `triggerRef()`。这些方案均出现“Nuxt 状态已是临时值、最终 DOM 仍是原值”。因此下一轮不得重复堆叠 ref 或 revision 计数器；应直接观测首页 `pageContent → reasons → marqueeItems → render` 每一级的运行时值和 Vue 更新调度，定位临时值在哪一级丢失。

### 10.3 当前不得宣称完成的项目

- 修复后的共享响应式记录尚未完成登录态下的浏览器闭环；
- 首页样本文字尚未完成保存、Directus 回读、刷新保持和原值恢复；
- 六页尚未逐可见元素完成唯一来源与绑定审计；
- 图片、视频、排序和视觉参数尚未各自形成真实 Directus/MinIO 闭环；
- 审核、发布、退回和版本回退尚未在当前数据上形成完整证据。

## 11. 继续执行计划

每个切片严格遵循：

```text
先写失败测试 → 最小实现 → 定向测试 → 全量测试 → 生产构建
→ 真实 Chromium → Directus 回读 → 刷新复核
→ 撤销/重做/失败恢复 → 恢复测试数据 → 登记证据
```

### P0-1 实时预览最小闭环（当前进行中）

范围只包括 Nuxt 临时状态到真实 DOM 的响应式更新，不改任何页面布局和动画。

1. 先取得或恢复 Directus 工作台的合法验收登录态；只读检查当前页面和权限。
2. 在最新 Nuxt 重启后用 Chromium 验证当前共享记录方案。
2. 执行临时修改、画布更新、撤销、重做、取消和原值恢复。
3. 若仍失败，先确认 composable 是否被打包为多个客户端实例，再决定使用 Nuxt 客户端插件或显式 store 单例。
4. 不接受直接修改 DOM 文本作为长期方案。

退出条件：属性面板、CMS 表单、Nuxt 状态和目标 DOM 同步；不刷新、不保存测试值、不改变画面。若无登录态，只能标记“阻塞于验收前置条件”，不得伪造通过。

### P0-2 首页第一条真实保存闭环

```text
读取原值 → 临时修改 → 即时预览 → 撤销 → 重做 → 取消
→ 再次修改 → 保存 → Directus 回读 → 刷新保持
→ 恢复原值 → 再次保存和回读
```

退出条件：画布、属性、请求和回读四处一致；只写目标字段；最终恢复原值。

### P0-3 全宽工作台验收

1. 折叠 Directus 原始表单，确保导航、画布和属性面板并列。
2. 实测 `1440x900`、`1920x1080`、`3840x2160`。
3. 实测面板开关、缩放、滚动、区块跳转及视频未结束时操作。

退出条件：1440 下有效画布不少于 720 px；无覆盖、重叠或工具栏溢出；画布缩放不改变 Nuxt 坐标。

### P0-4 六页逐元素绑定审计

按网站主页、产品展示、先进制造、视频新闻、关于瑞钧、服务支持、全站设置的顺序执行：

```text
可见元素盘点 → 唯一来源 → 完整绑定 → 画布选择
→ 临时编辑 → 保存目标核对 → Directus 回读 → 刷新 → 恢复样本
```

退出条件：每个可见元素有唯一状态和证据；fallback 与缺字段元素明确只读或待建模。

### P0-5 媒体、重复项和视觉参数闭环

1. 各用一张审核图片和一个短视频验证替换、海报、焦点、撤销、保存、刷新和恢复。
2. 核对 Directus 文件记录、MinIO 对象和页面引用。
3. 验证三大理由、产品参数、新闻、设备和图库的新增、删除、排序及稳定身份。
4. 验证字号、字重、颜色、对齐和有限偏移的前后端白名单。
5. 模拟 Directus 失败、MinIO 失败、预览断连和跨集合部分失败。

退出条件：失败不丢草稿和原媒体引用；排序不写错项；越界参数被服务端拒绝。

### P0-6 内容行为、权限与发布闭环

1. 新闻和视频分别验证第 7 条进入下一页，并按业务发布日期降序。
2. 产品和大型图库验证分页、轮播或懒加载。
3. 验证草稿、审核、批准、发布、退回和版本回退。
4. 先识别和备份演示资讯，再按业务确认清单删除，禁止模糊批量删除。
5. 验证公开 BFF 只返回已发布样本，草稿不泄漏。

退出条件：API 权限真实生效；发布与回退可追溯；所有测试数据和临时媒体恢复或清理。

### P1 与 P2

- P1：版本差异、批量排序、媒体高级筛选、审核备注、操作日志、导入导出、辅助线和细粒度权限。
- P2：手机端可视化编辑、自由模板编辑器、生产转码/CDN、多人实时协作和模板市场。

P1、P2 不得绕过 P0 的绑定、媒体、权限和发布规则。

## 13. P0 完成定义

只有以下项目全部通过，才能宣布“PC 六页 Visual Editing P0 完成”：

- [ ] 六页按真实区块组织，无两层同名分类。
- [ ] 全宽工作台可边编辑边预览，面板不覆盖画布。
- [ ] 单击选择、文字编辑、媒体替换和区块定位可用。
- [ ] 临时修改无需刷新即可同步到真实 Nuxt DOM。
- [ ] 视频未结束、失败或被阻止时仍能编辑。
- [ ] 每个 P0 可编辑元素都有完整、唯一且可回读的绑定。
- [ ] 画布值、属性值、请求值和 Directus 回读值一致。
- [ ] PSD/代码 fallback 明确只读，不冒充 CMS 内容。
- [ ] 文字、图片、视频、排序和受控视觉属性完成真实闭环。
- [ ] 撤销、重做、取消、刷新、离开提示和失败恢复通过。
- [ ] 跨集合部分失败可识别、可重试且不重复写入。
- [ ] 新闻/视频分页排序和大型图库按需加载符合规则。
- [ ] 草稿、审核、发布、退回和回退权限在 API 层有效。
- [ ] 六页 PC 端无非内容性布局、坐标、动画、路由和锚点变化。

## 14. 风险、成本与待决策项

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 同一内容存在多个来源 | 预览与发布不一致、修改互相覆盖 | 逐元素确定唯一主来源并停止写旧来源 |
| 使用数组下标作为身份 | 排序后写错项目 | 使用真实 id 或稳定源索引，提交前复核 |
| 直接改 DOM 修预览 | Vue 状态、历史和保存链路分裂 | 修响应式单例或受测 store |
| 名义全宽但实际过窄 | 无法边做边看 | 720 px 硬门槛，必要时使用独立路由 |
| 开放过多视觉参数 | 破坏 PSD、品牌和手机端 | 模板和白名单，服务端拒绝越界值 |
| 未审核业务内容 | 宣传数字、证书、Logo、电话错误或侵权 | 指定业务负责人并在发布前签字 |
| 不限量媒体直接渲染 | 首屏性能、内存和带宽恶化 | 缩略图、分页、轮播和懒加载 |
| 只验证本机 | 生产缺 HTTPS、备份、CDN、转码和监控 | 本地 P0 与生产上线另行验收 |

以下决策不阻塞 P0-1 到 P0-3，但会阻塞真实内容发布和最终签字：

1. 编辑、审核、发布是否强制三人分离；
2. 第一批闭环使用哪组已审核文字、图片和短视频；
3. 宣传数字、证书、专利、客户 Logo、负责人和联系方式的确认人；
4. 新闻排序是否最终采用业务发布日期；本版暂按业务发布日期；
5. 产品、设备、证书和客户图库的默认每页或每屏数量；
6. 哪些记录是可删除演示资讯，哪些已转为真实资料。
