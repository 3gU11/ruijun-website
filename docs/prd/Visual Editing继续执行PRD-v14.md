## 1. 执行摘要

本项目不是重做官网，也不是开发 HTMLPage、Webflow 或 WordPress 式自由建站器。本期交付的是一个受控的 Visual Editing 工作台：运营人员在真实 Nuxt 页面上选择内容，用接近 PowerPoint 的操作方式修改文字、图片、视频、列表顺序和有限的视觉属性；Nuxt 继续独占页面布局、坐标、动画、路由、锚点、组件结构和响应式规则。

当前不能宣称“六页已经可视化编辑”。首页文字的错误字段路径已经修正，但实时预览仍有阻断缺陷：CMS 发出的临时值已到达 Nuxt 共享状态，画布 DOM 没有重新渲染。正确的继续顺序是：

```text
修复预览响应式更新
→ 完成首页一条文字的保存/回读/恢复闭环
→ 验收全宽工作台
→ 逐元素审计六页绑定
→ 完成媒体、排序、视觉属性和发布闭环
```

## 2. 前提核对

| 原说法或隐含前提 | 判断 | 依据与处理 |
| --- | --- | --- |
| 只要工作台显示了字段，就能安全保存 | 错误 | 字段必须同时具有真实集合、记录 id、区块和字段路径，并与画布可见值一致 |
| 当前实时预览完全不可通信 | 错误 | `postMessage`、消息校验和 Nuxt 共享状态更新已实测成功；当前失败点是 DOM 未响应更新 |
| 首页字段绑定仍指向 `content.items.0.body` | 已过时 | `pages/1` 的 `performance` 正文已修正为相对路径 `body`；`homepage_sections` 才使用 `content.*` |
| 自动化测试通过就等于产品完成 | 错误 | 还需要真实 Chromium、Directus 保存回读、刷新保持、撤销/重做和失败恢复证据 |
| “像 PPT”代表可以自由拖动任何元素 | 错误 | 任意坐标和 CSS 会破坏既有 PSD 布局与响应式；只允许模板内排序、对齐和受限偏移 |
| 六页看得到的所有素材都已经有 CMS 字段 | 未证实 | PSD/代码兜底素材仍可能存在；没有真实媒体角色的元素必须只读 |
| 图片库存不限量等于页面一次展示不限量 | 错误 | 素材库可以扩展，前台必须分页、轮播或懒加载 |
| HTTP 200 说明 Nuxt 已读到 CMS 正式内容 | 错误 | `data: null` 也可能返回 200；必须核对记录、内容和发布状态 |

## 3. 产品目标

### 3.1 P0 目标

1. 在一个工作台内按“六个页面 → 页面真实区块”组织内容，不出现两层同名页面分类。
2. 中央画布显示真实 Nuxt PC 页面，支持区块定位、单击选中、文字编辑和媒体替换。
3. 属性面板明确显示业务名称及 `collection / itemId / sectionKey / fieldPath`。
4. 临时修改立即显示在画布，无需等待视频结束，也无需刷新 iframe。
5. 文字、图片、视频、重复项排序和白名单视觉属性各至少完成一条真实保存闭环。
6. 保存、回读、刷新、撤销、重做、取消、离开提示和失败恢复均有证据。
7. 六页每个承诺元素均标记为 `已闭环`、`只读`、`待建模` 或 `延期`，不得用“整页已接入”代替字段级验收。
8. 改造前后官网布局、坐标、动画、路由、锚点和响应式结构没有非内容性变化。

### 3.2 成功指标

| 指标 | P0 门槛 |
| --- | --- |
| 预览反馈 | 属性值改变后，目标画布内容在 300 ms 内开始更新；不进行整页刷新 |
| 绑定准确率 | 纳入 P0 的可编辑元素 100% 具有完整、唯一、可回读的绑定 |
| 错写容忍度 | 0 个字段写入错误集合、错误记录或错误数组项 |
| PC 可用宽度 | `1440x900` 下属性面板打开时有效画布宽度不低于 720 px |
| 数据恢复 | 所有验收临时值最终恢复原值，Directus 回读一致 |
| 结构回归 | 六页 PC 基准视口无非内容性布局、动画、路由和锚点回归 |
| 移动端回归 | `390x844` 只读页面无新增重叠、横向溢出和路由错误 |

300 ms 是本地工作台的交互目标，不是公网发布 SLA；正式环境指标需在部署方案中另行定义。

### 3.3 非目标

- 不重做 Nuxt 官网画面。
- 不开放自由 DOM 排版、任意 HTML、JavaScript、CSS、字体文件和无限像素坐标。
- 不允许运营人员改变路由、动画时间线、锚点和组件结构。
- 不在 P0 提供手机端可视化编辑。
- 不在 P0 建设生产 CDN、视频转码集群、多人实时协同或模板市场。
- 不把演示资讯迁移数量当作真实内容完成度。

## 4. 产品与技术边界

```text
Nuxt 页面模板层
  布局、坐标、动画、路由、锚点、组件、响应式
                    ↓
Visual Binding 编辑层
  选中、高亮、字段定位、预览同步、历史、受控样式
                    ↓
Directus 数据层
  页面、产品、新闻、媒体、权限、审核、版本、发布
                    ↓
MySQL 3307 + MinIO 9000/9001
```

### 4.1 所有权规则

| 能力 | 唯一所有者 | 禁止事项 |
| --- | --- | --- |
| 页面结构与动画 | Nuxt | CMS 不得保存 DOM、脚本或任意 CSS |
| 可编辑目标身份 | Visual Binding | 不得根据显示文字、路由名称或排序后数组下标猜测目标 |
| 业务内容与状态 | Directus | Nuxt fallback 不得伪装成已连接 CMS 的内容 |
| 媒体对象 | MinIO，经 Directus 管理 | 页面不得直接持有本地磁盘路径或不可信外链 |
| 发布读取 | Nuxt BFF | 公开接口不得返回草稿或未授权字段 |

### 4.2 数据来源决策

同一可见内容只能有一个主数据来源。若 `pages.sections` 与独立集合同时包含相似内容，必须逐元素选择主来源，迁移完成后停止写入旧来源。P0 不允许“双写保持一致”作为长期方案。

## 5. 用户、权限与状态

| 角色 | 允许操作 | 禁止操作 |
| --- | --- | --- |
| 内容编辑 | 修改草稿内容、媒体、排序和受控视觉参数 | 发布、改权限、录入代码、绕过媒体审核 |
| 内容审核 | 查看差异、来源、版权与规格；批准或退回 | 修改绑定契约、绕过服务端校验 |
| 发布人员 | 发布已批准版本、执行回退 | 发布未审核版本、覆盖版本冲突 |
| 开发维护 | 维护模板、绑定、迁移、监控和恢复 | 代替业务确认宣传数字、证书、客户 Logo 和联系方式 |

权限必须在 Directus API 层执行，仅隐藏按钮不算权限控制。

```text
草稿 → 待审核 → 已批准 → 已发布
          └────→ 已退回 → 草稿
已发布 → 已归档 / 回退到历史版本
```

## 6. 工作台体验

### 6.1 信息架构

```text
┌────────────────────────────────────────────────────────────────────┐
│ 页面 | 选择/文字/媒体 | 撤销/重做 | 缩放 | 保存草稿 | 退出       │
├──────────────┬──────────────────────────────────┬──────────────────┤
│ 页面/区块导航│       真实 Nuxt PC 页面画布      │ 选中元素属性     │
│ 可折叠       │       单击选择、定位、滚动       │ 内容/媒体/样式   │
└──────────────┴──────────────────────────────────┴──────────────────┘
```

- 可视化编辑必须进入独立全宽模式；Directus 原始记录表单不能长期占用画布宽度。
- 左侧导航展开建议 200-240 px，可折叠。
- 右侧属性面板建议 300-360 px，不得覆盖画布。
- 顶部使用图标加中文工具提示；控件不得重叠或把画布顶出可用区域。
- 画布缩放只改变编辑视口，不改变 Nuxt 页面真实 CSS 和断点。
- 只提供 PC 编辑设备；平板和手机按钮在 P0 作为只读预览，不允许保存位置变化。

| 产品展示 | 页面首屏、分类筛选、产品系列、产品型号、参数与尺寸图、资料下载 |
| 先进制造 | 页面首屏、工艺画布、制造区域、核心设备 |
| 视频新闻 | 页面首屏、动态新闻、视频分享 |

Footer 可从首页定位，但只能维护一份数据，不复制为首页专属条目。

### 6.3 核心操作

| 操作 | 正常结果 | 失败处理 |
| --- | --- | --- |
| 单击元素 | 高亮并显示业务名称、绑定来源和当前值 | 绑定不完整或值不一致时只读 |
| 双击文字 | 进入就地编辑，属性面板同步 | 富文本必须清洗；禁止脚本与任意样式 |
| 选择图片/视频 | 显示替换、焦点、适配和规格 | 未审核媒体不可进入发布状态 |
| 拖动 | 仅改变允许的顺序、对齐或受限偏移 | 超范围、重叠或破坏模板时拒绝 |
| 点击区块导航 | 打开正确路由并滚动到真实锚点 | 锚点缺失时明确报错，不静默回页首 |
| 保存草稿 | 显示逐目标结果并建立新历史基线 | 部分失败不得显示为全部成功 |
| 切换页面或退出 | 已保存内容保持；未保存内容先确认 | 不允许无提示丢弃草稿 |

### 6.4 视频预览

- 编辑模式先显示海报和文字，视频异步加载。
- 导航、滚动、选择和编辑不等待视频播放结束。
- 自动播放必须静音；被浏览器阻止、加载失败或解码失败时仍可编辑。
- 支持暂停、跳过和替换海报。
- 视频失败时保留海报、文字、错误状态和重试入口。

## 7. Visual Binding 强制契约

每个可编辑元素必须提供完整绑定：

```json
{
  "collection": "pages",
  "itemId": "1",
  "sectionKey": "performance",
  "fieldPath": "body",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

### 7.1 绑定规则

1. `collection`、真实 `itemId`、`sectionKey`、`fieldPath` 任一缺失时只读。
2. `itemId` 必须来自 Directus 响应，不能从路由、名称或可见顺序推断。
3. 对 `pages`，先用 `sectionKey` 定位 `sections[]` 中的区块，`fieldPath` 相对于该区块，例如 `body`。
4. 对 `homepage_sections`，路径按独立记录结构保存，例如 `content.body`；不能与 `pages` 共用前缀规则。
5. 重复项排序或过滤后必须保留稳定记录 id 或原始索引；提交前再次校验。
6. PSD 或代码兜底可以显示，但没有真实字段和媒体角色时只能只读。
7. 画布值与属性面板值不一致时禁止编辑和保存。
8. 保存前校验集合、记录、字段、版本和权限；禁止自动创建不存在的路径。
9. 跨集合保存逐项返回结果，失败项可单独重试，成功项不得重复写入。

### 7.2 当前首页基线

已确认首页文字“效能提升50%，丝损降低30%”的目标为：

```text
pages / 1 / performance / body
```

当前代码已把 `pages` 的路径修正为 `body`，并保留 `homepage_sections` 使用 `content.*` 的差异。浏览器已显示来源 `pages · body`，属性值与可见文字相同。该项状态是“绑定修复完成、保存闭环未完成”，不能写成 P0 已验收。

## 9. 受控视觉能力

| 类别 | P0 允许 | 强制限制 |
| --- | --- | --- |
| 文字 | 内容、样式预设、字号、字重、行高、颜色、对齐、最大宽度 | 只用授权字体；按元素类型限定范围 |
| 位置 | 模板、顺序、对齐、层级、桌面横纵偏移 | 偏移限制为容器比例 `-30..30`；不得生成任意定位 |

| 响应式 | 安全模板、显示开关、独立字号 | PC 可编辑；手机 P0 只使用安全预设 |

“位置可调”是受模板约束的参数编辑，不是自由拖动 DOM。若某个区块确需自由画布，应另立模板编辑器项目，不能混入本期内容工作台。

## 10. 数据、媒体与发布

### 10.1 本地链路

```text
Nuxt 4175 → Directus 8055 → MySQL 127.0.0.1:3307
                              ↘ MinIO 9000/9001
```

- 只能使用隔离 MySQL `3307`，不得操作既有 `3306`。
- Directus 环境变量改变后必须重启，再验证数据库和对象存储。
- MinIO 正常不能只看进程名；必须验证端口、健康接口和真实对象写入。
- 预览与公开读取必须区分 Directus 内容、浏览器缓存和 Nuxt fallback。

### 10.2 媒体流程

```text
上传 → Directus 文件记录 → MinIO 对象
→ 用途/版权/规格审核 → 页面草稿引用 → 内容审核 → 发布
```

图片至少记录用途、替代文本、版权、尺寸、比例和格式。视频至少记录标题、海报、时长、编码、用途、版权及可选字幕/文字稿。视频首帧可以作为默认海报，但必须允许人工替换，避免黑帧或转场帧。

### 10.3 内容规则

- 新闻和视频分享每页最多 6 条，按业务发布日期降序。
- 产品、设备和图库的库存可扩展，前台通过分页、轮播或懒加载限制渲染。
- 演示资讯删除前必须识别、备份并与真实内容隔离；不得按名称模糊批量删除。
- 公开 BFF 只返回已发布且当前角色有权读取的内容。

### 11.2 当前根因边界

已证实：发送端、`postMessage`、来源校验、内容清洗和 Nuxt 共享状态写入正常。

当前高概率原因：替换共享预览对象后，现有 composable 消费者没有收到响应式更新通知。首选最小修复是显式触发 ref 更新；如果浏览器仍不重渲染，再引入有测试覆盖的 revision/event 机制。禁止直接硬改 DOM 文字作为长期方案，因为那会绕过 Vue 状态、撤销/重做和刷新一致性。

## 12. 继续执行计划

每个切片严格执行：

```text
先写失败测试 → 最小实现 → 定向测试 → 全量测试 → 生产构建
→ 真实 Chromium → Directus 回读 → 刷新复核
→ 撤销/重做/失败恢复 → 恢复测试数据 → 登记证据
```

### P0-1 修复实时预览响应式更新

范围：仅修复 Nuxt 共享预览状态更新后的消费者通知，不修改页面布局和动画。

步骤：

1. 保留当前失败测试，最小实现显式通知共享 ref 消费者。
2. 运行预览定向测试、Nuxt 全量测试和生产构建。
3. 仅重启 Nuxt，禁用 Chromium 缓存后硬刷新 Directus。
4. 执行“临时修改 → 画布更新 → 撤销 → 重做 → 取消”。

验收：临时正文在属性面板和画布同步；取消后两处恢复原值；不刷新页面、不保存测试值、不改变 Nuxt 布局。

### P0-2 首页第一条真实文字闭环

固定顺序：

```text
读取原值 → 选中 → 临时修改 → 即时预览
→ 撤销 → 原值 → 重做 → 临时值 → 取消 → 原值
→ 再次修改 → 保存 → Directus 回读 → 刷新保持
→ 恢复原值 → 再次保存和回读
```

验收：画布、属性面板、保存请求和 Directus 回读四处值一致；除目标字段外没有其他数据变化；最终恢复原值。

### P0-3 全宽工作台与 PC 画布验收

1. 进入可视化编辑后隐藏或折叠原始 Directus 记录表单。
2. 在 `1440x900`、`1920x1080`、`3840x2160` 实测导航、画布、属性面板和工具栏。
3. 验证面板开关、缩放、滚动、区块跳转及视频未结束时操作。

验收：1440 下属性面板打开时有效画布不低于 720 px；没有覆盖、重叠和横向工具栏失控；Nuxt 页面坐标不因编辑器缩放而改变。

### P0-4 六页逐元素绑定审计

```text

→ 属性编辑 → 保存目标核对 → Directus 回读 → 刷新 → 恢复样本
```

验收：每个元素有唯一状态和证据；不存在页面级“已接入”结论；所有 fallback 和缺字段元素明确只读或待建模。

### P0-5 媒体、重复项和受控视觉闭环

## 15. 风险、成本与业务决策

### 15.1 主要风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 同一内容存在多个来源 | 修改互相覆盖或预览与发布不一致 | 确定唯一主来源，停止写入旧来源 |
| 使用数组下标作为长期身份 | 排序后写错项目 | 使用真实 id；提交前复核原始身份 |
| 直接改 DOM 修实时预览 | Vue 状态、历史和保存链路分裂 | 修响应式通知或受测 revision/event |
| 画布无覆盖但过窄 | 名义可用，实际不能边做边看 | 720 px 硬门槛，必要时完全独立路由 |
| 开放过多位置和字体参数 | 破坏 PSD 布局、品牌和手机端 | 模板与白名单；越界服务端拒绝 |
| 真实内容未审核 | 宣传数字、证书、Logo、电话错误或侵权 | 发布前指定业务负责人确认 |
| 不限量媒体直接渲染 | 首屏性能、内存和带宽恶化 | 缩略图、分页、懒加载和发布上限 |
| 只验证本机 | 生产仍缺 HTTPS、备份、CDN、转码和监控 | 本地 P0 与生产上线清单分开验收 |

### 15.2 需要业务确认但不阻塞当前修复

1. 编辑、审核、发布是否必须三人分离。
2. 第一批保存闭环使用哪组已审核文字、图片和视频。
3. 宣传数字、客户 Logo、证书、负责人和联系方式的确认人。
4. 新闻排序采用业务发布日期、事件日期还是创建时间；本 PRD 暂用业务发布日期。
5. 产品、设备和图库默认每页或每屏数量。
6. 哪些记录属于可删除演示资讯，哪些已经转为真实业务资料。

这些决策不阻塞实时预览、首页文字闭环和工作台宽度修复，但会阻塞真实内容发布和 P0 最终签字。

## 16. 执行结论

立即执行项只有一个：先把实时预览从“状态已更新、画布未更新”修到浏览器闭环。该项通过前，不继续批量接入六页字段，也不保存临时业务值。

后续进度必须按元素报告，例如：

```text
网站主页 / 三大理由 / 增效降损正文
→ pages / 1 / performance / body
→ 预览通过、保存回读通过、刷新通过、原值已恢复
```

禁止继续使用“首页已接入”“六页基本完成”这类无法证明写入目标和恢复结果的表述。
