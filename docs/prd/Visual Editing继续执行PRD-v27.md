## 1. 先统一问题判断

用户提出的“六个页面所有内容都可做可视化编辑”，需要拆成两个不同问题：

1. **内容可编辑**：页面上的文字、图片、视频、列表记录、标题、日期、参数和正文，必须能在 CMS 中找到真实绑定并写回 Directus。
2. **版式可调整**：编辑者可以在真实画布中调整模板允许的对齐、偏移、宽度、裁切焦点、层级和文字样式。

本项目不做任意像素拖拽、任意 CSS、HTML/JavaScript 注入或页面结构自由重排。原因是这些操作会破坏现有 Nuxt 的 PSD 坐标、动画、路由、锚点、断点和响应式结构，也会使手机端不可预测。参考建站器的交互可以用于“画布中选中、双击文字、顶部工具栏、右侧属性面板”，但不改变上述边界。

## 2. 产品目标

运营人员在一个 PC 工作台中完成：

`选择页面 → 选择真实区块/元素 → 画布中修改 → 即时预览 → 保存草稿 → 审核 → 发布/回退`

必须满足：

- 工作台只按六个页面分组，页面下直接列真实区块，不重复套两层同名分类。
- 画布使用真实 Nuxt 页面，选中元素后自动定位；预览不遮挡编辑区域。
- 文字和图片优先即时同步，不等待视频播放结束；视频加载失败也不能阻塞文字和布局。
- 每次写回都能证明真实 `collection + itemId + fieldPath`，不能用数组下标、显示文本或 fallback 定位。
- 草稿、受保护预览、审核、发布、下线和版本回退彼此隔离。
- 内容、媒体、排序和样式的修改均可撤销、重做、取消；保存失败时保留草稿并可重试。

## 4. 工作台交互基线

### 4.1 固定 PC 布局

- **顶部工具栏**：页面切换、选择/文字/媒体模式、撤销、重做、缩放、保存草稿、预览、审核状态。
- **左侧导航**：六个页面及其真实区块，只负责导航，不能挤压或覆盖画布。
- **中央画布**：真实 Nuxt iframe；选中元素显示边框和绑定状态，并自动滚动到可视区域。
- **右侧属性面板**：内容、媒体、列表、文字样式、受控位置、绑定诊断、错误和保存状态。

### 4.2 直接编辑行为

- 单击图片/视频打开媒体属性；双击文字进入编辑；完成后按 Enter 或点击画布外结束编辑。
- 拖动只改变白名单内的 `offset_x/offset_y`、对齐或尺寸范围；超出范围立即回弹并说明原因。
- 重复内容支持新增、复制、隐藏、排序和分页；删除前需要确认并保留可恢复版本。
- 预览使用草稿叠加层，文字、图片和布局先更新，视频异步加载；禁止等待视频结束才显示内容。
- “取消”恢复进入编辑前快照；撤销/重做仅作用于当前会话；切页或关闭前提示未保存更改。
- 网络或 API 失败时保留本地草稿、显示具体失败原因并提供“重新保存”，不得清空未保存内容或留下孤儿媒体引用。

## 5. 数据绑定与安全契约

每个可编辑 DOM 必须带有稳定绑定：

```json
{
  "sectionKey": "about-milestone",
  "collection": "milestones",
  "itemId": 1,
  "fieldPath": "event",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

规则：

1. 缺少真实 `collection`、`itemId` 或合法 `fieldPath` 时只读，不显示保存控件。
2. 页面会话下的嵌套业务记录必须显式声明集合和真实 ID；禁止错误回落到 `pages` 根记录。
3. 媒体必须通过集合白名单、类型、用途、`placementKey`、发布状态和版权校验。
4. 富文本只允许受控标签和属性；公开端必须清理脚本、事件属性和危险链接。
5. 多条记录保存要逐条返回结果；任一失败都保留本地草稿和历史，不假装整体成功。

允许的视觉字段：

```text
layout.enabled / align / offset_x / offset_y / width / max_width / z_index
text_style.enabled / preset / font_family / size_desktop / weight / line_height / color
media_presentation.fit / focal_x / focal_y / overlay / poster_asset_id
responsive.desktop_visible / mobile_visible / mobile_order
```

所有字号、颜色、偏移和尺寸由模板白名单及范围校验控制。

## 6. 内容、媒体和列表规格

### 6.1 内容字段

- 文字：标题、正文、按钮、图标名称、替代文本、说明、年份、日期、单位和负责人。
- 产品：系列、型号、卖点、参数、尺寸图、技术资料和展示排序。
- 新闻：标题、业务日期、封面、摘要、受控图文正文、发布状态。
- 视频：标题、业务日期、视频媒体、自动首帧海报、可替换海报、字幕/文字稿。

### 6.2 媒体建议规格

| 用途 | 建议规格 | 必填辅助信息 |
| --- | --- | --- |
| 首屏背景/视频 | 图片桌面至少 2560x1440；视频 MP4 H.264 1920x1080，15-60 秒 | 海报、替代文本、桌面/手机裁切焦点、版权 |
| 产品/设备主图 | 1:1 或 4:3，至少 1600x1200 | 产品/设备名称、替代文本、contain/cover |
| 新闻封面 | 16:9，至少 1600x900 | 标题、日期、替代文本、裁切焦点 |
| 证书/参数/尺寸图 | 保持原比例，长边至少 2000 px | 名称、编号/版本、来源、有效期（适用时） |
| 图标/标志 | SVG 优先，位图至少 512x512 | 名称、用途、版权 |

当前本地单文件限制以 CMS 实际校验为准：图片 25 MB、视频 500 MB、PDF 50 MB。建议值用于表单提示和发布前校验，不等于允许用未经审核的素材直接上线。视频首帧不可用时必须显示备用海报和明确错误状态。

## 7. 权限与状态机

状态机：`编辑草稿 → 提交审核 → 审核通过/退回 → 发布 → 下线/归档 → 版本回退`。

| 角色 | 权限 |
| --- | --- |
| 内容编辑者 | 创建、修改、预览草稿；不能发布 |
| 审核人员 | 查看、通过、退回、提出修改意见 |
| 发布管理员 | 发布、下线、归档、回退 |

是否允许同一账号兼任必须由业务确认后配置。公开接口只返回已发布内容；草稿预览必须使用受保护会话。HTTP 200、缓存响应或 `data:null` 都不能单独作为 CMS 内容已生效的证据。

## 10. TDD 与验收证据

每个工作包固定执行：

```text
失败测试 → 最小实现 → 定向测试 → CMS/Nuxt 全量测试
→ 扩展/生产构建 → 真实 PC 浏览器 → Directus 受保护回读
→ 工作台刷新一致 → 恢复测试值 → 更新本文执行记录
```

每个样本至少记录：页面、区块、可见元素、`collection/itemId/fieldPath`、原值、临时值、回读值、恢复值、预览是否等待视频、保存响应、刷新结果和验收时间。不得记录密码或 token。

## 11. 发布门槛与停止规则

以下任一项出现，当前切片不得宣布完成：

- 修改破坏 Nuxt 原 PSD 几何、动画、路由、锚点、断点或响应式。
- 公开接口读取草稿或未授权媒体。
- 画布值与 Directus 回读不一致，或失败保存留下半成品引用。
- 正式素材、版权、规格或审批规则缺失。
- 只有自动化测试，没有真实浏览器和受保护回读证据。

Visual Editing P0 只有在六页承诺元素均已真实绑定或明确只读/延期，文字、媒体、位置、样式、列表、失败恢复和审核发布回退全部通过，PC 六页回归和手机公开只读回归完成后，才能标记为发布就绪。
