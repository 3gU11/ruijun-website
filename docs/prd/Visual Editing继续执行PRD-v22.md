# 瑞钧官网 Visual Editing 继续执行 PRD

- 版本：v22.0（执行重整版）
- 日期：2026-08-26
- 产品范围：PC 网页端六页；手机端只做只读回归
- 关联系统：Nuxt 官网、Directus CMS、MySQL `127.0.0.1:3307`、MinIO `9000/9001`
- 唯一执行入口：本文档；v8-v21 仅作为历史记录和证据索引

## 1. 背景与问题定义

当前系统已经具备 CMS 工作台、页面分组、画布选择和部分实时预览能力，但仍存在三类风险：

1. 工作台显示的条目可能与官网真实渲染内容不是同一条绑定，容易出现“CMS 有正文、官网看不到”的假连接。
2. 临时预览、保存回读、发布回读和媒体存储是不同闭环，不能用浏览器 HTTP 200 或 fallback 图片证明全部完成。
3. 用户需要类似 PowerPoint/htmlpage builder 的可视化操作，但官网原有布局、PSD 坐标、动画和路由不能因 CMS 任意拖拽而被破坏。

本 PRD 将产品定义为“受控 Visual Editing”：编辑者在真实 Nuxt 画布上选中业务内容，顶部工具栏和右侧属性面板完成编辑；位置和样式只能在模板白名单内调整，不开放任意 HTML、CSS、脚本或无限自由布局。

## 2. 目标与非目标

### 2.1 本期目标

- 六个 PC 页面都能按真实页面区块进入同一工作台。
- 文字、图片、视频及重复项均有可追溯的 Directus 绑定。
- 编辑、临时预览、保存草稿、Directus 回读、刷新、取消、撤销、重做和恢复原值形成可验证闭环。
- 新闻/视频、产品、设备、证书、客户、合作品牌、办事处和里程碑支持真实数量管理、排序和分页。
- 正式媒体同时存在于 Directus 文件元数据、`media_assets` 和 MinIO，并能被 Nuxt 渲染。
- 不改变 Nuxt 原布局、动画、路由、锚点和 PC/手机响应式结构。

### 2.2 明确不做

- 不把系统改造成任意拖拽建站器。
- 不允许 CMS 直接修改 Nuxt 组件代码、任意 CSS/JS 或 PSD 静态层。
- 不使用 PSD、静态 fallback、数组下标或演示数据伪装成 CMS 已接入内容。
- 本期不做移动端 Visual Editing；移动端只验证公开页面不回归。

## 5. 绑定与数据契约

画布元素必须使用真实绑定，不得通过内容文本猜测记录：

```json
{
  "collection": "product_series",
  "itemId": "1",
  "sectionKey": "series-card",
  "fieldPath": "title"
}
```

### 5.1 绑定规则

- `collection`：Directus 真实集合名。
- `itemId`：真实记录主键，不得使用数组下标。
- `sectionKey`：页面区块的稳定标识，跨刷新不变。
- `fieldPath`：字段或嵌套字段路径；媒体字段必须能解析到文件记录。
- fallback、PSD 静态层、未托管外链只读，并在诊断面板显示原因。
- 服务端保存前校验字段权限、类型、媒体规格、位置范围和工作流状态。

### 5.2 内容类型规则

- 动态新闻：标题、业务日期、封面、富文本正文、发布状态；点击后展开图文详情。
- 视频分享：标题、业务日期、视频文件；默认用视频首帧作封面，可人工替换。
- 动态新闻和视频分享：官网单页最多 6 条，按业务日期倒序，最新在前；超出后分页。
- 产品/设备/证书/客户/合作品牌/办事处/里程碑：CMS 不设“四张图片”硬上限，支持新增、隐藏、排序；官网按模板分页、轮播或网格呈现。
- 首页与关于瑞钧共用 `milestones` 主数据，不复制同一里程碑。

## 6. 工作台交互要求

固定布局：顶部工具栏、左侧页面与区块树、中间 Nuxt 画布、右侧属性面板。

- 顶部：页面切换、选择模式、文字/媒体属性、撤销、重做、缩放、保存草稿、预览、发布状态。
- 左侧：只显示六页及其真实区块；选中区块后画布自动定位并高亮。
- 画布：双击文字进入编辑；单击图片/视频打开媒体属性；重复项支持新增、复制、隐藏、排序。
- 右侧：内容、媒体、文字样式、受控位置、绑定诊断五组属性。
- 预览采用草稿叠加层，不等待视频结束；文字和图片优先更新，视频只负责媒体状态。
- 位置调整仅允许模板白名单字段，例如偏移、对齐、裁切焦点、层级；超出范围拒绝保存并说明原因。
- 取消必须恢复到进入编辑前的值；撤销/重做只操作当前会话的变更栈。
- 网络失败时保留本地草稿，显示失败原因和重试入口，不静默回退旧值。

## 7. 工作流与权限

```text
编辑草稿 → 提交审核 → 审核通过 → 发布
                    ↘ 退回 → 编辑草稿
已发布版本 → 回退到指定历史版本
```

| 角色 | 权限 |
| --- | --- |
| 编辑者 | 修改允许字段、上传媒体、保存草稿、提交审核 |
| 审核者 | 查看差异、通过或退回，不直接修改内容 |
| 发布者 | 发布已通过版本、回退历史版本 |
| 只读用户 | 查看工作台和公开页面，不写入 |

公开 BFF/API 只返回已发布记录；草稿和待审核内容只能通过受保护的预览会话访问。

## 9. 每个切片的开发与验收步骤

1. 先写一个能证明问题的失败测试。
2. 做最小实现，不改动 Nuxt 非内容布局。
3. 跑对应 CMS/Nuxt 定向测试，再跑全量测试和生产构建。
4. 用命名 Playwright 会话完成 PC 浏览器操作：选择、预览、保存、回读、刷新、取消、撤销、重做。
5. 用 Directus 受保护接口核对记录、状态、字段和 `itemId`；媒体再核对 MinIO 对象。
6. 将原值、临时值、最终值、请求目标、响应状态、截图路径写入证据表。

### 单页闭环验收表

| 项目 | 必填结果 |
| --- | --- |
| 页面/区块/元素 | 明确名称，不使用模糊“正文” |
| 绑定 | `collection + itemId + sectionKey + fieldPath` |
| 原值/临时值/最终值 | 三者可回读 |
| 临时预览 | 约 300ms 内开始更新，视频不阻塞 |
| 保存/刷新 | Directus 回读与刷新一致 |
| 取消/撤销/重做 | 状态和画布一致 |
| 媒体（如有） | Directus 文件、`media_assets`、MinIO、Nuxt 均有证据 |
| 发布状态 | 草稿/审核/发布结果明确 |

## 10. 风险、前置条件与停止规则

- 正式图片、视频、文案、日期和尺寸规格未提供时，媒体切片保持阻塞；不得生成演示素材冒充正式内容。
- 删除演示资讯前先备份并得到确认；不能把“公开列表为空”直接解释为连接失败。
- 任何 HTTP 200、缓存 `fresh/stale` 或 `data: null` 都不是内容回读证明，必须核对受保护记录和发布状态。
- 任何修复若改变 Nuxt 原布局、坐标、动画、路由或锚点，立即停止该切片并回归评估。
- MySQL 只使用 `127.0.0.1:3307`，不得触碰既有 `3306`；不在文档或日志记录密码/token/cookie。
