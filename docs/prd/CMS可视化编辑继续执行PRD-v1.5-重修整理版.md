## 1. 执行结论

本项目应建设的是“模板约束的可视化编辑器”，而不是任意拖拽网页搭建器。

编辑者应能在 Directus 的“内容编辑工作台”中，按官网 Header 的六个页面进入真实 Nuxt PC 画布，点击可编辑内容，在右侧修改字段，立即看到草稿预览，并完成保存、回读和发布。Nuxt 的既有视觉布局、PSD 几何、动画、路由和响应式行为不因 CMS 编辑而变化。

用户提出的“像 PPT/PowerPoint 一样在画布上直接修改”只在受控范围内成立：点击或双击文本选中，顶部工具栏选择编辑模式，右侧修改文字、媒体、白名单样式和有限位置。任意 DOM 结构、任意坐标、任意 CSS 的自由编辑与“原 Nuxt 画面不动”相互冲突，本期不实施。

### 2.2 不得当作证据的项目

以下都不能单独证明 CMS 已真实生效：HTTP 200、缓存命中、`data: null`、截图、iframe 可见、静态 fallback、画布红框可选中、工作台有导航入口。保存结论必须包含认证 Directus 回读，且字段路径、集合和记录 ID 正确。

### 2.3 本期目标

1. 六页按 Header 页面管理，页面内按真实业务区块管理，避免重复分类和左侧塞入完整表单。
2. 每个承诺的可编辑元素都有稳定数据绑定，或明确显示“只读/待媒体/待建模”的原因。
3. 实现文字、媒体、受控样式与位置、列表、错误恢复各至少一个真实端到端闭环。
4. 编辑与预览可并行使用，预览不遮挡输入区；视频、动画、iframe 事件不阻塞选中或保存。
5. 先完成 PC，移动端只做公开页面回归，不扩展移动端可视化编辑。

## 3. 产品边界

### 3.1 本期支持

| 类型 | 编辑能力 | 边界 |
| --- | --- | --- |
| 文字 | 标题、正文、按钮文案、年份、参数、链接说明 | 必须有集合、记录 ID、字段路径 |
| 媒体 | 图片、视频、海报、图标、替代文本、焦点、适配方式 | 必须先有 Directus 文件、`media_assets` 和 MinIO 对象 |
| 样式 | 字体、字号、字重、行高、颜色、对齐 | 仅允许区块白名单值与范围 |
| 位置 | 预设对齐、有限 X/Y 偏移、最大宽度、层级、显隐 | 必须限制边界，不能改变模板结构 |
| 列表 | 新增、排序、隐藏、分页/轮播配置 | 每项必须有独立记录 ID，删除可恢复 |

### 3.2 本期不支持

- 任意拖放、任意缩放、任意 CSS 或自由修改 Nuxt DOM。
- 编辑 PSD 源文件，或将磁盘静态资源伪装成 CMS 可替换媒体。
- 在没有正式素材、版权/来源、替代文本和用途信息时开放媒体替换。
- 在 PC 未逐页验收前开发移动端编辑器。
- 由“保存草稿”自动发布公开官网。

若业务确实需要自由专题页，应另立“专题页搭建器”项目。其需要独立的断点模型、碰撞处理、结构版本、回退、无障碍和性能预算，不能附加在这六个受保护的官网模板上。

## 4. 信息架构与编辑工作流

```text
Header 页面（六项）
  -> 当前页面业务区块（不重复显示 Header 分类）
    -> 真实 Nuxt iframe 画布的可编辑锚点
      -> 右侧受控属性面板
        -> Directus 稳定写入目标、版本与发布流程
```

工作台布局要求：

- 顶部：页面/区块面包屑、选择/文字/媒体模式、撤销、重做、缩放、保存草稿、预览状态。
- 左侧：只显示当前页面的区块与相关业务记录，支持搜索/折叠；不得放整页表单。
- 中央：真实 Nuxt PC iframe。编辑模式拦截导航、视频播放和卡片跳转，浏览模式恢复官网原行为。
- 右侧：当前元素的字段、内容、媒体、白名单样式/位置、绑定诊断、保存错误和恢复操作。
- 宽度：预览列和属性面板必须占用布局空间，不能浮层覆盖输入区。

编辑流程固定为：选择页面 -> 选择区块或画布元素 -> 修改受支持属性 -> iframe 立即显示草稿 -> 保存草稿 -> 认证回读 -> 刷新一致 -> 提交审核/发布。离开有未保存修改的页面必须提示。

## 5. 绑定与数据规则

每个可写元素必须具备以下稳定绑定；缺任一项则只读：

```json
{
  "pageKey": "about",
  "sectionKey": "overview",
  "collection": "pages",
  "itemId": "2",
  "fieldPath": "sections[overview].body",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

写入目标只能从当前加载的草稿记录解析，不能按显示文字、列表数组下标、视觉坐标或旧侧栏快照猜测。跨页面、跨集合、跨记录切换时必须清空旧选中态和旧表单，避免串写。

目标内容状态机为 `draft -> in_review -> published -> archived`。当前优先完成草稿和授权预览；公开 Nuxt 只读取 `published`，授权预览可读取对应草稿。保存失败必须保留本地草稿并显示服务端实际错误，允许重新保存。

## 7. 媒体规格与治理

媒体开放替换前，必须有：Directus 文件记录、`media_assets` 业务记录、MinIO 实际对象、用途、替代文本、版权/来源、发布状态、PC 裁切焦点和适配方式。

| 用途 | 建议最低规格 | 必填元数据 |
| --- | --- | --- |
| 首屏图片/视频 | 图 `2560x1440`；MP4 H.264 `1920x1080`、15-60 秒 | 海报、替代文本、焦点、版权/来源 |
| 产品/设备图 | `1:1` 或 `4:3`，至少 `1600x1200` | 名称、替代文本、适配方式 |
| 新闻封面 | `16:9`，至少 `1600x900` | 标题、业务日期、替代文本、焦点 |
| 证书/尺寸图 | 原比例，长边至少 `2000px` | 名称、来源、编号/版本、有效期（如适用） |
| 图标/标志 | SVG 优先；位图至少 `512x512` | 名称、用途、深浅色适配、版权 |

视频首帧抽取失败时必须提示，并允许人工指定海报。`media_assets=0` 时，所有未托管图片、视频、PSD 图层和 static fallback 都标记为“只读/待媒体”。

### P1：媒体、列表与受控版式

1. 用一条有正式业务信息的图片或视频完成上传 -> MinIO 验证 -> `media_assets` -> 页面绑定 -> 预览 -> 保存 -> 回读 -> 刷新 -> 恢复。
2. 再按页面逐批开放首屏媒体、尺寸图、核心设备、证书、品牌、客户、服务图标等替换。
3. 完成新闻、视频、设备、品牌、客户、资料的新增、排序、隐藏、分页/轮播，并为每项提供独立记录 ID。
4. 完成样式/位置字段的白名单、输入校验和三档 PC 视口验证。

### P2：生产治理

完成审核、发布、下线、版本恢复、审计、角色隔离和失败重试。编辑者、审核者、发布者的权限必须分别验证；发布动作需要明确的业务责任人。

## 9. 单项验收协议

每一个字段、媒体或列表功能必须按以下顺序闭环，不能跳步：

```text
失败测试 -> 最小修复 -> 定向测试 -> 相关构建
-> 真实 PC 浏览器画布选择 -> 即时草稿预览
-> 保存草稿 -> 认证 Directus 回读 -> 整页刷新一致
-> 同一路径恢复原值 -> 最终认证回读 -> 更新绑定台账
```

一项被标记为“已闭环”的最低条件：

1. 画布选择命中正确集合、记录 ID 和字段路径。
2. 临时值在同一 iframe 内立即可见，不依赖视频结束或页面重新打开。
3. 保存后认证回读到目标字段，刷新工作台与页面仍一致。
4. 临时值通过同一路径恢复，最终回读确认没有测试残留。
5. 不改变既有 Nuxt 的布局、动画、路由或响应式。

PC 验收视口为 `1440x900`、`1920x1080`、`3840x2160`。三个视口都不得出现预览遮挡表单、横向溢出、文字遮挡、选择偏移或动画卡死。

## 10. 明确的暂停条件与待决策项

以下情况必须暂停并要求业务确认，不能由开发自行猜测：

1. 需要改变 PSD、既有页面几何、动画或响应式来满足编辑需求。
2. 没有正式素材与权属信息，却要求将静态素材标记为 CMS 可替换。
3. 同时要求任意 CSS/自由拖拽和现有版式完全不变。
4. 要删除演示新闻、证书、媒体或历史内容，但没有明确保留清单和删除范围。
5. 未定义新闻日期时区、同日排序、审核人、发布人和下线责任。
6. 需要对外公开当前草稿页面，但没有完成发布状态与权限验收。
