## 1. 本次重修结论

本项目要做的不是类似 HTMLPage 的通用网页搭建器，也不是允许运营人员任意改写 Nuxt 布局的 PowerPoint。正确产品定义是：

> 在保持现有 Nuxt 页面模板、坐标体系、动画、路由、锚点和响应式结构不变的前提下，为六个官网栏目提供一个类似 PowerPoint 操作习惯的结构化可视化内容编辑器。

运营人员在真实 Nuxt 页面画布中点击元素完成选中，双击文字直接修改，并通过顶部工具栏和右侧属性面板更换媒体、调整排序及受控视觉属性。所有修改必须落到明确的 Directus 集合、记录 id 和字段路径，并能保存、回读、刷新保持、撤销、重做和失败恢复。

### 1.1 必须先纠正的错误前提

| 原始想法 | 事实判断 | 本 PRD 的处理 |
| --- | --- | --- |
| 像 PPT 一样拖动，就能保证所有页面都可编辑 | 不成立。任意坐标会破坏现有动画、响应式和移动端布局 | 只允许模板内的受控偏移、排序、对齐和媒体焦点；不开放任意 CSS |
| 自动化测试通过，说明 CMS 已完成 | 不成立。测试只能证明代码契约，不能证明真实 Directus 数据闭环 | P0 必须提供浏览器、Directus 保存/回读、刷新和恢复证据 |
| 素材可无限存放，因此页面可无限展示 | 不成立。存储容量和单页性能是两件事 | CMS 库存可扩展，官网采用分页、轮播、折叠或懒加载 |
| 页面显示了文字，就一定已连接 CMS | 不成立。当前 Nuxt 同时存在 Directus 内容和 PSD/代码兜底内容 | 没有真实集合、记录 id、字段路径的元素必须标记只读 |
| HTTP 200 就证明读取了 CMS 内容 | 不成立。`data: null` 也可能返回 200 | 验收必须核对响应数据、发布状态和 Directus 原记录 |

## 2. 目标与成功标准

### 2.1 产品目标

1. 六个官网栏目中的承诺内容可以在同一个工作台内按页面和区块管理。
2. 编辑人员不需要理解 Directus 集合结构，也不需要在多个系统页面之间来回寻找字段。
3. 中央画布始终显示真实 Nuxt 页面，修改表单和预览互不遮挡。
4. 画布选中元素后，工作台能明确显示“正在修改哪个集合、哪条记录、哪个字段”。
5. 保存后的草稿能够从 Directus 回读，并在刷新后保持一致。
6. CMS 改造不得改变公开官网的既有视觉布局、动画、路由、锚点和响应式结构。

### 2.2 P0 成功标准

P0 只有在以下条件全部满足后才能宣布完成：

1. 六页承诺元素均具备真实绑定，或被明确标记为只读、待建模或延期。
2. 至少完成文字、图片、视频、列表排序和白名单视觉属性的完整编辑闭环。
3. 保存只修改目标 Directus 记录，不误写其他集合或数组项。
4. 支持撤销、重做、取消、刷新保持、保存失败恢复和未保存离开提示。
5. 通过 `1440x900`、`1920x1080`、`3840x2160` 三种 PC 分辨率回归。
6. `390x844` 手机端展示无新增重叠、溢出或路由回归，但不要求手机端编辑。
7. Directus、Nuxt、MySQL `3307`、MinIO `9000/9001` 的真实链路有验收证据。
8. 验收使用审核过的业务样本，测试结束后恢复原始数据。

## 3. 用户和权限

| 角色 | 能力 | 明确限制 |
| --- | --- | --- |
| 内容编辑 | 修改正文、媒体、排序和受控视觉属性；保存草稿 | 不能发布、改权限、录入脚本或任意 CSS |
| 内容审核 | 查看差异、媒体来源、版权和发布检查；退回或批准 | 不能修改系统绑定契约 |
| 发布人员 | 发布已审核内容、执行回退 | 不能绕过媒体和字段校验 |
| 开发维护 | 维护页面模板、绑定契约、迁移和故障恢复 | 不代替业务人员确认宣传数据和版权 |

权限必须同时在工作台界面和 Directus API 层生效。隐藏按钮不能代替服务端权限。

## 4. 产品形态

### 4.1 固定四区布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ 顶部工具栏：页面 | 选择/文字/媒体 | 撤销/重做 | 缩放 | 保存 | 退出 │
├──────────────┬───────────────────────────────────┬───────────────────┤
│ 左侧页面导航 │                                   │ 右侧属性面板      │
│              │       真实 Nuxt PC 页面画布       │                   │
│ 六个栏目     │                                   │ 内容/媒体/样式    │
│ 真实区块     │       点击选中，双击编辑          │ 绑定来源/校验错误 │
│              │                                   │                   │
└──────────────┴───────────────────────────────────┴───────────────────┘
```

- 顶部工具栏固定展示明确命令，不堆放业务字段。
- 左侧按“栏目 → 页面真实区块”组织，禁止出现两层同名分类。
- 中央画布加载真实 Nuxt 页面，不重绘近似预览。
- 右侧属性面板只在选中元素后出现，并为中央画布预留空间，不得覆盖编辑目标。
- 在窄桌面宽度无法同时容纳三栏时，右侧面板可折叠为抽屉，但必须保留画布可见区域。

## 5. 核心交互

### 5.1 选择和编辑

| 操作 | 预期行为 | 异常处理 |
| --- | --- | --- |
| 单击元素 | 高亮元素，打开右侧属性面板，显示标签和绑定来源 | 无完整绑定时显示只读原因 |
| 双击文字 | 进入就地文字编辑，右侧内容字段同步 | 不允许直接写入 HTML、脚本和样式 |
| 单击图片/视频 | 选中媒体，显示替换、焦点、适配和规格 | 未审核素材不能进入可发布状态 |
| 拖动元素 | 只改变允许的受控偏移或排序 | 超出范围、发生重叠或破坏模板时拒绝并提示 |
| 左侧点击区块 | 画布打开对应页面并滚动到真实锚点 | 锚点不存在时提示绑定缺失，不静默跳到页首 |
| 切换页面 | 保留已保存状态；有未保存改动时先确认 | 不允许无提示丢失草稿 |

### 5.2 顶部工具栏

P0 工具：选择、文字、媒体、撤销、重做、缩放、保存草稿、退出专注模式。

P1 工具：辅助线、批量排序、版本对比、审核、发布。

工具状态必须可解释：无选中元素时禁用元素工具；保存中防止重复提交；保存失败保留本地草稿和重试入口。

### 5.3 视频预览

- 页面进入编辑模式后立即显示海报和文字，视频异步加载。
- 编辑、导航和滚动不等待视频播放结束。
- 自动播放必须静音；浏览器阻止播放时仍可编辑。
- 支持暂停、跳过和替换海报。
- 视频失败时保留海报、文字和错误状态，不让画布空白。

### 5.4 历史和恢复

- 撤销/重做覆盖当前未保存会话，不跨用户共享。
- 新编辑发生后清空重做分支。
- 保存成功后建立新的恢复基线。
- 取消恢复到最近一次保存成功的基线。
- 网络失败或部分集合保存失败时，不得把失败内容显示为已保存。
- 页面关闭或切换前存在未保存内容时必须提示。

## 7. 视觉控制白名单

“位置可调”和“文字样式可调”通过白名单实现，不开放完整样式系统。

| 类型 | P0 可编辑 | 约束 |
| --- | --- | --- |
| 文字 | 内容、预设、字号、字重、行高、颜色、对齐、最大宽度 | 字体第一期仅使用项目已授权字体；按文本类型限制范围 |
| 位置 | 模板、水平/垂直对齐、顺序、层级、桌面横纵偏移 | 偏移按容器比例限制在 `-30..30`；禁止负间距和任意定位 |
| 图片 | 素材、替代文本、`cover/contain`、焦点、遮罩、顺序 | 必须引用 Directus 已审核媒体；禁止不可信外链 |
| 视频 | 文件、海报、静音、循环、移动端替代媒体、字幕 | 首屏编辑不依赖自动播放；失败有海报回退 |
| 响应式 | 桌面/平板/手机显示开关，安全模板和独立字号 | PC 本期可编辑；手机配置只允许安全预设，不做自由画布 |

禁止保存：任意 CSS、JavaScript、事件代码、未经校验的 HTML、任意字体文件、不受控外链、无限像素坐标。

## 8. Visual Binding 数据契约

每个可编辑 DOM 元素必须提供以下最小绑定：

```json
{
  "sectionKey": "manufacturing-core-equipment",
  "collection": "manufacturing_evidence",
  "itemId": 3,
  "fieldPath": "media.2",
  "elementType": "image",
  "mediaRole": "image",
  "placementKey": "equipment-3"
}
```

### 8.1 强制规则

1. `collection`、真实 `itemId`、`fieldPath` 任一缺失时元素只读。
2. `itemId` 只能来自 Directus 响应，禁止从路由、数组下标或字段名猜测。
3. 数组经过排序后仍要保存原始数组索引，避免修改错误条目。
4. `pages.sections` 使用 `sectionKey` 定位 section；section 不是自动独立出来的 Directus 记录。
5. PSD 和代码兜底内容可继续展示，但不得伪装成可保存的 CMS 内容。
6. 跨集合保存必须拆分结果；一个集合失败不能回滚或覆盖另一个集合已成功的数据。
7. 工作台必须显示当前绑定来源，例如 `articles/17 · title`。

## 9. 数据、媒体和发布

### 9.1 数据来源

优先复用现有集合：`pages`、`homepage_sections`、`product_series`、`product_models`、`articles`、`milestones`、`qualifications`、`manufacturing_evidence`、`service_locations`。

新增集合前必须回答：为什么现有模型不能表达、权限如何配置、旧数据如何迁移、失败如何回滚、公开 BFF 如何过滤草稿。

### 9.2 媒体链路

```text
工作台上传 → Directus 文件元数据 → MinIO 对象存储
→ 用途/版权/规格审核 → 页面草稿引用 → 发布 → Nuxt BFF 输出
```

- MySQL 固定为隔离实例 `127.0.0.1:3307`，不得操作既有 `3306`。
- MinIO API/控制台固定为 `9000/9001`。
- Directus 环境变量修改后必须重启，再用真实上传核验 `storage: s3` 和对象存在性。
- 图片必须记录替代文本、用途、版权、宽高和格式。
- 视频必须记录海报、时长、编码、用途和可选字幕/文字稿。
- 具体像素、比例和体积建议以配套媒体规格清单为准。

### 9.3 内容状态

```text
草稿 → 待审核 → 已批准 → 已发布
          └────→ 已退回 → 草稿
已发布 → 已归档 / 回退到历史版本
```

公开 BFF 只输出已发布且通过权限过滤的记录。`data: null` 必须在工作台显示为“没有可公开记录或记录未发布”，不能显示为连接成功。

## 10. 失败处理和可观测性

| 场景 | 用户界面 | 数据要求 | 记录要求 |
| --- | --- | --- | --- |
| Directus 不可用 | 保留本地草稿，显示重试，不关闭面板 | 不标记已保存 | 记录请求、集合、状态码和时间 |
| MinIO 上传失败 | 保留原媒体引用，可重新上传 | 不产生半成品页面引用 | 记录文件 id、对象键和失败阶段 |
| 部分集合保存失败 | 逐项显示成功/失败 | 成功项不重复写，失败项可安全重试 | 保存批次有唯一 id |
| 绑定缺失 | 元素只读并说明缺哪个字段 | 不允许猜测写入目标 | 记录页面、区块和 DOM 绑定信息 |
| 草稿冲突 | 提示远端版本已变化，提供刷新/比较 | 禁止静默覆盖 | 记录版本号和操作者 |
| 预览断连 | 页面仍可退出专注模式 | 未保存草稿保留 | 记录 iframe 握手状态和来源 |

P0 日志不得记录密码、访问令牌和完整个人敏感信息。

## 11. 非功能要求

### 11.1 兼容和布局

- P0 目标浏览器：当前 Windows Chromium 环境。
- 工作台最小验收宽度：1440 px。
- 画布、表单和属性面板之间至少保留可识别间隔，不互相覆盖。
- 动态标签、长标题和错误信息不能改变工具栏高度或挤出按钮。
- Nuxt 公开页面在接入 CMS 前后截图差异只允许来自内容本身，不允许来自结构性布局变更。

### 11.2 性能

- 视频不阻塞页面可编辑状态。
- 大图库首屏不一次性加载全部原图。
- 输入修改采用本地草稿即时反映，保存请求防抖或显式提交。
- 工作台断线后不得无限自动重试造成重复写入。

### 11.3 安全和可访问性

- 富文本经过白名单清洗。
- 媒体上传校验 MIME、扩展名、体积和用途。
- 图标按钮有可访问名称；工作台核心流程可使用键盘完成。
- 颜色选择要做对比度提示，图片要求替代文本。

## 16. 待业务确认事项

以下问题会改变数据或发布结果，不能由开发人员自行假设：

1. 谁拥有最终发布权限，是否需要“编辑 → 审核 → 发布”三人分离。
2. 第一批可用于闭环验收的已审核图片、视频和文字是哪一组。
3. 宣传数字、客户 Logo、证书、负责人和联系方式的真实性及授权由谁签字。
4. 新闻的“日期”按创建时间、业务发布日期还是实际事件日期排序。本 PRD 暂按“业务发布日期”处理。
5. 产品和设备图库的默认每页数量、轮播数量及下载资料公开范围。

这些问题不阻塞工作台基础技术验证，但会阻塞真实业务内容发布和 P0 最终签字。

## 17. 最终判定

当前项目可以继续实施，但尚不能称为“六页全部可视化编辑完成”。已确认的主要剩余工作不是再增加更多表单，而是完成以下闭环：真实绑定来源可见、画布选择可用、保存目标正确、Directus 可回读、刷新后保持、失败可恢复，并证明整个过程没有改变 Nuxt 原画面。

后续所有进度更新应写入单独的验收证据表或任务记录。本 PRD 只在产品范围、交互规则、数据契约或验收标准发生变化时升级版本，避免继续把测试日志堆进需求正文。
