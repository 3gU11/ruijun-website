## 1. 决策与目标

### 1.1 产品目标

在 Directus 的“内容编辑工作台”中，运营人员按官网 Header 的六个页面进入页面级编辑界面：

```text
网站主页 / 产品展示 / 先进制造 / 视频新闻 / 关于瑞钧 / 服务支持
  -> 当前页面的业务区块
    -> 真实 Nuxt PC 画布
      -> 受控属性面板
      -> 保存草稿、审核、发布
```

进入“网站主页”后，左侧仅显示“首页视频、三大特点、产品系列、时间轴”等实际区块。不得出现第二层重复的六页分类；完整编辑表单不得挤入左侧导航。

编辑完成的最低可用流程：从区块列表或画布元素选中 -> 右侧修改 -> iframe 立即显示草稿 -> 保存草稿 -> 认证 Directus 回读 -> 整页重新加载一致。发布是独立动作，不能由“保存成功”暗示。

### 1.2 关键约束

本项目采用“模板约束的可视化编辑”，不是自由网页搭建器。

原因是两个要求彼此冲突：既有 Nuxt 的 PSD 几何、动画、路由和响应式不能被破坏，同时又希望像 PPT 一样任意拖放和任意 CSS。对既有页面开放任意坐标和样式会直接破坏断点与动画，也无法可靠回退。

本期可以编辑：文字内容与白名单样式、已治理媒体、预设对齐与有限偏移、列表新增/排序/隐藏、按钮与已审批链接。禁止任意 DOM 结构、任意绝对定位、任意 CSS、编辑 PSD 本体、使用本地静态资源冒充可替换 CMS 媒体。

若需要真正自由画布，应另立“专题页搭建器”项目，独立处理断点、碰撞、版本迁移、无障碍、性能与回退，不应改造这六个既有官网模板。

### 2.3 明确不能采用的错误判断

`HTTP 200`、截图、缓存命中、静态 fallback、`data: null`、红框可选中，均不等于 CMS 已真正读取、保存或发布。每次闭环必须使用受保护 Directus 回读验证准确集合、记录 ID 和字段路径。

## 3. 目标架构与绑定规则

```text
Nuxt 页面模板层：保持现有布局、动画、路由、响应式；提供可编辑锚点
        ↓
Block 组件层：Banner、图文、产品列表、新闻列表、Gallery、RichText、页尾
        ↓
Directus 数据层：页面、产品、新闻、媒体、版式白名单、版本、审核与发布
        ↓
内容编辑工作台：选中、草稿、受控属性、即时预览、保存、错误与审计
```

每个可写元素必须有稳定绑定；任一关键项缺失即只读，并说明原因：

```json
{
  "pageKey": "news",
  "sectionKey": "dynamic-news",
  "collection": "pages",
  "itemId": "9",
  "fieldPath": "sections[dynamic-news].title",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

写入目标只能从当前已加载的草稿记录解析，不能按显示文字、数组下标或左侧列表旧快照推测。跨记录后必须清空旧选中态，避免串写。

1. 为 `display_date` 增加失败测试，明确输入为空、合法 ISO 日期、含时区日期时的展示规则；不得把无效日期格式化成 `Invalid Date`。
2. 检查文章读取层、预览覆盖层与 `website/pages/news.vue` 的字段命名是否一致；采用一个明确的日期格式化函数，非法值显示可读占位且报告绑定诊断。
3. `pages/9.sections[dynamic-news].title` 已闭环（2026-08-26）：画布选中、输入临时值、保存、认证回读、工作台重载、恢复原值、最终回读均已完成。
4. 单独验证 `articles/10` 的标题、日期和详情读写。它是草稿，不得用它证明公开端已发布。

验收：相关单测、工作台构建、真实 PC 浏览器、认证 Directus 回读全部通过，且没有遗留临时测试值。

### P0-2：完成六页最小文字闭环与台账

按以下顺序选择每页一个未覆盖且低风险的真实文字字段。每完成一个就更新台账，未完成绝不升级状态。

| 顺序 | 页面 | 目标样本 |
| --- | --- | --- |
| 1 | 关于瑞钧 | `pages/2.sections[overview].title` 或真实里程碑字段 |
| 2 | 服务支持 | `pages/3.sections[support].title` 或 `service_locations/{id}.address` |
| 3 | 网站主页 | 再选一个未覆盖的区块文字 |
| 4 | 产品展示 | 再选一个模型/资料文字字段 |
| 5 | 先进制造 | 再选一个工艺节点或区域文字字段 |

每个字段的唯一完成定义：画布选中 -> 草稿即时预览 -> 保存草稿 -> 认证回读 -> 工作台刷新一致 -> 同一路径恢复原值 -> 最终回读。

### P0-3：编辑体验稳定性

1. 验证选择、文字、媒体模式，以及 iframe 重载、视频播放结束、动画运行期间的可编辑性。
2. 验证预览列和属性面板占用布局空间，桌面端不覆盖输入区；缩放和侧栏收缩不改变官网实际 iframe 布局。
3. 保存失败保留草稿、显示服务器实际错误并提供“重新保存”；禁止静默失败。
4. 对跨页面、跨集合、跨记录的选择和保存增加回归测试。

### P1-1：正式媒体治理和一条媒体闭环

前置输入：正式图片/视频、版权或授权、用途、替代文本、PC 裁切焦点、是否允许公开发布。技术不能自行编造这些信息。

执行：上传一条真实媒体 -> 验证 Directus `directus_files`、`media_assets`、MinIO 实际对象 -> 指定用途和元数据 -> 绑定到真实页面字段 -> 画布预览 -> 保存 -> 认证回读 -> 重载 -> 恢复。

只有此链路完成后，才能逐批开放首页首屏、产品尺寸图、制造设备、证书、品牌、客户、服务图标等替换。`media_assets=0` 时只能显示“待媒体”，不能称为已完成。

### P1-2：内容记录、分页、审核与发布

1. 新闻将标题、业务日期、封面、摘要、富文本正文统一到文章记录；支持新增、编辑、隐藏、排序与详情展开。
2. 视频分享支持视频文件、标题、业务日期；默认采用首帧，抽帧失败时提示并允许指定海报。
3. 产品参数、设备、证书、品牌、客户使用独立记录，支持新增、排序、隐藏与前台分批展示。
4. 实现并验证 `draft -> in_review -> published -> archived`、角色权限、审计、版本恢复、发布/下线与网络失败重试。公开端只读 `published`，授权预览才可读取草稿。

### P1-3：受控样式与位置

每个区块只开放事先声明的 `font_family`、`font_size`、`font_weight`、`line_height`、`color`、`align`、`offset_x`、`offset_y`、`max_width`、`z_index`、`visible`，并定义最大边界。超出范围时拒绝保存或回退。

必须在 `1440x900`、`1920x1080`、`3840x2160` 验证文字不溢出、不遮挡、不卡住动画、不改变原 Nuxt 模板几何。

## 6. 页面编辑界面要求

- 顶部：页面/区块面包屑、选择/文字/媒体模式、撤销、重做、缩放、保存草稿、预览与状态。
- 左侧：当前页面的区块和记录列表，可搜索/折叠；禁止放完整表单。
- 中央：真实 Nuxt iframe；编辑模式拦截链接跳转、卡片打开与视频播放，只用于选择；浏览模式保留原行为。
- 右侧：当前元素允许的内容、媒体、受控样式/位置、绑定诊断与保存错误；没有稳定绑定的元素必须显示只读原因。
- 预览：实时草稿更新不依赖视频结束；视频首尾帧处理与画布编辑解耦。

## 8. 暂停与决策条件

以下情况必须暂停并要求业务决策，而不是由开发自行猜测：

1. 需要改变 PSD、原页面几何、动画或响应式才能满足编辑要求。
2. 没有正式素材却要求将静态资源标记为“CMS 可替换”。
3. 同时要求任意拖拽/CSS 编辑与现有版式完全不变。
4. 要删除资讯、证书或媒体，但未提供明确保留清单与删除范围。
5. 需要确定新闻日期时区、同日排序、审核人和发布人职责，但业务规则未确认。
