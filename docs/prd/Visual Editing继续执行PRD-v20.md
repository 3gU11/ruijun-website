# 瑞钧官网 Visual Editing 继续执行 PRD

- 版本：v20.0
- 日期：2026-08-26
- 本版本用途：基于 v19 的执行重整稿，作为后续开发、测试和业务验收的单一执行入口
- 首期范围：PC 网页端六页；手机端只做只读回归，不开放移动端编辑
- 继承文档：`Visual Editing继续执行PRD-v19.md`、`CMS可编辑内容清单与视觉控制规范.md`

## 1. 先确认边界

“六个页面所有内容都可视化编辑”不能理解为把 Nuxt 改成任意拖拽建站器。当前官网的布局、PSD 坐标、动画、路由、锚点和响应式结构已经存在，继续执行必须保护这些结构。

本期只把有明确业务数据来源的内容接入 CMS：文字、图片、视频、新闻、产品、证书、客户、合作品牌、里程碑和办事处。没有 Directus 记录、没有文件对象或只来自 PSD/fallback 的内容只能展示为只读，并在工作台显示原因。任意 HTML/CSS/脚本、无限像素拖拽和改变页面骨架不在本期范围。

## 2. 目标与完成定义

运营人员从 CMS 工作台进入一个页面，在同一窗口内完成：选择画布元素 → 顶部工具栏或右侧属性面板修改 → 300ms 内看到草稿叠加 → 保存 → Directus 精确回读 → 刷新后仍保持 → 可取消/撤销/恢复。

P0 完成必须同时满足：

1. 工作台只按“一级页面 → 真实区块”组织，不出现重复的同名分类。
2. 每个可编辑元素都能显示完整绑定：`collection`、真实 `itemId`、`sectionKey`、`fieldPath`。
3. 预览与编辑面板并排显示，预览不能覆盖编辑面板，也不要求等待视频播放结束。
4. 草稿只在预览会话显示，公开接口只返回已发布内容。
5. 图片/视频保存后能证明 Directus 文件元数据和 MinIO 对象同时存在；失败时不留下半条业务记录。
6. Nuxt 原布局、动画、坐标、路由、锚点和 PC/手机响应式行为无非内容性变化。

## 4. 统一绑定与编辑规则

所有画布元素必须使用稳定 Directus 记录 id，禁止用页面 id 或数组下标冒充业务记录：

```json
{
  "collection": "product_series",
  "itemId": "1",
  "sectionKey": "series-card",
  "fieldPath": "title"
}
```

允许的视觉参数为字体、字号、字重、颜色、行高、对齐、排序、裁切模式、焦点和模板白名单内的有限偏移。服务端必须校验范围，保存前给出字段级错误。静态 PSD、代码 fallback、未托管外链不生成编辑绑定。

媒体最低要求：图片记录必须含文件 id、MIME、字节数、宽高和 MinIO 对象 key；视频必须含 MIME、字节数、时长、宽高和首帧策略。规格提示只作为校验和上传引导，不自动改变官网布局。

## 5. 内容与列表规则

- 动态新闻：标题、业务日期、封面、富文本详情、发布状态；点击封面或标题展开详情。
- 视频分享：标题、业务日期、视频文件；无独立海报时用视频首帧，可人工替换。
- 新闻和视频分享每页最多 6 条，按业务日期倒序；页码越界收敛到最后一页。
- 产品、设备、证书、客户和合作品牌支持新增、编辑、隐藏、排序和分页/轮播，不限制 CMS 库存。
- 首页和关于瑞钧共用 `milestones` 主数据，不复制时间轴。

## 7. 继续执行顺序

### P0-1 服务支持绑定治理

先新增失败测试覆盖：静态服务 fallback 不产生媒体绑定；真实 `service_locations/<id>` 保留 `region`、`contact.address`、`contact.name`、`contact.phone` 精确路径；配置区块重复项不以数组标题代替记录身份。通过后做最小实现，并执行服务页定向测试。

### P0-2 六页最小闭环

每页各抽取一个文字、图片、视频或重复项，完成“选择、草稿预览、保存、回读、刷新、取消、撤销、恢复”。每次记录请求目标、绑定、原值/临时值/最终值和页面截图。

### P0-3 真实媒体闭环

业务提供至少一份审核图片和一份视频。创建 `media_assets`，验证 MinIO 对象、文件元数据、Nuxt 渲染、预览草稿和发布回读。没有素材时把切片保持为阻塞，不伪造成功。

### P0-4 列表、详情和分页

完成新闻图文展开、视频首帧、6 条上限、日期排序，以及产品/设备/证书/客户图库的新增、隐藏、排序和分页回归。

### P0-5 审核发布闭环

验证草稿 → 待审核 → 已批准 → 已发布、退回和回退。用编辑、审核、发布不同角色调用 API，确认公开 BFF 只返回已发布内容。

### P1 体验完善

批量上传、规格提示、定位高亮、键盘操作、断连重试、操作日志和手机只读回归；不改变官网视觉设计。

## 8. 验收证据与测试门槛

每个切片固定执行：失败测试 → 最小实现 → 定向测试 → Nuxt/CMS 全量测试 → 生产构建 → Chromium PC 验收 → Directus/MinIO 精确回读 → 刷新 → 撤销/重做/恢复。发布前至少保留六页各一条完整证据，且不得记录密码、token 或 cookie。

P0 发布门槛：定向测试全通过；全量测试无回归；Nuxt 构建通过；PC 画布不遮挡编辑面板；公开接口不泄漏草稿；真实媒体有 MinIO 对象；任一失败均标记对应切片阻塞。

## 9. 外部前置条件与待确认事项

1. 业务提供正式文案、图片/视频、标题和日期，并指定编辑、审核、发布人。
2. 明确审核与发布是否必须三人分离，以及回退保留版本数。
3. 确认新闻日期时区、产品/设备/证书/客户默认分页数量和上传大小限制。
4. 确认哪些现有记录是演示数据；删除前必须备份并取得清单确认。

## 10. 本版本结论

当前系统适合继续做“受控 Visual Editing”，不适合宣称已经完成任意元素、任意位置的 PPT 式建站。下一次开发从 P0-1 服务支持绑定治理开始；素材和发布权限是 P0-3/P0-5 的真实前置条件，不能由代码或 fallback 替代。
