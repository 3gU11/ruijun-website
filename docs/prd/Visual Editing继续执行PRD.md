## 1. 产品目标

在 Directus“内容编辑工作台”中，以类似 PowerPoint 的工作区操作真实 Nuxt 页面：

```text
选择六个官网栏目之一
-> 在真实 Nuxt 画布中定位并选中内容
-> 显示真实 collection / itemId / fieldPath
-> 修改文字、合规媒体和受控视觉属性
-> 即时预览、撤销、重做
-> 保存 Directus 草稿
-> 刷新后结果一致
-> 审核与发布
```

目标不是让运营人员重做网页，而是在不改变现有 PSD 视觉结构的前提下，让已经登记的内容可直接在画布中修改。

## 2. 必须先明确的产品边界

### 2.1 本期必须实现

- 工作台只设六个一级栏目：网站主页、产品展示、先进制造、视频新闻、关于瑞钧、服务支持。
- 中央区域加载真实 Nuxt PC 页面，不使用仿制预览或孤立表单代替官网。
- 双击或选中元素后，顶部工具栏和属性面板编辑同一条草稿。
- 每次写回使用真实 `collection`、真实 `itemId` 和精确 `fieldPath`，不得根据通用字段名猜测目标。
- 支持文字、图片、视频、受控位置、对齐、字号、字重、颜色、行高和列表排序。
- 支持撤销、重做、取消恢复、保存失败保留草稿和未保存离开提示。
- 预览不能遮挡编辑区，不能等待视频播放结束，刷新后仍能定位到对应元素。
- 所有视觉能力默认关闭，只有显式启用后才覆盖 Nuxt 原样式。

### 2.2 本期明确不做

- 不允许任意 HTML、CSS、脚本、外链素材或无约束的像素拖拽。
- 不允许运营人员改变 Nuxt 的 PSD 布局、动画、路由、锚点、断点和响应式结构。
- 不做类似 HTMLPage 的通用页面生成器、自由区块拼装或模板市场。
- 手机端不开放原位编辑，只做只读预览和回归检查。
- “素材不限制数量”只指 CMS 库存可扩展；前台仍必须分页、轮播、折叠或懒加载。

### 2.3 为什么不能照搬 PowerPoint 自由拖拽

PowerPoint 面向固定画布，官网同时受动画、滚动状态、不同宽度和 DOM 阅读顺序约束。无限制拖拽会破坏原 PSD 比例和响应式。本期借鉴 PowerPoint 的顶部工具栏、选中框、属性面板和操作历史，但只开放白名单属性与受控偏移。

## 3. 用户与核心流程

| 角色 | 主要任务 | 权限边界 |
| --- | --- | --- |
| 内容编辑 | 选择页面、修改草稿、替换已审核媒体、预览 | 不能直接发布，不能选择未授权媒体 |
| 内容审核 | 对比草稿与当前版本、退回或批准 | 不替代技术与版权确认 |
| 发布人员 | 查看发布阻断项、发布、回滚 | 不能绕过字段、媒体和证据校验 |
| 系统管理员 | 维护模型、权限、绑定和运行环境 | 不应代替业务方确认宣传数据 |

正常流程：

```text
进入工作台 -> 选择栏目/内容区 -> 画布滚动定位
-> 选中元素 -> 查看绑定身份 -> 修改草稿
-> 即时预览 -> 撤销/重做 -> 保存
-> Directus 数据核验 -> 刷新复核 -> 提交审核
```

失败流程：

```text
保存失败 -> 画布保留未保存内容 -> 历史仍可撤销
-> 显示明确错误 -> 用户重试或取消恢复最近成功基线
```

## 4. 信息架构

工作台左侧一级导航只保留六页，不再出现“网站主页 -> 网站主页”之类的重复层级。二级内容区按页面真实结构划分，例如网站主页包含：首页视频、三大理由、产品系列、横移图文、时间轴、页尾。

```text
页面模板层：六个真实 Nuxt 页面
        ↓
Block 层：Hero / TextMedia / ProductList / NewsList / Gallery
          Timeline / ProcessCanvas / Offices / RichText
        ↓
Visual Binding：sectionKey + collection + itemId + fieldPath
                + elementType + mediaRole + placementKey
        ↓
Directus 数据层：pages / articles / product_series / product_models
                 milestones / qualifications / service_locations / ...
```

PC 工作区固定为：顶部编辑工具栏、左侧页面/内容区导航、中央真实 Nuxt 画布、右侧属性面板。专注画布模式必须有明显退出入口，不得覆盖编辑控件。

## 5. 数据与保存契约

每个可编辑 DOM 必须提供以下身份：

```json
{
  "sectionKey": "service-offices",
  "collection": "service_locations",
  "itemId": 1,
  "fieldPath": "service_scope",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

保存规则：

- `collection/itemId/fieldPath` 三者缺一时只读，不能开放保存。
- 字符串 ID 与数字 ID 必须先解析为 Directus 返回的真实主键，再选择记录。
- 跨集合只能装饰明确声明集合和真实 ID、且与当前预览会话匹配的根节点。
- 写回前校验集合白名单、记录存在、字段路径合法、消息来源与当前会话一致。
- 一次保存涉及多个集合时，必须分别记录成功/失败；任一失败不能清空未保存草稿。
- 保存成功后更新本地成功基线；取消恢复该基线，而不是依赖网络重新加载。

受控视觉字段：

```text
layout.enabled / align / offset_x / offset_y / max_width
text_style.enabled / preset / font_family / size_desktop
text_style.weight / line_height / color
media_presentation.fit / focal_x / focal_y / overlay / poster_asset_id
```

偏移默认限制为容器比例 `-30..30`；字体只允许项目内置字体；危险链接、未知集合、原型链路径、任意 CSS 和脚本必须拒绝。

## 9. TDD 与证据规则

每个执行切片固定采用：

```text
先写失败测试
-> 最小实现
-> 定向测试
-> CMS/Nuxt 全量测试
-> 构建
-> 真实 PC 浏览器操作
-> Directus 数据核验
-> 恢复测试数据
```

每个浏览器样本必须记录：页面、内容区、可见文字或媒体、`collection/itemId/fieldPath`、修改前后值、即时预览、撤销/重做、保存结果、Directus 返回值、刷新结果、恢复结果和验收时间。证据中不得记录密码或 token。

## 10. 媒体规格与治理

每个媒体位置在 CMS 中显示基于真实页面容器审计得到的推荐比例、最小尺寸、格式、最大文件体积、`cover/contain`、焦点、海报和视频编码要求。不得用一套经验数值覆盖所有位置。

通用底线：

| 类型 | 允许格式 | 治理要求 |
| --- | --- | --- |
| 图片 | JPG、PNG、WebP、AVIF | 有替代文本、用途、版权、位置规格；透明标志优先 `contain` |
| 视频 | MP4、WebM | 有标题、用途、版权；首屏视频需海报/替代图，预览先渲染文字和海报 |
| 文档 | PDF | 只能用于资料下载，不得作为图片或视频验收素材 |
| 图标/品牌标志 | 受控 SVG 或透明位图 | 需要名称、用途、浅深色适配和授权信息 |

媒体引用必须同时满足：记录有效、已启用、已发布、版权为 `owned/licensed/authorized`、类型匹配、用途匹配、`placementKey` 匹配。
