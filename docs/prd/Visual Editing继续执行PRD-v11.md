# 瑞钧官网 Visual Editing 继续执行 PRD

- 版本：v11.0
- 日期：2026-08-25
- 状态：执行基线，P0 未完成
- 目标端：PC Web；手机端本阶段只读回归
- 关联版本：`Visual Editing继续执行PRD-v10.md`

## 1. 一句话目标

在不改变现有 Nuxt 官网视觉布局、动画、路由、锚点和响应式结构的前提下，建立一个类似网页编辑器的 PC 工作台：运营人员可以在真实官网画布中选中页面元素，在顶部工具栏/右侧属性面板编辑文字、媒体、排序和受控视觉属性，并完成即时预览、保存、撤销、重做、刷新保持和失败恢复。

## 2. 先校正三个前提

1. **自动化测试通过不等于 CMS 闭环完成。** 必须同时有真实 PC 浏览器、Directus 读取和刷新/恢复证据。
2. **“所有内容可编辑”不等于开放任意 CSS 或无限画布。** 本期只允许白名单属性和受控位置偏移，避免破坏 PSD 布局、响应式和维护成本。
3. **“素材数量不限制”只适用于 CMS 存储。** 官网展示必须通过分页、轮播、折叠、懒加载或限制单页数量来控制性能。

## 3. 用户与核心场景

### 3.1 用户

- 内容运营：编辑文字、图片、视频、新闻、产品资料和排序。
- 审核人员：检查草稿、发布状态、媒体用途和版权信息。
- 开发人员：维护绑定契约、组件和回归证据，不代替运营录入业务内容。

### 3.2 核心流程

```text
选择栏目 → 选择区块 → 真实 Nuxt 画布选中/双击元素
→ 顶部工具栏或右侧面板编辑 → 画布即时反映草稿
→ 保存草稿 → Directus 核验 → 刷新复核
→ 撤销/重做/取消恢复 → 重新保存或提交审核
```

预览不能遮挡编辑面板；视频不得阻塞首屏或要求播放结束后才可编辑。画布需提供退出专注模式的明确按钮。

## 4. 产品范围

### 4.1 六个栏目

| 栏目 | 主要区块 | 可编辑内容 |
| --- | --- | --- |
| 网站主页 | 首页视频、三大理由、产品系列、横移图文、时间轴、页尾 | 视频/海报、标题、正文、按钮、图标、年份、里程碑、页尾文字 |
| 产品展示 | 首屏、筛选、系列、型号、参数、尺寸图、资料 | 标题、封面、型号、参数、单位、尺寸图、资料、排序、分页 |

| 视频新闻 | 首屏视频、动态新闻、视频分享 | 标题、日期、封面、图文正文、视频文件；列表每页最多 6 条，日期降序 |
| 关于瑞钧 | 故事、时间轴、厂区、认证/荣誉/专利、品牌、国内外客户 | 背景、文案、年份/事件、证书和客户图库、标题、排序 |

Header、Footer 和全站公共按钮使用全站设置维护一次，不在六个栏目中重复维护。

### 4.2 本期不做

- 不重绘或重排 Nuxt 原有 PSD 页面。
- 不做手机端自由编辑画布；手机端只保证展示不回归。
- 不开放任意 HTML、CSS、JavaScript、外链和无限像素拖拽。
- 不用演示资讯或未审核媒体作为业务验收数据。

## 5. 目标工作台

固定为四区布局：

1. **顶部操作栏**：栏目切换、撤销、重做、保存、草稿状态、预览/退出预览。
2. **左侧导航**：六个栏目及其真实页面区块，例如“网站主页 → 首页视频 / 三大理由 / 产品系列 / 时间轴”，禁止重复的两层同名分类。
3. **中央画布**：真实 Nuxt PC 页面 iframe，支持点击选中、双击编辑、选中高亮、滚动定位和不阻塞视频的媒体预览。
4. **右侧属性面板**：内容、媒体、排序和视觉属性；无完整绑定时显示只读原因，不显示误导性的保存按钮。

### 5.1 可视化操作规则

- 文本：双击进入编辑；支持内容、字体、字号、字重、颜色、行高、对齐和受控位置偏移。
- 图片：替换、裁切/适配、焦点、遮罩、说明文字；显示规格要求和当前媒体状态。
- 视频：替换媒体、海报、静音/自动播放策略；预览采用可跳过/静音方式，不等待播放结束。
- 列表：新增、编辑、删除、排序、分页；保存时保留 Directus 原始数组索引。
- 位置：只允许容器比例 `-30..30` 的受控偏移；越界、重叠和响应式破坏必须提示。

## 6. Visual Binding 契约

每个可编辑 DOM 元素至少声明：

```json
{
  "sectionKey": "manufacturing-core-equipment",
  "collection": "manufacturing_evidence",
  "itemId": 3,
  "fieldPath": "media.2",
  "elementType": "image",
  "mediaRole": "image",
  "placementKey": "equipment-3"
}
```

规则：

- `collection`、真实 `itemId`、`fieldPath` 任一缺失时，该元素只读。
- `itemId` 必须来自 Directus 返回，禁止用 URL、数组下标或字段名推断。
- `pages` 区块使用 `sectionKey` 定位页面内 section；页面 section 不是自动生成的独立 Directus 记录。
- 跨集合保存必须隔离；一个集合失败不得覆盖其他集合成功结果。
- 保存成功建立本地基线；取消恢复最近成功基线；新编辑清除重做分支。
- 视觉属性只能写入白名单字段，不将样式字符串直接写入业务正文。

## 7. 数据与媒体要求

### 7.1 记录模型

优先复用现有集合：`pages`、`homepage_sections`、`product_series`、`product_models`、`articles`、`milestones`、`qualifications`、`manufacturing_evidence`、`service_locations`。确需新集合时先补迁移、权限、字段说明和回滚方案。

### 7.2 媒体规格

- 图片：保留原图和缩略图，记录用途、版权、替代文本、宽高和格式；前台按区块要求裁切/适配。
- 视频：记录媒体文件、封面/第一帧、时长、编码和用途；首屏必须支持静音预览和加载失败回退。
- 上传前校验类型、大小、用途和发布状态；MinIO 为媒体存储，Directus 保存元数据。

## 11. Definition of Done

P0 仅在以下全部满足时关闭：

1. 六页承诺元素全部真实绑定，或明确标记为只读/延期/待建模；
2. 文字、媒体、排序和白名单视觉属性支持即时预览、保存、撤销、重做、失败恢复和刷新保持；
3. 跨集合操作只写目标 Directus 记录；
4. 审核媒体通过类型、用途、发布和版权校验；
5. CMS/Nuxt 测试、扩展构建、Nuxt 构建和健康检查通过；
6. PC 多分辨率无布局回退，手机端只读不被破坏；
7. 测试数据已恢复，并留存真实闭环证据。
