## 1. 目标与成功标准

在 Directus 内容编辑工作台中，运营人员可以在真实 Nuxt 页面画布上定位并编辑已经登记的内容。编辑行为类似 PowerPoint 的“选中、属性修改、即时预览、撤销/重做”，但不改变官网原有 PSD 布局、动画、路由、锚点、断点和 DOM 结构。

一次能力只有在以下证据全部具备时才算完成：

1. 画布元素带有精确的 `collection/itemId/fieldPath`。
2. PC 浏览器中能选中元素并立即看到修改结果，不依赖视频播放结束。
3. 保存后通过 Directus 读取目标记录，证明只写入目标字段。
4. 刷新页面后内容一致，撤销、重做、取消恢复和失败保留草稿行为正确。
5. 自动化测试、构建和基础设施健康检查通过。

代码存在、入口可打开、单元测试通过或画面发生变化，均不能单独视为完成证据。

```text

    ↓

          + elementType + mediaRole + placementKey
    ↓

```

PC 工作区固定为：顶部工具栏、左侧六页和当前页面内容区导航、中央真实 Nuxt 画布、右侧属性面板。预览不可覆盖编辑区；专注画布模式必须有明显退出入口。页面内容区导航必须直接对应页面真实区块，禁止出现“网站主页 -> 网站主页”的重复分类。

## 4. 数据绑定与保存契约

每个可编辑 DOM 至少包含：

```json
{
  "sectionKey": "service-offices",
  "collection": "service_locations",
  "itemId": 1,
  "fieldPath": "service_scope",
  "elementType": "text",
  "mediaRole": null,
  "placementKey": null
}
```

规则：

- 三项身份任一缺失时只读，不能显示可保存控件。
- `itemId` 必须使用 Directus 返回的真实主键，不得从 URL 字符串或通用字段名猜测。
- 跨集合绑定必须声明集合、真实 ID 和当前预览会话；禁止装饰器污染相邻记录。
- 多集合保存逐项返回成功/失败；部分失败时保留未保存草稿和历史。
- 保存成功更新本地成功基线；取消恢复该基线，不依赖网络重新加载。

受控视觉字段：`layout.enabled/align/offset_x/offset_y/max_width`、`text_style.enabled/preset/font_family/size_desktop/weight/line_height/color`、`media_presentation.fit/focal_x/focal_y/overlay/poster_asset_id`。偏移默认限制为容器比例 `-30..30`，字体只能使用项目字体，任意 CSS、脚本和危险链接必须拒绝。

## 8. TDD 与证据模板

每个切片必须遵循：

```text
失败测试 -> 最小修复 -> 定向测试 -> 全量测试 -> 构建
-> 真实 PC 浏览器 -> Directus 核验 -> 刷新复核 -> 恢复测试值
```

证据至少包含：页面、内容区、元素、`collection/itemId/fieldPath`、修改前后值、即时预览、撤销/重做、保存结果、Directus 返回值、刷新结果、恢复结果、时间。不得记录密码或 token。

## 9. 媒体与内容治理

每个媒体位置必须基于真实容器审计显示推荐比例、最小尺寸、格式、体积、`cover/contain`、焦点和视频海报要求。图片允许 JPG/PNG/WebP/AVIF，视频允许 MP4/WebM，文档 PDF 仅用于下载。引用必须满足记录有效、启用、发布、版权合规、类型/用途/`placementKey` 匹配。
