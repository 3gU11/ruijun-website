## 2. 执行准备与统一约定

### 2.1 环境与数据

- 使用隔离测试环境，记录代码提交号、未提交改动、浏览器版本、实际访问地址与执行时间。当前工作区已有源码改动，执行前需记录差异。
- 配置参考：官网 4175、CMS 8055、MySQL 3307、MinIO 9000/9001；执行前确认实际配置，不仅检查端口监听，还检查页面和接口响应内容。
- 准备编辑者、审核者、发布者及无权限用户；缺少角色账号时对应权限用例记为阻塞，不用管理员代测后判通过。
- 数据统一前缀 `FT-20260923-<用例ID>`；仅使用专用测试记录。执行前保存原值、状态、关联关系和媒体清单。
- 准备两张内容明显不同、用途相同的合规图片 A/B；一段可播放 MP4、对应海报、可下载 PDF；不使用真实客户个人资料。
- 准备至少两个不同产品型号、7 条不同业务日期的新闻和 7 条视频记录。公开测试须在隔离环境准备已发布夹具，不能为测试发布真实业务草稿。
- PC 使用 1440×900、1920×1080、3840×2160；移动公开页面使用 390×844。移动 CMS 编辑不是本期必验范围。
- 故障注入仅针对测试请求或隔离服务；不停止共享数据库、不初始化数据库、不执行种子覆盖真实数据。

### 2.2 公共步骤

下表用例引用的公共步骤必须完整执行，并记录实际集合、记录 ID、字段路径；不可用历史 ID 猜测当前目标。

**C1 文字保存闭环**：①认证读取原值及发布状态；②在工作台画布点击目标，确认属性面板绑定；③修改为带用例标记的新值，检查即时预览；④保存草稿并认证接口回读；⑤完整刷新工作台，检查字段及画布一致；⑥恢复原值、保存、回读及再次刷新。

**C2 媒体替换闭环**：①记录原关联；②画布选择目标，由 A 替换为内容明显不同的 B；③确认新资源请求成功、图片实际解码或视频实际播放；④保存、认证回读媒体 ID、完整刷新确认；⑤恢复原关联并验证。只重新选择 A 不算替换通过。

**C3 列表闭环**：①记录原列表、稳定 ID 与顺序；②新增专用测试条目；③编辑、重排、隐藏及确认删除，逐步保存并回读；④刷新检查无串项、重复或丢失；⑤恢复原列表并回读。若产品未提供恢复入口，应记录缺口，不擅自删除真实条目。

**C4 发布闭环**：在隔离环境，记录公开旧版本 → 编辑草稿并确认公开端未变化 → 按配置完成审核及发布 → 公开接口回读 → 新无痕会话查看页面 → 比对内容/媒体/版本 → 恢复测试前发布状态。不得用带预览令牌的页面证明公开发布成功。

### 2.3 优先级与状态

- P0：核心保存、绑定正确、权限和数据隔离等阻断问题。
- P1：列表、异常恢复、入口联动等主要功能。
- P2：辅助交互和补充边界。
- 优先级仅在所属阶段内比较；发布阶段 P0 不代表必须先完成复杂审批才能验收草稿编辑。
- 状态：未执行 / 通过 / 失败 / 阻塞 / 不适用。不适用须写明批准的范围依据；缺功能、缺素材、缺账号不能直接当作通过。
- 表内“UI+API”表示真实浏览器操作与认证接口回读均需完成。每行多个断言全部满足才能通过。

## 6. 冒烟顺序与验收标准

建议冒烟顺序：ENV-01～03 → ED-01/02 → PG-01～12 → PR-03/04 → MED-01/08 → ERR-02 → PUB-01 → WEB-01/03。阶段发布时追加 PUB-02/04/05。完整回归执行所有已纳入范围的用例。

建议阶段准入标准（需项目负责人认可）：

1. 已纳入阶段的 P0 全部通过，无未解释的数据损坏、越权、草稿泄露和错型号问题。
2. 六页逐页提供画布操作、保存请求、认证回读、刷新以及恢复证据；一条样本通过不代表全页所有字段均可编辑。
3. 发布测试使用无痕公开页面；预览成功不能替代发布成功。
4. 阻塞、不适用和延期项逐条说明，不从结果中静默删除。
5. 临时记录与媒体清理完成，原值和关联回读一致；不得按测试前缀批量删除未经核对的记录。

## 8. 现有自动化入口
