# 服务支持页面调研

flow: 制造设备官网的售后与联系入口

## 可采用的通用模式

- 一个主问题入口优先于平铺的多个同类动作。用户先描述需求，系统再按意图给出下一步，避免在“维修申请、进度查询、保修核验”之间反复判断。
- 任务入口和系统动作分层。官网负责识别问题、说明准备材料；维修工单系统只在用户需要提交或查询时打开。
- 面向不同意图的内容可以保留，但应作为第二层的情境入口，而不是与主入口重复的四个大卡片。

## 竞品观察

- Google Help Center: 首页首先要求用户“描述您的问题以查找可能对您有所帮助的信息”，产品选择在其后。采用“先描述，后分流”的信息层级。
  Source: https://support.google.com/
- Cisco Support: 先提供“Troubleshoot by product”，再分出文档、软件下载、安全公告等资源；工单和历史记录收在独立的 “My support” 区域，并将虚拟助手作为快速支持工具。
  Source: https://www.cisco.com/c/en/us/support/index.html
- Microsoft Support: 首屏使用“今天需要什么帮助？”按产品或使用场景进入，页面下方再给出具体解决方案和联系渠道。
  Source: https://support.microsoft.com/zh-cn/

## 当前页面的问题

- 四张售后卡都能进入同一个 AI 客服，视觉上看似有四个入口，实际却是一次重复操作。
- 固定悬浮入口与区块内按钮承担了相同功能，用户难以判断哪个是主要路径。
- 客服入口图标使用拼接式气泡轮廓，在小尺寸下易产生断边和杂色。

## 本轮落地

- 将“在线售后服务”改为一个 AI 服务台：一个主按钮，三条非点击式办理能力说明。
- 保留全局悬浮入口作为任意页面的快捷唤起，但改成无图标拼接的文字状态入口。
- 报修、进度、保修的维修系统链接仅在 AI 已确认意图后的“下一步”页面出现。
