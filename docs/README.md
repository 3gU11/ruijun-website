# 瑞钧项目文档中心

`docs/` 是本项目需求和说明文档的唯一归档目录。以后新增或更新 PRD、需求说明、架构说明、设计研究、实施方案、部署运维说明、模块运行说明、QA 记录和资料台账时，必须放在本目录对应分类中，不在项目根目录或各代码模块中新增项目自有的 Markdown 文档。

## 当前主文档

- [官网与售后系统一体化 PRD](prd/官网与售后系统一体化PRD.md)：当前跨系统需求与目标架构的主要依据。
- [官网 FAQ 与维修系统目标架构](architecture/官网FAQ与维修系统目标架构.md)：已确认的双端 FAQ、维修事实和一次性交接边界。
- [新网站建设方案](prd/新网站建设方案.docx)：早期网站页面需求源。
- [网站设计方案 v2](design/网站设计方案-v2-全屏生命周期版.md)：官网视觉、信息架构和交互方案。

## 目录结构

| 目录 | 用途 |
|---|---|
| `prd/` | PRD、业务需求、原始需求稿 |
| `architecture/` | 系统架构、系统边界、集成方案 |
| `design/` | 设计背景、研究、方案、审计和 QA |
| `implementation/` | 分阶段开发和专项实施计划 |
| `operations/` | 本地开发、部署、运维和安全说明 |
| `modules/` | 官网、CMS、FAQ、Demo 等模块运行说明 |
| `reference/` | 原始资料盘点、数据台账和核实记录 |
| `assets/` | 仅供文档引用的图片等配套素材 |

## 新文档规则

1. 先选择最接近的分类；没有必要时不新增一级目录。
2. 文件名应直接说明主题，避免使用 `notes.md`、`new.md`、`final.md` 等含义不清的名称。
3. PRD 和实施方案应在开头记录版本、日期、状态和负责人；变更既有需求时优先更新主文档，避免创建多个互相冲突的副本。
4. 文档链接使用相对于 `docs/` 内当前文件的相对路径；配套图片放入 `assets/`。
5. 代码路径仍指向实际模块目录，如 `../../website/`、`../../cms/` 和 `../../repairsys/`；不要把源码或运行数据复制进 `docs/`。
6. `node_modules`、构建产物、测试缓存和工具生成的第三方 Markdown 不属于项目文档，不迁入本目录。
