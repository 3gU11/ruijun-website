# 本地开发环境

> 适用代码目录：`../../repairsys/`。下文命令均在 `repairsys/` 中执行。

## 当前版本

这个初版先做成可本地运行的模块化单体：

- 后端：Node.js + Express，后续 Java/JDK 环境可用后再迁 Spring Boot
- 前端：Vue 3 + Element Plus
- 数据库：MySQL 优先；未配置 MySQL 时使用 `data/db.json` 兜底
- 文件：第一版先预留附件表，真实上传目录后续接入
- 本地安全版：服务端 HttpOnly 会话 Cookie、角色权限、密码哈希和受限跨域

## 安装依赖

```powershell
npm install
```

## 初始化 MySQL

先安装并启动 MySQL 8.x，然后在项目根目录执行：

```powershell
npm run db:init -- -User root -Password 你的密码
```

这个脚本会执行：

- `database/schema.sql`：创建 `repair_system` 数据库和业务表
- `database/seed.sql`：写入机床、物料、实例、绑定、维修申请、工单等虚拟数据
- `.env`：如果不存在，会自动生成本地数据库配置

当前机型字典不再从 V8 数据库实时读取；即使未启用 MySQL，仍使用项目内的本地快照。

当前本地试运行阶段不连接 V8。客户端机型和机型拍照配置读取项目内的 `data/v8-photo-config.snapshot.json`，机台与零件绑定基础资料读取 `data/v8-machine-bindings.snapshot.json`；后续由本地同步脚本从 V8 转换后上传到维修系统，再替换/更新维修系统自己的配置数据。

如果上述 V8 快照尚未生成，服务端会自动从维修系统 MySQL 的机床、物料、物料实例和绑定关系生成兼容数据，相关接口仍可用于本地开发；放入正式快照后会优先读取快照。

安全配置：`AUTH_SECRET` 必须换成随机长字符串；生产环境设置 `NODE_ENV=production`、`COOKIE_SECURE=true`，并把 `CORS_ORIGINS` 改成实际前端域名。生产部署应使用构建后的 `dist` 和 HTTPS 反向代理，不要把 Vite 开发服务器或 `3101` API 端口直接暴露到公网。

如果你的 MySQL 用户不是 `root`，或端口不是 `3306`：

```powershell
powershell -ExecutionPolicy Bypass -File database/init-mysql.ps1 -HostName 127.0.0.1 -Port 3306 -User root -Password 你的密码
```

## 启动系统

```powershell
npm run dev
```

默认地址：

- 客户端/代理商申请：http://127.0.0.1:2888/
- 工厂后台管理：http://127.0.0.1:1888/
- 后端：http://127.0.0.1:3101/api/health

## 当前已覆盖

- 代理商提交维修申请，一单多零件
- 系统根据机床编号和零件编号提示在保、出保、未建档、绑定异常
- 工厂审核，通过后自动生成维修工单
- 维修部接单、登记检测结果、维修方案和维修结果
- 零件更换记录，并自动更新旧件/新件绑定关系
- 手工登记寄回物流单号
- 机床、物料、物料实例、绑定关系基础资料
- V8 同步任务记录预留
- 基础报表和操作日志

## 数据库说明

核心表：

- `machines`：机床档案
- `materials`：物料档案
- `material_instances`：可追溯零件实例
- `machine_material_bindings`：机床与零件绑定关系
- `repair_requests` / `repair_request_items`：维修申请主表和明细
- `work_orders`：维修工单
- `replacement_records`：维修更换记录
- `logistics_records`：寄回物流
- `v8_sync_tasks`：V8 同步任务记录
- `operation_logs`：操作日志

## 开发注意

不要把数据库密码写进代码。真实配置放 `.env`，仓库里只保留 `.env.example`。
