## 3. 服务托管（计划任务）

全部服务由 `\Ruijun\` 计划任务在开机时以 SYSTEM 身份启动，带失败自动重启（每分钟一次，无次数上限）：

| 任务 | 启动内容 |
| --- | --- |
| Redis | `redis-server.exe --port 6379 --bind 127.0.0.1` |
| CMS | `npm run start`（Directus） |
| Website | `cmd /c C:\ruijun\start-website.cmd`（设置 PORT/NITRO_PORT=8091） |
| FAQ | `python -m uvicorn app.main:app --host 127.0.0.1 --port 8092 --env-file .env` |
| Repairsys-API | `node server/index.js` |
| Repairsys-Admin | `node serve-repairsys.mjs 2888 dist\admin admin.html` |
| Repairsys-Client | `node serve-repairsys.mjs 1888 dist\client client.html` |

> 注意：不要用 `Start-Process` 通过 SSH 直接拉起常驻进程，SSH 会话结束会被回收。必须走计划任务。

**防火墙**：已新增 4 条入站放行规则（`Ruijun Website 8091`、`Ruijun CMS 8055`、`Ruijun FAQ 8092`、`Ruijun Repairsys 2888 1888`）。主机原有 `Local Cloud 8080/8081` 规则未改动。

## 5. 部署过程中做的代码修复

Nuxt 服务端打包把 `#shared/*`（package.json `imports` 子路径映射）落成了相对构建产物的 `./shared/*`，导致 Nitro 打包阶段 rollup 报 `Could not resolve`。为避免部署依赖本机缓存，做了如下修改（**需合入仓库**）：

1. `website/nuxt.config.ts`
   - 增加 `vite.resolve.alias` 与 `nitro.alias`，把 `#shared` 指到绝对路径；
   - 增加 `nitro:build:before` 钩子，把 `shared/` 复制进 `.nuxt/dist/server/shared` 作为兜底。
2. `website/server/services/cms-media-asset-resolver.mjs`：`#shared/public-media-path.mjs` → `../../shared/public-media-path.mjs`
3. `website/server/services/cms-page-reader.mjs`：`#shared/page-section-registry.mjs` → `../../shared/page-section-registry.mjs`

上述改动不改变运行时行为，只是让构建在不同机器上稳定复现。

## 6. 已知限制与后续建议

1. **CMS 为空库**：`pages`、`product_series`、`articles`、`homepage_sections` 等集合已建好但无数据（0 行）。官网当前显示的是代码内静态兜底内容。需要执行内容迁移或后台录入后，官网才会读取 CMS 数据。
2. **FAQ 问答不可用**：`FAQ_DIFY_BASE_URL` / `FAQ_DIFY_API_KEY` 未配置，`/internal/health/ready` 返回 503。配置 Dify 后改为 `FAQ_ENV=production` 并设置 `FAQ_COOKIE_SECURE=true` 才能启用完整能力。
3. **机型字典降级**：`rjfinshed.model_dictionary` 库表不存在，售后系统日志会告警并退回本地机型数据。
4. **售后账号**：`seed.sql` 的种子用户没有密码，需通过 `/admin/auth/register` 注册首个管理员。
5. **无 HTTPS / 域名**：当前为内网 HTTP 直连。上公网前需配置证书、域名与反向代理，并把 CMS 后台限制到白名单。
6. **与既有 Java 售后系统并存**：主机原有 `8080/8081`（nginx）+ `8082/8788`（Java jar）售后系统未被修改，本次部署的是独立的 Vue/Express 版本，两者数据互不相通。
7. **门户重复暴露**：CMS 的 `8055` 目前对网段开放，正式环境建议仅保留反代入口。
