### 5.1 实时预览链路（画布编辑）

**现象**：后台「官网画布编辑」提示「无法连接官网实时预览」。

**根因 1（主因）**：Directus 运行时**没有把 `.env` 里的 `WEBSITE_PREVIEW_OPEN_URL` 注入 `process.env`**。单独用 dotenv 解析该文件能拿到值（29 个变量、值正确），但 CMS 进程内读不到，导致 `/content-preview-tokens/issue` 返回 `preview_open_url: ""`，`/open` 直接 503「官网预览地址尚未配置」。

**根因 2**：扩展前端兜底函数 `fallbackWebsitePreviewOpenUrl()` 硬编码了开发端口 `:4175`，一旦上面为空就去找不存在的 4175。

**修复**：

1. 新增 `C:\ruijun\start-cms.cmd`，显式 `set` 以下变量后再 `npm run start`，CMS 计划任务改为执行该批处理：
   ```
   WEBSITE_PREVIEW_OPEN_URL=http://127.0.0.1:8091/api/preview/open
   WEBSITE_PREVIEW_ALLOWED_HOSTS=127.0.0.1,localhost,0.0.0.0,172.21.8.71
   CMS_PREVIEW_ORIGINS=http://172.21.8.71:8091,http://127.0.0.1:8091
   WEBSITE_CACHE_INVALIDATION_URL=http://127.0.0.1:8091/api/internal/v1/cms/cache-invalidate
   ```
2. 清除 `cms\.env` 的 UTF-8 BOM（此前由 `Set-Content -Encoding UTF8` 引入）。
3. `content-editor-workbench` 兜底端口 `4175` → `8091`（`src/module.vue` 与 `dist/index.js`）。

**验证**（链路逐段打通）：

| 步骤 | 结果 |
| --- | --- |
| `POST /content-preview-tokens/issue` | 返回 `http://172.21.8.71:8091/api/preview/open` |
| `GET /content-preview-tokens/open` | 200，HTML 含到 `/cms-preview-handoff#cmsPreviewToken=…` 的跳转 |
| 带 token `POST` 官网 `/api/preview/open` | 303 + `set-cookie: ruijun_preview_session`，跟随得 200（143 KB） |
| 官网响应头 | `frame-ancestors` 含 `http://172.21.8.71:8055`，允许后台嵌入 |

> 教训：Directus 的自定义环境变量不要只依赖 `.env`，关键变量在启动批处理里显式注入更可靠；PowerShell 写 `.env` 务必用无 BOM 的 UTF-8。

## 6. 构建修复（已合入仓库）

Nuxt 服务端打包把 package.json `imports` 的 `#shared/*` 落成相对构建产物的 `./shared/*`，导致 Nitro 阶段 rollup 报 `Could not resolve`：

1. `website/nuxt.config.ts`：增加 Vite/Nitro 绝对别名 + `nitro:build:before` 复制 `shared` 兜底；
2. `website/server/services/cms-media-asset-resolver.mjs`、`cms-page-reader.mjs`：改为相对导入。

## 7. 剩余限制与建议

1. **FAQ 问答不可用**：未配置 Dify，`/internal/health/ready` 返回 503。配置后需切 `FAQ_ENV=production` 并设 `FAQ_COOKIE_SECURE=true`。
2. **机型字典降级**：`rjfinshed.model_dictionary` 不存在，售后系统告警后走本地数据。
3. **售后账号**：种子用户无密码，需通过 `/admin/auth/register` 注册首个管理员。
4. **无 HTTPS / 域名**：当前内网 HTTP 直连。上公网前需证书、域名与反代，并把 CMS 限制到固定 IP。
5. **与既有 Java 售后系统并存**：主机原有 8080/8081（nginx）+ 8082/8788（Java jar）未被修改，两套售后数据互不相通。
6. **Directus 版本**：11.17.4，落后主线 12.x 一个大版本，升级需单独评估。
