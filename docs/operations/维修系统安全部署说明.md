# 维修系统安全部署说明

> 适用代码目录：`../../repairsys/`。文中的相对路径和命令均以 `repairsys/` 为基准。

## 当前安全边界

- 未登录只允许健康检查、客户端/后台注册登录、后台注册角色选项、机型字典和机型配置。
- 客户端维修申请按服务端会话中的账号 ID 隔离，不接受前端传入的账号 ID 作为权限依据。
- 后台接口按 `REQUEST_REVIEW`、`WORK_ORDER`、`CLIENT_ACCOUNT_AUDIT`、`MASTER_DATA`、`REPORT_LOG` 等权限校验。
- 登录状态使用签名的 HttpOnly Cookie；浏览器本地存储不作为身份凭据。
- 新密码使用 scrypt 哈希。旧明文账号首次成功登录后自动迁移为哈希。
- 上传文件需要有效登录会话，并按维修申请归属或后台维修权限校验。

## 本地试运行

1. 在 `.env` 中设置随机 `AUTH_SECRET`，不要使用示例值。
2. 保持 `NODE_ENV=development`、`COOKIE_SECURE=false`。
3. `CORS_ORIGINS` 只填写实际使用的本地客户端和后台地址。
4. 使用 `npm run dev`。客户端和后台通过 Vite 将同源 `/api` 代理到本机 `3101`。
5. 防火墙不要把 MySQL 端口开放给局域网；API `3101` 也应只允许本机或受信任网段访问。

## 生产服务器

1. 执行 `npm ci` 和 `npm run build`，只部署 `dist`，不要运行 Vite 开发服务器。
2. 设置 `NODE_ENV=production`、`COOKIE_SECURE=true`、`TRUST_PROXY=true` 和新的随机 `AUTH_SECRET`。
3. 使用 Nginx、Caddy 或 IIS 提供 HTTPS，并把 `/api`、`/uploads` 反向代理到 `127.0.0.1:3101`。
4. 客户端和后台建议使用不同域名；后台域名再增加 VPN 或办公网 IP 白名单。
5. API 进程只监听回环地址；数据库只允许 API 服务器账户访问，并使用独立的最小权限数据库账号。
6. `CORS_ORIGINS` 只配置正式客户端和后台域名。
7. 上线前修改初始管理员密码，删除测试账号和演示业务数据。
8. 配置数据库、上传目录和快照文件的备份；备份文件不得放在 Web 根目录。

Nginx 双域名示例见 `deploy/nginx.conf.example`。
