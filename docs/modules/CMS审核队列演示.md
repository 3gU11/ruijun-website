# CMS 审核队列演示

## 入口

- 内容工作台：`/admin/ruijun-content-editor-workbench`
- 在工作台顶部选择“提交审核”或“审核队列”。

## 送审

编辑人员在“提交审核”中有两个清单：

- “提交审核”只显示 `draft` 草稿，并且只提交 `draft -> review` 的状态流转。
- “恢复草稿”只显示 `rejected` 与 `unpublished` 记录，可执行 `rejected/unpublished -> draft`。恢复后才能继续编辑或重新送审。

两种操作都不会修改内容字段，也不能跳过审核或直接发布。

## 演示范围

审核队列按当前登录账号的 Directus 权限汇总处于“审核中”的官网内容：页面文案、产品、文章、企业资料、服务支持、FAQ、媒体资产和全站设置。

选择任一记录后可以填写审核说明，并提交以下一种流转：

- 批准进入待发布：请求将状态从 `review` 更新为 `scheduled`。
- 退回修改：请求将状态从 `review` 更新为 `rejected`。

页面不提供直接发布功能，也不允许在审核时修改内容字段。角色范围、状态迁移、内容完备性以及受控媒体校验均由 `content-publication-workflow` 服务端钩子最终判定。账号没有对应权限或内容未满足就绪条件时，服务端会拒绝请求，记录保持原状。

队列详情会只读显示已有的提交说明或最近审核说明；本次操作的新说明仍在下方表单填写。这样审核人员能够在同一界面了解前序沟通内容，同时避免在生命周期流转中直接改动内容字段。

## 使用顺序

1. 内容编辑人员在“页面文案”“产品系列”“企业资料”“服务支持”“文章与案例”“FAQ 知识”或“媒体资产”中维护草稿。
2. 通过既有内容版本流程将草稿提交审核。
3. 审核人员在“审核队列”中查看并给出说明，批准或退回。
4. 发布人员在发布就绪度工作台核验后，再执行正式发布。

这样后台演示可以覆盖编辑、审核、发布三段职责，同时保持官网前台只读取已发布内容。
