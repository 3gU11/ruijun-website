# CMS 内容发布演示

本演示只使用本机或 RFC1918 私有地址，并创建带 `DEMO-CMS-CONTENT` / `DEMO-NOTIFICATION-MANUAL-REVIEW` 标记的临时内容。它不会发布现有官网内容，也不会调用官网通知、repairsys、Dify 或外部 Webhook。

## 先看工作台

如果目的是先查看 CMS 的页面结构和后台设计，在 `cms/` 目录执行：

```powershell
npm run demo:seed
```

该命令会幂等创建一组仅供演示的草稿：页面、新闻、产品系列、产品型号、独立参数，以及一条通知异常示例。打开内容编辑工作台可以看到各类结构化表单，打开发布队列可以看到它们仍处于草稿状态；它们不会出现在官网公开 API 中。

在页面、文章、产品系列或型号表单中点击“预览当前草稿”，可以直接查看当前未保存表单的品牌化预览。预览只存在于 CMS 工作台弹窗中，不会改变记录状态，也不会生成公开链接。

Directus 原生内容库也已按业务语言显示中文集合和字段名称，例如“新闻文章”“产品系列”“常见问题知识”以及“分类”“路由标识”“标题”。这些只是后台显示翻译，接口和数据库仍使用稳定的英文键，已有官网与 BFF 代码无需修改。

查看完毕后执行：

```powershell
npm run demo:cleanup
```

清理命令只删除带上述演示标记的记录，且先删除产品参数和型号，再删除产品系列，不触碰已有业务内容。

## 运行

在 `cms/` 目录执行：

```powershell
npm run publication:verify-e2e
```

脚本会使用本地 `.env.local` 中的管理员会话临时创建三个业务角色账号，依次完成：

```text
草稿 -> 待审核 -> 已排期 -> 已发布 -> 已下线 -> 已归档
```

每次状态变化都通过对应角色的真实 Directus 会话提交，并检查发布人、审核人、发布时间和 `publication_log`。演示结束后文章和临时账号会自动删除；清理失败会让命令失败，不应继续把环境当作干净。

## 查看后台

演示执行期间可在浏览器打开 CMS 的内容编辑、审核队列、发布就绪检查和内容版本工作台，观察同一条临时文章的状态变化。脚本结束后该记录会被删除，因此不要把它当作官网正式内容。

## 限制

这只验证 Windows/SQLite 本地状态机和 Directus 角色链路，不代表生产 MySQL、对象存储、HTTPS、备份、Docker/Linux 或真实业务审核已经完成。
