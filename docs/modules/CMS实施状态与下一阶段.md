## 本轮演示完善

- 内容编辑工作台的“提交审核”和“审核队列”会只读展示已有提交说明或最近审核说明；当前操作仍在独立表单填写，审核人员无需跳回原生记录页即可了解前序沟通。
- 官网首页、关于我们、产品、新闻和服务支持均通过网站 BFF 读取已发布 CMS 内容；草稿、下线记录和审核字段不会暴露给浏览器。CMS 不可用时，官网仅使用最后一次有效缓存或静态兜底，不会把草稿当作公开内容。
- 本地验收基线：CMS `npm test` 为 `175/175`；官网 `npm test` 为 `128/128`，官网 `npm run build` 已通过。官网首屏的视频末帧到静态机台图交叉淡入已在最终构建包中以实际浏览器截图复核。
- 另新增通用内容发布队列和预览令牌 endpoint，构建后共 `21` 个扩展；运营总览的快捷入口已同步指向内容发布队列。
- 官网公开 URL 边界已补齐：Nuxt 生产包提供动态 `robots.txt` 与 `sitemap.xml`，固定路由之外只收录公开 reader 返回的已发布文章、产品系列和型号；CMS 明确返回“无记录”时文章/产品详情 BFF 返回 `410`，避免下线内容继续以 `200` 旧 URL 暴露。官网回归测试为 `128/128`，生产构建与本地 `4173` 运行验证通过。
- 新增 `npm run publication:verify-e2e` 内容发布演练：临时上传受控 PNG、完成媒体审核，再用内容编辑/品牌审核/发布人员真实 Directus 会话完成文章 `draft -> review -> scheduled -> published -> unpublished -> archived`，最后校验审计日志并清理文章、媒体、文件和临时账号。最近一次本地运行成功，输出 `temporaryDataCleaned: true`。
- 内容编辑工作台新增“预览当前草稿”：页面、文章、产品系列、产品型号及独立参数可直接用当前表单内容打开本地品牌预览，不需要先发布，也不会调用官网公开 API；预览弹窗明确标识“未发布”，并对待审核主张显示警示。
- 内容编辑工作台增加面向非技术人员的三步使用说明，工作台标题、字段分组、审核和发布操作已改为简体中文；本地 Directus 系统默认语言已设置为 `zh-CN`。生产环境仍应使用短时效、服务端授权的预览令牌，不能把草稿内容放进公开 URL。
- 内容编辑工作台进一步按“常用内容 / 更多工具”分层，默认隐藏技术型入口；页面编辑中的路由标识、来源记录和段落内部标识移入“高级设置（一般无需修改）”，并增加中文填写提示。顶部流程条统一引导“编辑 → 预览 → 送审”。
- 原生 Directus 内容库已补充 23 个集合和 410 个字段的简体中文显示翻译；schema 应用器幂等更新已有元数据，真实浏览器已验证“新闻文章”列表的中文集合名和列名。
- 运营总览、发布队列、产品发布、产品审核、FAQ 审核、线索、通知和服务审核等工作台的英文眉标题已统一改为中文，并增加回归断言，避免后台界面重新出现英文操作提示。
- 新增私有 `content_preview_tokens` 集合和预览令牌 endpoint。令牌只保存哈希，默认 15 分钟有效且只能消费一次；签发按内容角色范围和草稿状态校验，撤销保留操作者和时间。本地 Directus 已真实完成集合应用、签发、消费和清理演练。
- 官网 BFF 已接入草稿预览：CMS 消费令牌时按集合白名单返回受控内容，官网服务端将其放入短时效会话并通过 HttpOnly Cookie 提供给 `/preview` 页面；本地真实联调已验证令牌交换、会话读取和预览页面渲染，浏览器 URL 不携带草稿正文或 CMS 凭据。
- 内容编辑工作台新增“在官网中预览草稿”：运营人员保存未发布草稿后可直接打开官网审核画面；“预览当前草稿”仍用于检查未保存的表单文字。工作台全程使用中文业务名称，技术字段与原生库仅保留为高级入口。CMS 通过 `WEBSITE_PREVIEW_OPEN_URL` 指向正式预览接收地址，本地演示未配置时回退到当前主机的 `4173` 端口。
- 内容编辑工作台新增未保存修改保护：编辑人员修改表单后会看到“有未保存修改”提示；切换内容、重新加载或关闭后台前会得到中文确认。保存、上传或新建成功后提示自动清除，减少非技术人员误丢草稿的风险。
- Directus 原生角色与集合说明已进一步中文化：内容审核只读账号、通知任务服务账号、通知管理员均使用中文显示名。schema 应用器会识别历史英文角色，原地改名；若已存在重复中文角色，则先迁移服务账号/用户关联再删除旧角色，避免中文化导致权限或服务账号断链。
- 日常编辑界面继续去技术化：项目名称与登录页说明改为“瑞钧官网内容后台”，常见问题知识不再向运营人员显示英文缩写、英文分类示例或内部同步状态值；页面清单隐藏网址内部标识。原生内容库仍作为“高级设置（专业人员）”保留，避免牺牲审核、媒体治理和版本审计能力。
- 内容编辑工作台首次进入改为任务式起始页：“修改官网页面、更新产品资料、补充企业资料、维护服务支持、发布新闻或案例”五项入口直接带入对应表单。该页只做日常操作引导，不会绕过草稿保护、保存、预览、送审或发布权限。

## 未完成但不应以本地 CMS 替代

| 项目 | 原因 | 前置条件 |
| --- | --- | --- |
| Dify 同步 Worker、生产 FAQ BFF 与 Redis | PRD 明确要求 Linux/Docker、Redis 和真实 Dify 配置 | Linux/Docker、Dify DSL/密钥轮换、容量上限 |
| 生产 MySQL、对象存储、备份恢复与 HTTPS | 属于生产基础设施，不应在本地 SQLite 演示中伪造完成 | 正式域名、服务器或云资源、备份策略 |
| repairsys 正式开放与健康探测 | 需满足 repairsys 的生产安全阻断项 | 正式 repairsys 部署、HTTPS、CORS、生产数据库 |
| 实际内容审核与发布 | 当前记录保守保持草稿，不能由开发替代业务确认 | 产品参数、证书、网点、宣传主张、媒体授权确认 |
| FAQ 高风险知识公开 | 235 条知识仍以内部草稿保存 | 售后技术审核、安全前置和人工升级说明 |
| 官网 BFF 预览生产化 | 本地使用单实例内存会话，尚未满足多实例生产部署 | Redis 会话存储、HTTPS、限流、正式域名和生产联调 |

## 建议的下一轮执行顺序

1. 业务团队在 CMS 中补齐并审核产品参数、产品/品牌素材、服务资料、网点和宣传主张，先完成一条产品内容的草稿到发布演练。
2. 确认正式域名、企业主体、隐私政策、销售通知渠道和 repairsys 面向人群。
3. 准备 Linux/Docker 后部署 FastAPI FAQ BFF、Redis、Dify 同步 Worker，再做官网与 repairsys 的真实交接联调。
4. 最后迁移 CMS 到生产 MySQL 和对象存储，配置 HTTPS、访问控制、备份恢复与监控，再执行正式发布验收。
