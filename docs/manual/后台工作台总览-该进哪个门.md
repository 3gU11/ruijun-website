# 后台工作台总览 · 该进哪个门

> 面向：日常使用 CMS 后台的人
> 适用版本：瑞钧官网 + CMS（Directus）
> 最后核对：2026-10-14，逐个打开全部 12 个工作台确认过界面与按钮

---

## 一句话

后台左侧一共有 **12 个工作台**。但**日常改内容只需要记住 2 个**：

| 我要做的事 | 进这个 |
|---|---|
| **改文案、改图片、改内容** | **内容编辑工作台**（左侧边栏铅笔图标） |
| **把改好的内容发布到官网 / 从官网撤下** | **内容发布队列** |

其余 10 个是审核、产品、查看用途，需要时再查下面的表。

> 完整操作步骤见 [内容编辑到官网发布 · 操作教程](内容编辑到官网发布-操作教程.md)。

## 按任务找入口

| 我想做什么 | 进哪个工作台 | 说明 |
|---|---|---|
| 改官网某个页面的文字/图片 | 内容编辑工作台 | 左侧铅笔图标 |
| 把改好的内容提交审核 | 内容编辑工作台 → 内容送审 | |
| 批准别人提交的内容 | 内容编辑工作台 → 高级设置 → 审核队列 | |
| 把审核通过的内容发布到官网 | 内容发布队列 | |
| 把某个页面从官网撤下 | 内容发布队列 → 已发布 → 下线内容 | |
| 改完后悔了，想回到之前的版本 | 内容版本 | 可「恢复为草稿」 |
| 发布前想知道还差什么条件 | 发布就绪 | 列出发布前阻断项 |
| 改产品系列/型号/参数 | 产品技术审核 → 产品统一发布 | 产品走独立流程 |
| 看看官网整体运营情况 | 官网运营总览 | 有常用工作台快捷入口 |
| 处理客户留资 | 销售线索 | |
| 处理通知发送失败 | 通知异常处理 | |
| 看官网到售后系统的点击情况 | 售后入口归因 | |
| 审 FAQ 知识草稿 | 常见问题知识审核 | |
| 审服务支持内容 | 服务支持审核 | |

## 全部工作台一览

### 一、改内容（日常最常用）

| 工作台 | 干什么 | 能改东西吗 |
|---|---|---|
| **内容编辑工作台** | 改官网六个页面的内容；提交审核；审核别人的提交 | ✅ 能改 |

> 入口是左侧边栏的**铅笔图标**（鼠标悬停显示「内容编辑工作台」），
> 不是文字条目，别在侧边栏找名字。

### 二、发布上线

| 工作台 | 干什么 | 能改东西吗 |
|---|---|---|
| **内容发布队列** | 正式发布 / 下线内容 / 归档已下线内容 | ✅ 能改状态 |

分三个分类：**待发布**、**已发布**、**已下线**。

### 三、产品（独立流程）

产品的改动**不走**上面那条内容流程，走自己的一条线：

| 工作台 | 干什么 | 能改东西吗 |
|---|---|---|
| **产品技术审核** | 产品系列 / 型号 / 独立产品参数的审核准备 | ❌ 查看为主 |
| **产品统一发布** | 按同一份快照统一发布产品，保证列表/详情/对比用同一版本 | ✅ 能发布 |

> 为什么产品要单独一套：产品的列表页、详情页、参数对比必须用**同一个版本**的数据，
> 否则会出现列表和详情对不上的问题。所以用「统一发布」一次发一份快照。

### 四、审核准备（只读，帮你判断能不能提交）

这几个工作台**只查看、不修改**，作用是提前告诉你还差什么条件：

| 工作台 | 干什么 |
|---|---|
| **发布就绪** | 列出「发布前阻断项」——发布会被拦下来的原因 |
| **常见问题知识审核** | FAQ 知识草稿的技术审核准备情况 |
| **服务支持审核** | 服务资料 / 服务网点 / 售后入口的审核准备情况 |

> 发布失败时，先来这里看阻断项，比反复试点「正式发布」有效。

### 五、查看与跟进

| 工作台 | 干什么 | 能改东西吗 |
|---|---|---|
| **官网运营总览** | 官网内容运营整体情况；有**常用工作台快捷入口** | ❌ 查看为主 |
| **内容版本** | 每条内容的版本历史与审计轨迹 | ✅ 可「恢复为草稿」 |
| **销售线索** | 客户留资记录；领取线索、开始跟进、保存记录、关闭线索 | ✅ 能改 |
| **通知异常处理** | 通知发送异常；重新投递、标记已人工通知、标记解决 | ✅ 能改 |
| **售后入口归因** | 官网到售后系统的匿名入口点击汇总 | ❌ 查看为主 |

> **建议把「官网运营总览」当默认首页**：它里面就有常用工作台的快捷入口，
> 不用每次在侧边栏里找。

## 两个容易搞混的点

### 1. 「能改」和「只能看」是两回事

- **能改的**：内容编辑工作台、内容发布队列、产品统一发布、内容版本（仅恢复草稿）、
  销售线索（跟进记录）、通知异常处理（重投/标记）
- **只能看的**：发布就绪、常见问题知识审核、服务支持审核、产品技术审核、
  官网运营总览、售后入口归因

只读工作台里按钮通常只有「刷新」和「活动日志」——**看不到修改按钮是正常的，不是权限出问题**。

### 2. 有些"编辑器"不在侧边栏里

这三个不是独立工作台，而是**嵌在其他界面里的字段编辑器**，所以侧边栏找不到：

| 名称 | 出现在哪 |
|---|---|
| 官网首页内容编辑器 | 首页区块的字段编辑位置 |
| 官网首页区块摘要 | 首页区块的只读摘要位置 |
| 产品技术参数表单 | 产品参数的字段编辑位置 |

## 打不开 / 看不到某个工作台

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 侧边栏没有铅笔图标 | 账号角色没有内容编辑权限 | 找管理员确认角色（需要「内容编辑」或以上） |
| 看不到「内容发布队列」 | 需要管理员权限 | 发布动作限管理员，找管理员操作 |
| 看不到「常见问题知识审核」「产品统一发布」 | 这两个限管理员 | 同上 |
| 侧边栏找不到某个工作台 | 可能是字段界面（见上）或权限不足 | 对照本表确认它是否应该出现 |

## 附录：为什么有这么多工作台

后台的 12 个工作台对应**四类不同职责**，分开是为了各管各的、互不越界：

| 类别 | 工作台 | 职责 |
|---|---|---|
| 编辑 | 内容编辑工作台 | 改内容、送审、审核 |
| 发布 | 内容发布队列、产品统一发布 | 决定什么内容对外可见 |
| 审核准备 | 发布就绪、常见问题知识审核、服务支持审核、产品技术审核 | 提前暴露问题，避免发布被拦 |
| 查看与跟进 | 官网运营总览、内容版本、销售线索、通知异常处理、售后入口归因 | 掌握状态、追溯历史、跟进线索与异常 |

**为什么发布和编辑要分开**：编辑决定"内容是什么"，发布决定"内容什么时候对外可见"。
合成一个界面容易误操作——改到一半就上线了。分开之后，编辑随便改都不影响官网，
直到有人明确点了「正式发布」。
